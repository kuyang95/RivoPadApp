화면별로 지금 무엇이 어디에 있는지 적는다. 모양은 `04_component_specs.md`의 컴포넌트 이름으로 말한다. 모든 화면은 라이트/다크를 따르고 soft UI 팔레트(`03_design_tokens.md`)를 쓴다. 예외는 카메라 미리보기 위 버튼, 위젯, 쉬운 브라우저의 본문 색이다. 각 화면의 Android 원본 파일을 함께 적는다. Android와 다른 곳은 각 절 끝의 **Android와 다른 곳**에 적는다(구조적 불가 또는 사용자가 유지하기로 한 iPad 전용).

## 홈

파일: `HomeView.swift` — `HomeView` (Android `compose/MainScreen.kt`, `VcSoftHome.kt`, `HomeLayoutController.kt`)

홈 구성은 설정 "화면 및 글꼴" 그룹의 `홈 화면 구성`에서 고른다. `목록형`(기본)과 `카테고리형`. `@AppStorage("visioncraft.home.layout")`(`HomeLayoutMode`)에 저장하고 바로 바뀐다. 홈이 나타날 때 저장된 값과 화면 상태가 다르면 저장값을 다시 적용한다. 공통 항목은 `HomeView`에 정의하고, 카테고리형의 카메라 메뉴와 문구는 `categoryCameraActions`·`categoryMenuItem`에서 구성한다.

### 공통 머리

- 제목 줄(`homeTitleRow`): 왼쪽 `VisionCraft`(24 Bold heading, 최소 32pt 글자 칸, `.title2` Dynamic Type), 오른쪽에 리모컨 연결 상태 아이콘(`VisionCraftHomeRemoteStatusIcon`, 누르면 앱 안의 리모컨 연결 화면)과 설정 아이콘(`VisionCraftIconButton` "전체 설정", 누르면 전체 설정 화면). 두 아이콘은 간격 없이 붙고 행 높이는 최소 52pt다. 카테고리 제목도 같은 글자 규격을 사용한다.
  - 리모컨 아이콘은 연결됨 초록 / 연결 중 노랑 / 끊김 보조글자색 + 오른쪽 위 점. 읽기: "리모컨 연결. 연결됨·연결 중·연결 안 됨. 조작 가능·상태 확인 중·리모컨을 켜주세요".
- 홈 1~4번째 방문에는 제목 아래 사용법 안내 카드(`VisionCraftHomeGuideEntry`): "앱 사용법이 궁금하신가요? / 기능과 상황별 사용법을 알려드려요". 5번째 방문부터 카드를 숨기고 설정 바로 오른쪽에 황금색 물음표 아이콘(`VisionCraftIconButton`, `guideIcon`, 읽기 "사용 설명서 열기")을 표시한다. 카드와 아이콘 모두 같은 사용법 화면을 연다. 목록형·카테고리형에 같은 기준을 적용한다.
- 방문은 홈 최초 표시, 다른 화면에서 홈으로 복귀, 백그라운드에서 홈으로 복귀할 때 센다. 화면 갱신·회전·홈 안의 다이얼로그는 새 방문으로 세지 않는다. `HomeGuideVisitStore`가 횟수를 5회까지 기기에 저장하므로 앱 재시작 후에도 아이콘을 유지한다.
- 바깥 여백: 좌우 24, 화면 가장자리 기준 위 44, 아래 최소 32. 상태표시줄·홈 표시줄의 안전 영역을 중복해서 더하지 않고, 안전 영역 자체가 더 크면 그 영역을 우선한다. 제목에서 안내 카드까지 16, 머리에서 카테고리 타일 영역까지 20, 목록형 첫 섹션까지 28이다.

### 목록형

위에서부터 섹션 제목(`VisionCraftHomeSectionHeader`) + 목록 카드(`VisionCraftHomeActionList`), 섹션 사이 28:

1. **AI 대화**: 새 대화, 대화 기록(저장된 대화가 있을 때만)
2. **카메라와 연결**: 확대 보기, 문서 스캔, 실시간 읽기, 장면 설명(→ 촬영하기/사진에서 다이얼로그), AI 질문, 저장된 사진
3. **읽기와 문서**: 텍스트, 문서 작업, 도서 읽기
4. 비전링크 카드(섹션 제목 없이, 위 28)
5. **설정**: 설정 그룹 전체(`HomeSettingsPanel`) + "모든 설정" 카드(iPad 전용 설정 화면)
6. **업데이트 기록**(`HomeUpdateNotesSection`): 최신 버전 카드 + "이전 업데이트 기록보기"

- "텍스트"는 클립보드에 글이 있으면 바로 텍스트뷰어를 열고, 없을 때만 "텍스트 가져오기" 화면을 연다(`openTextView`).
- "장면 설명"은 다이얼로그(`HomeImageAnalysisDialog`: "촬영하거나 사진을 선택하면 내용을 설명하고 클립보드에 복사합니다.", 촬영하기 → 카메라 장면 설명 모드, 사진에서 → 사진을 고르면 바로 설명).

### 카테고리형

- 머리 아래 2x2 타일(`VisionCraftHomeCategoryGrid`, 가로 화면은 4개 한 줄): **AI 대화 / 카메라/이미지 / 텍스트/문서 / 비전링크**. 타일 그림은 회색 squircle 위에 `HomeTile*` 아이콘(라이트·다크 공용 한 벌).
- 타일은 전폭을 둘로 나누고 16 간격, 높이는 너비 × 5/4.
- Android `VcHomeTilePage`와 같은 계산으로 세로 모드에서는 머리 높이를 뺀 첫 화면에 홈의 네 칸을 중앙 배치한다(`VisionCraftHomeTilePageLayout`). 가로 모드에서는 중앙 여백 없이 머리 바로 아래로 타일을 올려 정렬한다. 카테고리 안의 기능 선택도 동일하다. 타일은 전폭·4:5 비율을 유지하며 세로 공간이 부족하면 머리와 함께 스크롤한다. 안내 카드 아래 20, 타일 아래 최소 12를 확보한다.
- 항목이 하나뿐인 타일은 바로 실행: 비전링크는 항상, AI 대화는 저장된 대화가 없을 때. 나머지는 홈 내용을 전체 화면의 기능 타일로 바꾼다. 홈과 같은 세로 2열·가로 4열, 타일 크기와 첫 네 칸의 위치를 유지하며 항목이 적어도 재중앙 정렬하지 않는다. 기능이 많으면 같은 크기로 아래에 이어지고 스크롤한다. 큰 글씨에서도 열 수는 유지하고 이름을 여러 줄로 표시한다. 제목은 카테고리 이름과 뒤로 가기이고 홈 방문 횟수는 늘리지 않는다. 카테고리에서 뒤로 가면 홈으로 돌아간다. 기능을 실행하거나 파일·사진 선택을 취소한 뒤에는 진입한 카테고리의 기능 선택 화면을 유지한다. 목록형과 다른 화면의 선택창은 기존 형식이다.
- 홈과 기능 타일에는 `menu icons 2`에서 메뉴 용도에 맞춰 고른 그림을 사용한다. 이미지 매핑은 `04_component_specs.md`의 메뉴 그림 표를 따른다.
- 카메라/이미지 타일은 전체 화면의 기능 선택으로 전환한다: 확대 보기 → 문서 스캔 → 실시간 읽기 → AI 질문 → 촬영 후 설명 → 사진 설명 → 저장된 사진. 촬영 후 설명은 카메라 장면 설명 모드로 바로 진입한다. 사진 설명은 사진 검토 화면에서 선택한 사진의 AI 설명을 먼저 받고 OCR·번역·대화 등의 다른 작업을 이어서 이용한다. 목록형의 장면 설명은 기존 촬영/사진 선택창을 유지한다.
- 기능 실행 전에 카테고리를 닫지 않는다. 새 대화·대화 기록, 카메라/이미지의 모든 기능, 텍스트·문서·도서 읽기는 같은 진입 규칙을 따른다. 첫 사진 선택 취소는 사진 화면을 닫고 카메라/이미지로 돌아가며, 텍스트 안의 이미지·문서 선택 취소는 텍스트 화면을 유지한다. 홈에서 바로 실행한 단일 항목(비전링크·대화 기록이 없는 AI 대화)은 닫으면 홈으로 돌아간다.
- 타일 읽기: 항목이 하나면 "<타일>. <기능 설명>", 여럿이면 "<타일>. <항목 이름들>", 역할 버튼.
- 설정과 업데이트 기록은 홈에 없다. 설정 아이콘 → 전체 설정 화면 맨 아래에 업데이트 기록이 있다.

### 쉬운 유튜브

- 쉬운 유튜브의 Google 로그인은 `accounts.google.com` 주 문서의 알려진 이메일 입력·비밀번호 입력 단계만 단순화한다. Google 원본 입력칸·라벨·자동완성·제출 처리·오류 메시지를 유지하고, Google 로고·제목·입력칸·다음 버튼을 한 묶음으로 가로·세로 화면 중앙에 배치한다. 로고·제목·안내는 가운데 정렬하며 폼은 한 열(최대 560 CSS px)이다. 보이는 뷰포트 높이에 맞춰 중앙 위치를 갱신하고 내용이 화면보다 높으면 세로 스크롤한다. 문서가 시작될 때 정렬 스타일과 뷰포트 높이를 먼저 적용하고 폼을 숨긴다. DOM 구성이 끝나면 정렬과 단계 판별을 같은 작업에서 마친 뒤 표시하며, 준비가 10초를 넘으면 숨김을 해제한다. 쉬운 유튜브의 네이티브 로딩 표시는 웹 콘텐츠 위 중앙의 원형 진행 표시로 제공하고, 별도 줄을 차지하지 않아 로딩 전후 콘텐츠 높이가 바뀌지 않는다. Google 폼 자체의 진행 막대도 기존 노출·애니메이션·접근성 상태를 유지하며 뷰포트 중앙에 고정한다. 입력 글자는 22px, 다음 버튼은 높이 64px 이상이며 포커스 외곽선을 제공한다.
- 해당 두 단계에서 이메일 찾기·게스트 모드 안내·계정 만들기·언어 및 도움말/개인정보처리방침/약관 푸터를 시각·접근성 탐색에서 숨긴다. 보안 문자·추가 본인 확인·동의 화면·대화상자나 인식하지 못하는 단계에서는 원본 화면을 표시한다. 입력값·비밀번호를 읽거나 복사하지 않으며 별도 로그인 폼·네이티브 인증 브리지를 만들지 않는다. 일반 접근성 웹에는 이 단순화를 적용하지 않는다. 비밀번호 단계도 새 문서 진입부터 같은 정렬·초기 숨김을 적용한다. 원래 비밀번호 입력칸의 `current-password` 자동완성과 비밀번호 표시 체크박스·제출·오류를 유지하고 비밀번호 찾기 보조 링크는 숨긴다.

- 미디어 탐색의 `쉬운 유튜브`에서 `https://m.youtube.com/`를 연다. 일반 접근성 웹·Ratio 브라우저와 분리된 전용 모드이며 주소창·색상 통일·팔레트·더보기·외부 브라우저 도구 줄을 표시하지 않는다.
- 전체 콘텐츠 영역에 닫기와 홈·구독·쇼츠·검색 메뉴, 큰 영상 카드, 공식 YouTube IFrame Player API의 바깥 조작 버튼을 제공한다. 원래 유튜브·밝기 전환 버튼은 두지 않는다. 밝고 어두운 모드는 앱 설정에서 WebView로 전달되는 `prefers-color-scheme`을 따른다.
- 홈·구독·검색 목록과 쇼츠 이동은 로그인된 원래 YouTube DOM을 사용한다. 공식 추천 API가 아니며 사이트 구조가 바뀌면 어댑터 수정이 필요하다. 쇼츠는 이전·다음 버튼으로 고르며 자동 연속 재생은 제공하지 않는다. 원래 페이지의 숨은 미디어는 일시정지한다.
- 영상은 공식 플레이어로 재생한다. 공식 iframe의 기본 조작부를 접근성·Tab 탐색에 열어 두고, 바깥에는 재생 위치·시간·재생속도·채널·댓글을 제공한다. 별도 10초 이동·재생/일시정지·자막·내부 탐색 버튼은 제공하지 않는다. 영상 자체의 터치·광고·공식 링크는 차단하지 않는다. Premium 광고 없는 혜택은 로그인된 계정과 임베드 인식 여부에 달려 있다.
- 닫기는 페이지의 단일 고정 URL 동작 `rivo-easy-youtube://close`를 주 문서 탐색에서만 처리한다. 네이티브 데이터·인증정보를 읽는 브리지는 제공하지 않는다. Google 로그인 정보는 사이트의 원래 입력칸에 직접 입력하며, 아래 로그인 단순화 규격을 적용한다.
- 로그인 상태가 확인되기 전에는 준비 안내만 표시한다. 로그아웃 상태에서는 “유튜브를 이용하기 위해 로그인해 주세요”와 로그인 버튼 하나만 표시하며, 은은한 재생 타일 이미지를 장식 배경으로 둔다. 닫기·홈·구독·쇼츠·검색·영상 목록은 시각·접근성 탐색에서 모두 숨긴다. 시스템 뒤로/탈출 동작은 유지한다. 공개 `LOGGED_IN` 설정과 늦게 로드되는 사이트 로그인 동작으로 상태를 갱신하고, 로그아웃 전환 시 열린 플레이어와 목록도 정리한다. 로그인 버튼은 원래 YouTube/Google 로그인 화면으로 이동하며 인증 정보는 사이트에서 직접 입력한다. 로그인 상태 확인 후 기존 메뉴를 표시한다.
- 로그인·웹 저장소는 쉬운 유튜브 전용 저장소에 유지한다. 기존 접근성 웹 임시 프로필·문서 웹뷰와 공유하지 않는다. 첫 진입은 새 로그인 세션이며 기존 임시 로그인은 복사하지 않는다.

- 구현: `AccessibleWebBrowserView(easyYouTube:)`·`AccessibleWebBrowserModel(easyYouTube:)`·`EasyYouTubePage`. 공식 API를 사용하는 전용 스크립트는 WKContentWorld.page에서 주 문서에만 실행한다. 일반 접근성 웹의 분리된 월드는 유지한다. 인증·로딩·오류 화면에는 네이티브 닫기만 표시하며 주소창·도구 줄은 표시하지 않는다.

### 쉬운 브라우저 (양 플랫폼 공통)

- 구글 간단히 보기: 기본 홈은 `https://www.google.com`, 검색어는 `/search?q=`로 보낸다. Google의 홈·일반 검색 결과에만 적용하며 프로필·로고·앱/필터 메뉴·추천/관련 검색·광고 등 주변 요소는 표시하지 않는다. 홈은 `검색` 입력·음성 버튼·입력 뒤에 나타나는 전송 버튼과 네이버·다음·유튜브·위키백과의 기본 즐겨찾기 타일 4개를 제공한다. 기본 즐겨찾기와 사용자가 추가한 즐겨찾기를 표시하고 마지막 추가 아이콘에서 주소를 입력해 등록한다. 사용자 즐겨찾기의 이름·아이콘 조회와 저장은 아래 브라우저 홈 규격을 따른다.
- 검색 결과는 검색 입력 → 구글이 제공하는 AI 개요(있을 때) → 상위 사이트 5개의 호스트·제목·원문 설명 목록 순서다. AI 개요는 원래 DOM을 유지해 출처·펼치기를 이용하며 자체 요약을 생성하거나 일반 검색 요약을 AI로 표시하지 않는다. 결과가 늦게 추가되거나 AI 영역이 갱신되면 함께 반영한다. 다른 사이트와 Google의 이미지/영상/AI 모드 페이지는 단순화하지 않는다.
- 네이티브 더보기의 `브라우저 홈`으로 구글 홈에 돌아가며 `구글 간단히 보기`를 꺼 Google 원본으로 복귀할 수 있다. 색상 통일과 Google 단순화는 독립적이다. Google 본인 확인·동의/모달 안내는 가리지 않으며 결과 구조를 인식하지 못하면 12초 후 원래 페이지를 표시한다. 문서·페이지 데이터는 네이티브 브리지로 전달하지 않는다.
- 구글 WebView 기본 응답의 서명된 중계 링크는 원래 Google 링크로 보존하고, 사이트 주소 표시는 원문 결과의 호스트 표기를 사용한다. Google 간단히 보기에서는 뷰포트의 초기 배율을 1로 명시해 자동 맞춤이 페이지 확대를 상쇄하지 않게 하며, iPad는 네이티브 확대 후 보이는 CSS 뷰포트 폭에 맞춰 단순화 레이아웃 폭을 제한한다. 원본 보기로 돌아가면 원래 뷰포트 설정을 복원한다.
- Google 단순화의 검색 입력/버튼은 56 CSS px 이상, 즐겨찾기/사이트 링크는 64 CSS px 이상, AI 본문 20px·결과 제목 23px·설명 18px·호스트 16px, 내용 최대 폭 760px·좌우 여백 20px이다. AI 본문·강조·출처에도 선택한 웹 색상 팔레트를 적용해 Google 자체 테마와 섞이지 않게 한다. 기존 웹 색상 팔레트와 페이지 전체 확대를 적용하고 가로 폭이 줄면 검색 입력은 남은 폭을 사용하고 즐겨찾기는 줄바꿈한다. 홈 검색·즐겨찾기 크기는 이 문서의 브라우저 홈 절을 따른다.


- 개발 화면의 `접근성 웹` → `Settings/AccessibleWeb/AccessibleWebBrowserView.swift`. 구글 기본 홈에서는 상단 주소/도구 줄을 숨기고, 다른 페이지에서는 상단 한 줄(접근성 웹 닫기·검색/주소·색상 통일 아이콘·색 조합 아이콘·더보기)과 `WKWebView`로 구성한다. 별도 제목·하단 실험 안내는 표시하지 않는다. 상태표시줄과 홈 표시줄은 숨기고 하단 안전 영역까지 웹을 확장한다. 첫 주소는 `https://www.google.com`이다.
- 상단 아이콘은 색상 통일 켬/원본과 색 조합 선택을 제공한다. 라이트 모드는 해, 다크 모드는 달 아이콘으로 현재 모드를 표시하며 접근성 이름·값으로 상태를 읽는다. 이전/다음 웹페이지·새로고침/중지·새 창 닫기(새 창이 있을 때)·Safari에서 열기는 더보기 메뉴에 둔다. 주소창의 이동 버튼은 입력 중에만 표시하고 키보드 이동 키도 지원한다. 상단 바는 좌우 4pt·위아래 4pt 여백, 아이콘은 52pt다. 네이티브 컨트롤은 앱 테마·Dynamic Type·48pt 이상 터치 영역을 따른다. 원본/색 조합 전환은 페이지를 다시 불러오지 않으며 입력값과 탐색 위치를 유지한다.
- 색상 통일은 기본 켜짐·다크 모드다. 메뉴는 라이트 모드/다크 모드만 제공한다. 주소창·로딩·도구·본문을 선택 모드의 색으로 통일하며 페이지 배치·글자 크기·링크·폼 값과 원래 장식·선택·비활성 표현은 유지한다.
- Android `accessible-web.js`와 iPad `AccessibleWebAppearance`는 같은 두 모드 변환 규칙을 사용한다. 미디어 색과 명암·원래 소스·폼 값을 유지하고 원본 보기로 즉시 복원한다.
- 라이트/다크 모드는 사진·영상·배경 URL 이미지·Canvas·일반 SVG·MathML·색상 입력기의 원래 색을 보존한다. 지도·차트·상품 색상 견본은 일반적인 요소 식별자에 한해 보존한다. 조작용 아이콘은 아래 기준으로 테마 색을 적용한다. 동적으로 추가되거나 class/style이 바뀐 일반 DOM과 iframe에도 적용한다.
- 아이콘 종류·동작 이름에 따른 변환 허용 목록은 사용하지 않는다. 버튼·링크 안의 4~64 CSS px 그래픽을 대상으로 원본 색을 검사한다. 인라인 SVG는 선·면이 거의 같은 무채색일 때만 글자색으로 바꾸며 유색·다색·그라데이션·외부 참조·면 전체를 채운 사각형은 유지한다. 이미지와 CSS 스프라이트/가상요소는 실제 보이는 영역의 픽셀을 분석해 투명 바탕에 명암 변화가 거의 없는 무채색 도형일 때만 단색 필터를 적용한다. 불투명 흑백 사진·명암이 다양한 사진·유색 그림은 유지한다. 사진·로고·색상 견본 등의 보존 표시는 보조 제외 조건으로만 사용한다.
- 픽셀 분석은 웹 보안 정책이 허용하는 이미지에 한하며 CORS/CSP 실패·알 수 없는 이미지 배치·분석 한도 초과 시 원본을 유지한다. 네이티브 우회나 이미지 외부 전송은 없다. 동시에 최대 4개를 읽고 이미지 64개·전체 3,200만 픽셀·부분 분석 512개까지 캐시한다. 원본 보기에서 색·필터·그래픽 받침이 복원되며 이미지 교체·로드·화면 크기 변경 때 다시 판별한다. 자동 판별이므로 어둡게/밝게/고대비에서는 일부 그래픽이 원래 색으로 남을 수 있다.
- 색상 변환은 불투명한 면과 경계에만 적용하고 반투명 배경·사진 위 그라데이션·투명 테두리·그림자를 보존한다. 이미지와 합성된 그라데이션 로고와 투명 글자도 보존해 숨겨진 아이콘 설명이 화면에 드러나지 않게 한다. 배경 이미지를 일괄 제거하지 않으며 장식용 그라데이션만 변환한다. 원본의 밝은 회색/어두운 중립색 배경은 바탕색, 나머지 불투명 면은 면 색으로 구분한다. 링크에 밑줄이나 버튼 테두리를 일괄 추가하지 않고 모드 적용 중 문서 루트의 color-scheme은 normal로 고정해 사이트의 light/dark 지정이 기본 캔버스 색을 따로 칠하지 않게 한다. 원본 보기에서는 이 규칙도 제거한다. 브라우저 기본 입력칸은 원래 테두리를 유지하고 내부 그림자로 면 색만 입혀 WebKit의 기본 컨트롤 크기가 바뀌지 않게 한다.
- 자동 보존은 휴리스틱이다. 비표준 색상 견본, Shadow DOM, 이미지 안의 글자, 작성자 inline `!important` 스타일 등은 변환/보존이 완전하지 않을 수 있다. 사이트가 어색하면 `원본 보기`로 복구한다. 광고 차단은 별도 도구 메뉴에서 제공하며 본문 추출·자체 낭독·리모컨 전용 탐색은 이 화면에 포함하지 않는다.
- 페이지 확대는 색상 변환과 독립적이다. 더보기에서 75~300% 범위를 25% 경계 단위로 조절하고 100% 또는 기기 글자 크기에 맞춤으로 복귀한다. 기본 배율은 Android 시스템 fontScale, iPad Dynamic Type 본문 배율을 같은 범위로 제한해 사용한다. 사이트의 호스트 이름별로 최대 256개의 배율을 현재 브라우저 세션 메모리에만 보관한다(서브도메인은 별개). 페이지 이동·뒤로가기·팝업 복귀에 해당 호스트 배율을 적용하고, 새로고침 후에도 배율을 적용하며, 배율·색상 전환은 페이지를 새로고치지 않아 입력값을 유지한다. 브라우저 세션 종료 시 사이트별 배율도 초기화한다.
- 독립 브라우저·쉬운 유튜브의 확대는 `AccessibleWebBrowserModel`의 `WKWebView.pageZoom`을 사용한다. 브라우저 위젯은 `WKWebView.pageZoom`을 1로 두고 `LauncherWebAppearance`의 CSS layout zoom만 적용하고 사이트 배치는 유지한다. 확대는 색상 스크립트와 분리한다. Android는 `accessible-web-zoom.js`의 주 문서 CSS layout zoom을 사용하므로 사이트의 viewport 단위·미디어쿼리에 따라 배치가 다를 수 있다. 손가락 확대는 유지하며, 가로 넘침이 있는 사이트는 독립 화면·위젯 모두 웹 가로 스크롤을 유지한다.
- 확대 설계 참고: [Chrome 페이지 확대](https://support.google.com/accessibility/android/answer/13532420), [Chromium의 Chrome/WebView 확대 구분](https://groups.google.com/a/chromium.org/g/blink-dev/c/rTNCw0lHmZk), [Safari 사이트별 확대](https://support.apple.com/en-ie/guide/safari/ibrw1068/mac), [Firefox 확대](https://support.mozilla.org/en-US/kb/font-size-and-zoom-increase-size-of-web-pages). 사이트별 컨트롤 CSS 패치를 일반 확대 방식으로 사용하지 않는다.
- `AccessibleWebBrowserModel`은 스크립트를 분리된 `WKContentWorld`에서 실행하며 네이티브 메시지 브리지를 노출하지 않는다. 주소는 HTTP/HTTPS만 열고 나머지 문자열은 구글 검색으로 처리하되 명시적 비웹 URL 스킴은 거부한다. 외부 앱 링크·표시 불가능한 파일은 화면 안내와 Safari 열기로 대응한다. 해당 안내는 현재 보이는 창의 주 페이지에서만 표시해 뒤에 열린 창이나 하위 프레임의 탐색과 섞이지 않게 한다.
- 새 창은 WebKit이 제공한 설정으로 열어 opener 통신·세션을 유지한다(원래 창 포함 최대 5개). JavaScript 알림·확인·입력 창은 요청 출처의 호스트를 제목으로 표시한다. 인증서 오류는 우회하지 않는다.
- 쿠키·로그인·웹 저장 데이터는 모드별 전용 영속 저장소에서 위젯·단독 화면과 공유한다. 색 선택·페이지 위치는 열린 화면의 세션에만 두고 문서 뷰어·앱 데이터 저장소와 분리한다. 로그인·결제 서비스의 내장 브라우저 허용 여부는 사이트에 따라 다르다.
- Android 대응은 `app/src/main/java/net/rivo/visioncraft/browser/AccessibleWebActivity.kt`·`AccessibleWebSession.kt`, 같은 변환 소스는 `app/src/main/assets/accessible-web.js`다. Android는 세션별 WebView 프로필을 사용하고 닫을 때 삭제를 요청한다. 디스크 삭제는 비동기이며 WebView가 프로필을 계속 점유하면 앱 프로세스 재시작 후 접근성 웹 진입 시 정리한다. 다음 세션은 항상 새 프로필을 사용한다. Android 스크립트는 페이지 실행 공간에서 동작하며 네이티브 브리지는 없다. 외부 열기는 기본 브라우저를 사용한다. Android는 앱의 평문 통신 차단을 유지하며 HTTP 입력·이동을 HTTPS로 올려 연다. HTTPS 미지원 사이트는 외부 브라우저에서 이용한다.

### Android와 다른 곳

- 런처의 리모컨 홈은 첫 페이지로 돌아간다. iPadOS 시스템 홈은 앱 밖으로 나가며 앱에서 가로챌 수 없다.
- Android 기본 HOME 등록·설치 앱 열거는 리보탭 전용이다. iPad는 설정의 런처 변경으로 앱 내부 Ratio 홈을 제공하며 설치 앱 목록 대신 사용자가 등록한 앱 링크를 표시한다. 전체 목록의 뒤로가기는 iOS에서 chevron 아이콘(56pt), Android에서 시스템 뒤로가기를 사용한다. iPad의 검색 의도 판단은 로컬 MLX, Android는 Gemini를 사용한다. 텍스트 바로가기의 앱 아이콘 색는 Android 설치 앱 아이콘, iPad 사용자가 등록한 아이콘 이미지로 표시하며 iPad는 다른 앱 아이콘을 자동 추출하지 않는다.
- 카테고리 내부 기능 선택 화면은 상단 뒤로 가기 버튼을 유지한다. Android는 시스템 뒤로 가기로 홈에 돌아가므로 상단에 제목만 표시한다. iPad에는 같은 시스템 뒤로 가기 버튼이 없다.
- 리모컨 상태 아이콘은 블루투스 설정 대신 앱 안의 리모컨 연결 화면을 연다(iOS는 시스템 설정을 열 수 없음).
- 설정 끝 "모든 설정" 카드는 iPad 전용(스캐너·공유·독서·연결 설정).

## 문서 작업

파일: `Documents/DocumentLibraryView.swift` (Android `compose/DocumentLibraryScreen.kt`, 최근 목록 `document/DocumentRecents.kt`).

- 최근 문서가 있으면 내비게이션 막대 오른쪽에 "편집"(VoiceOver "최근 목록 편집")이 있다. 누르면 최근 문서 행 앞에 빨간 삭제 버튼이 나오고(목록 편집 모드, `onDelete` → `DocumentLibraryViewModel.removeRecentDocuments`), 그 버튼을 누르면 행 끝에 나오는 확인 버튼으로 뺀다. "편집" 버튼은 굵은 "완료"로 바뀌어 누르면 끝난다. 최근 문서가 다 빠지면 편집도 끝난다. 앱 문서 폴더 행에는 삭제 버튼이 없다.

- 앱 문서 폴더가 iPadOS는 파일 앱의 "나의 iPad > VisionCraft"이고, Android는 앱 전용 `Documents/VisionCraft`와(모든 파일 접근을 허용했을 때) 내 파일의 `Documents/VisionCraft`다. 폴더 설명 문구도 그에 맞게 다르다.
- 편집 모드의 빨간 삭제 버튼은 iPadOS 목록 방식대로 행 끝의 확인 버튼을 한 번 더 눌러야 빠진다. Android(`IosDeleteButton`, TalkBack 이름 "<이름>, 최근 목록에서 제거")는 바로 뺀다.

### PDF 원본 보기

파일: `Documents/LocalDocumentView.swift`(`PDFOriginalPagesView`·`ZoomablePDFView`·`PDFZoomSteps`) (Android `document/LocalDocumentActivity.kt`의 `PdfPages`).

- PDF는 위 "문서 보기" 분할 버튼으로 원본과 추출된 텍스트를 오간다. 원본은 페이지를 폭에 맞춰 세로로 잇는다.
- 두 손가락 확대·축소의 대안으로 오른쪽 아래에 떠 있는 카드(면 `surface`, 모서리 12pt, 그림자)에 축소 버튼·배율 "N%"·확대 버튼(48pt)이 있다. 단계는 100·125·150·200·300·400·500%(`PDFZoomSteps.steps`)이고, 핀치로 단계 사이에 있으면 바로 위·아래 단계로 간다. 끝 단계에서는 그쪽 버튼이 흐려지고 눌리지 않는다. 핀치도 100–500%로 묶인다. 원본 보기를 다시 열면 100%다. 화면 폭이 바뀌어도 같은 배수를 유지한다.
- VoiceOver는 페이지마다 "n/m페이지"와 그 페이지의 글을 한 요소로 읽는다(`PDFPageAccessibilityElement`). 페이지 요소에 사용자 지정 동작 `확대`·`축소`(끝 단계에서는 빠짐)가 있다. 화면 밖 페이지로 초점이 가면 그 페이지로 넘긴다. 세 손가락 쓸기는 다음·이전 페이지로 넘기고 "n/m페이지"를 알린다.

## 스프레드시트

파일: `Documents/ExcelWorkbookView.swift`(`ExcelWorkbookView`·`ExcelWorkbookViewModel`·`ExcelGridView`·`ExcelAddRowView`·`ExcelSheetImageManagerView`), `Documents/ExcelZoomScrollView.swift`(`ExcelGridZoom`), `Documents/ExcelEditRowView.swift`, `Documents/ExcelSheetManagerView.swift`, `Documents/ExcelDrawingInspector.swift` (Android `document/SpreadsheetActivity.kt`·`SpreadsheetGrid.kt`·`SpreadsheetTools.kt`·`SpreadsheetViewModel.kt`).

- 표 배율: 원본 셀 격자 왼쪽 위 모서리(`tablecells` 표시)는 스크롤해도 제자리에 있는 메뉴 버튼(`ExcelGridView.zoomCorner`)이다. VoiceOver는 "표 배율"과 값 "표 배율 N%"로 읽는다. 메뉴 머리에 현재 배율, `표 확대`·`표 축소`(끝에서는 비활성)·`표 원래 크기`(100%일 때 체크)가 있다. 단계는 50·75·100·125·150·200·250·300%(`ExcelGridZoom.steps`, 범위 0.5–3배)이고 메뉴는 고른 뒤에도 열려 있어 이어서 바꿀 수 있다. 바뀐 배율은 상태 줄 문구 "표 배율 N%"가 되어 안내로 읽는다(`ExcelWorkbookViewModel.reportGridZoom`). 두 손가락 확대·축소의 대안이다. 모서리 크기는 현재 배율의 머리글 크기를 따르되 44pt보다 작아지지 않는다.
- 시트 관리(`ExcelSheetManagerView`): 시트 줄마다 VoiceOver 사용자 지정 동작 `위로 이동`·`아래로 이동`(시트를 관리할 수 있을 때, 끝에서는 없음)으로 손잡이를 끌지 않고 순서를 바꾼다(`ExcelSheetManagerView.paths(_:moving:by:)`).
- 행 편집(`ExcelEditRowView`): 칸 목록 아래 `원본 셀에서 보기` 버튼. 입력한 값을 먼저 저장해 폼을 닫고 그 행의 첫 칸을 골라 원본 셀 보기로 바꾼다. 읽기 전용 시트에서도 누를 수 있다.
- 새 행 추가(`ExcelAddRowView`): 새 행이 들어갈 칸에 드롭다운 목록이 있으면(`ExcelWorkbookViewModel.rowFieldsForAppending`이 엔진 `ExcelAccessibleRows.appendingFields`로 읽는다. 들어갈 행은 엔진 `ExcelRowEditing.appendedRow`가 정한다: 선택한 칸의 표 바로 아래 행, 표가 없으면 시트 마지막 행 다음 행이다. 단 그 행의 폼 열에 이미 값이 있으면 시트 마지막 행 다음 행) 입력칸 아래 "<열> 선택지" 메뉴 줄을 둔다. 메뉴는 목록이 빈 값을 허용하면 `비움`, 다음에 목록 값. 줄 값은 고른 값, 없으면 "선택".
- 드롭다운 선택지(`ExcelWorkbookViewModel.RowField.dropdownLabels`·`selectedDropdown`, 엔진 `ExcelAccessibleRows.dropdown`): 새 행 추가·행 편집의 메뉴와 셀 도구의 "드롭다운 값" 목록은 같은 선택지를 쓴다. 목록이 셀 범위나 이름에서 오면 각 선택지는 원본 셀에 보이는 글로 보이고(0.00 서식의 1.2345는 "1.23") 고르면 저장된 값(1.2345)을 원본 칸의 형식대로 쓴다: 글자 칸은 글자로(`=1+1`·`2024-03-05` 같은 글자도 수식·날짜가 되지 않고 칸 서식도 그대로), 수식 칸은 그 결과로(엔진 `ExcelListChoice.input`·`ExcelCellEditing.resolvedInput(_:at:sheetIndex:…)`, 셀에 입력하거나 행 편집·새 행 추가로 선택지와 똑같은 값을 쓸 때). 직접 쓴 목록 값은 입력한 것처럼 읽는다. 칸 값이 선택지의 보이는 글과 같으면 그 선택지로 읽는다(`RowField.dropdownDisplayValue`). "드롭다운 목록에 없는 값" 경고는 선택지가 쓰는 값과 비교한다. 드롭다운 설정 편집기는 직접 적은 목록일 때만 그 값으로 채워 시작한다(`selectedDropdownEditorValues`).
- 격자 위 그림·차트(`ExcelDrawingCanvasObject`): 두 번 탭하면 선택한다. VoiceOver 사용자 지정 동작은 `위로 이동`·`아래로 이동`·`왼쪽으로 이동`·`오른쪽으로 이동`·`개체 크게`·`개체 작게`(편집할 수 있는 개체만, 한 번에 20pt), `개체 설정`, `선택 해제`(선택한 개체만) 순서다. SwiftUI가 `accessibilityActions` 순서를 거꾸로 넘기므로 코드에는 반대 순서로 적는다.
- 이미지·차트 등(`ExcelSheetImageManagerView`): 시트에 이 화면이 다루지 않는 그리기 개체가 있으면 맨 위에 "그 밖의 개체 N개는 그대로 둡니다."(`ExcelDrawingManagerNotice.otherObjects`, 엔진 `otherDrawingObjectCount`). 이미지 줄 동작 메뉴에 `이미지 설정`, 차트 줄 동작 메뉴에 `위치와 크기`가 있어 개체 설정(`ExcelDrawingInspector`: 이미지는 개체 이름·이미지 설명·교체, 차트는 차트 설정, 모두 `위치와 크기`의 왼쪽 위 기준 셀·오른쪽 아래 경계 셀·`위치 적용`)을 연다.
- 나갈 때·백그라운드 저장: 뒤로 버튼과 앱이 활성 상태를 벗어날 때(`scenePhase`가 `.active`가 아닐 때) 하는 `ExcelWorkbookViewModel.flushAutosave`는 UIKit 백그라운드 작업(`DocumentBackgroundSave.run`, 저장이 끝나거나 시스템이 시간 만료를 알리면 끝냄) 안에서 돌아, 앱이 화면에서 벗어나도 저장을 마친다.

**Android와 다른 곳:**
- 원본 파일에 쓸 수 없을 때 Android는 `Documents/VisionCraft`에 복사본을 만들어 "원본에 쓸 수 없어 복사본을 저장했습니다: 경로"를 알리고 그다음 저장은 그 파일에 한다(한글 문서와 같다). iPadOS에는 이 동작이 없다(자동 저장 실패로 알린다).

### 안내 띠·원본 보기 개체

- 머리 막대 아래 안내 띠(`HWPDocumentNoticeBand`, Android `NoticeBand`): surfaceVariant 바탕에 안내(subheadline 굵게)·설명(caption)과 primary 캡슐 버튼(높이 34pt, 누르는 영역 48pt). 좁으면 버튼이 안내 아래로 내려간다. 원본·간편 보기 모두에 보인다.
  - 편집할 수 없는 HWP(`HWPDocumentViewModel.isLegacyReadOnly`): "이 한글 문서는 이 앱에서 바로 편집할 수 없습니다." + "원본 HWP는 바꾸지 않습니다. 표와 서식 없이 글만 옮기며, 저장하면 새 HWPX 파일이 됩니다." + `편집용 HWPX 사본 만들기`. 더보기의 HWPX 변환과 같은 동작이다(`convertForEditing`).
  - 읽을 내용이 없는 새 문서(`blankParagraphID`: 간편 보기 항목이 없고 편집 가능한 첫 본문 문단이 있을 때): "아직 내용이 없는 문서입니다." + `글 쓰기`. 누르면 편집 모드를 켜고 그 문단의 문단 편집 시트를 연다(`startWriting`).
- 원본 보기의 개체(`HWPOriginalDocumentCanvas.swift`의 `HWPDocumentCanvasObjectView`·`HWPCanvasObjectAccessibility`): Android `HwpPageText.objectText`처럼 읽는다(`HWPCanvasObjectLabel`). 그림은 "그림", 설명(개체 설명, 없으면 그림 설명)이 있으면 "그림: <설명>". 차트는 종류("막대형 차트"·"꺾은선형 차트"·"원형 차트"·"영역형 차트"·"분산형 차트"·"방사형 차트", 모르는 종류는 "차트"), 제목(없으면 설명), "계열: <계열 이름, …>"을 ". "로 잇는다. 수식은 "수식 <수식 내용>"(내용이 없으면 설명). 도형·묶음·글상자·그 밖의 개체는 설명이 있으면 설명, 없으면 "도형"·"묶음 개체"·"글상자"·"한글 문서 개체"(엔진이 이름을 주면 그 이름). 글상자는 안의 글을 값으로 읽는다. 엔진이 편집 대상을 주는 개체(`HWPCanvasObjectSelection.editingTargets`: 본문 문단의 그림·도형·묶음·글상자, 표 밖의 수식)만 VoiceOver에서 버튼이고, 머리말·꼬리말·바탕쪽의 개체나 표 안 수식처럼 고를 수 없는 개체는 버튼·힌트·동작 없이 읽기만 한다. 고른 개체는 "선택됨"으로 읽는다. 두 번 탭은 손가락 탭과 같다(고르기, 고른 그림·도형은 설정 시트). 고른 그림·도형(편집 가능한 문서)에는 사용자 지정 동작 `위로 이동`·`아래로 이동`·`왼쪽으로 이동`·`오른쪽으로 이동`(20pt), `개체 크게`·`개체 작게`(오른쪽 아래 모서리 기준 20pt), `개체 설정`, `선택 해제`가 있다. 묶음 안 도형을 골랐을 때는 `선택 해제`만 있다.
- 문단·개체가 없는 빈 종이를 누르면 고른 그림·도형 선택이 풀리고 문서 위 문단 편집이 끝난다(`HWPOriginalCanvasPageView`의 `pageBackground`, `HWPDocumentView.clearObjectSelection`). 그룹으로 묶으려고 고르는 중인 도형은 그대로 둔다.
- 빈 문단도 원본 보기에서 VoiceOver로 "빈 문단"으로 읽고 두 번 탭으로 문서에서 편집한다(`HWPInlineParagraphTarget`).
- 원본 보기의 편집 가능한 문단을 길게 누르거나 VoiceOver 동작 `문단 편집`을 고르면 문서 위 편집을 끝내고 그 문단의 문단 편집 시트(`HWPAccessibleParagraphEditor`)를 연다(`HWPInlineEditingContext.onOpenParagraphEditor`, `HWPDocumentView.openOriginalParagraphEditor`). 표 칸 문단도 같다.
- 원본 보기의 각 쪽은 맨 앞에 "한글 원본 문서 · N쪽"(종이, `pageBackground`)으로 읽힌다. 종이와 그 쪽에서 읽히는 글·문단·개체에는 VoiceOver 동작 `이전 쪽`·`다음 쪽`(첫·끝 쪽에서는 없는 쪽 동작이 빠짐)이 있고, 고르면 문서 위 편집을 끝내고 그 쪽으로 넘긴 뒤 "N / M쪽"을 안내한다(`HWPPageAccessibilityContext`, `HWPOriginalDocumentCanvas.pageAccessibility`). 동작 순서는 Android와 같이 쪽 동작이 먼저, 그다음 `문단 편집`이나 개체 동작이다.

### 간편 보기 편집

- 문단 카드를 길게 누르거나 VoiceOver 사용자 지정 동작 `문단 편집`(편집 가능한 문서의 편집 가능한 문단만, `HWPAccessibleEditActionModifier`), 또는 편집 모드 아래 "선택한 문단 편집" 칸의 `문단 편집` 버튼으로 문단 편집 시트(`HWPAccessibleParagraphEditor`)를 연다. 열기 전에 아래 칸에 입력한 글을 먼저 확정한다.
- 문단 편집 시트: 입력칸(이름은 엔진 `HWPAccessibleDocument.label`, 없으면 "선택한 한글 문단 편집") + `구조`(`커서에서 문단 나누기`·`앞 문단과 합치기`) + `글자`·`문단` + `삽입`(`커서에 표 넣기`·`링크`·`각주·미주`·`쪽 나누기`, 문단 앞에 쪽 나누기가 있으면 `쪽 나누기 없애기`). 위 막대 `취소`·`적용`. 도구 시트는 이 시트 위에 열리고, 취소하면 입력한 글 그대로 돌아온다. 할 수 없는 도구 줄은 흐리고 비활성으로 읽힌다(나누기·합치기는 `HWPParagraphEditing.supportsStructure`, 표 넣기·링크는 `HWPParagraphEditing.supports`, 쪽 나누기는 단이 하나인 구역의 본문 문단).
- 모든 변경은 입력한 글과 함께 실행 취소 한 단계다(`HWPDocumentViewModel`의 `applyAccessibleParagraphText`·`formatAccessibleParagraph`·`editAccessibleParagraph`, 링크·각주·미주·표 넣기는 `accessibleParagraphDrafts`를 `editHyperlink`·`editNote`·`insertTable`의 `drafts`로 넘긴다). 나누기와 쪽 나누기 뒤에는 새 문단의 편집 시트가 바로 열리고, 합치기·쪽 나누기 없애기·서식·삽입 뒤에는 닫힌다. 파일을 다시 쓰는 링크·각주·미주·표 넣기는 끝날 때까지 시트를 열어 둔 채 잠그고(진행 표시, 입력칸·도구 줄·`취소`·`적용` 비활성, 끌어내려 닫기 막음, 한 번에 하나만 — `HWPAccessibleToolRunner`) 기다리고, 성공해야 닫는다. 실패하면 입력한 글을 그대로 둔 채 시트 위쪽에 엔진 문구를 보이고 안내로 읽는다. 결과는 상태 줄 문구("문단을 나눴습니다. 새 문단을 이어서 편집합니다.", "앞 문단과 합쳤습니다.", "서식을 바꿨습니다. 저장하면 파일에 반영됩니다." 등)를 시트가 닫힌 뒤 VoiceOver 안내로 읽는다. 할 수 없으면 시트 위쪽에 이유(엔진 `HWPParagraphEditing.unavailableMessage`, "링크로 만들 글자를 선택하세요.", "이 위치에는 표를 넣을 수 없습니다.")를 보이고 안내로 읽는다.
- `글자`(`HWPCharacterFormattingSheet`): 선택한 글자에(없으면 문단 전체, 묶음 아래 적용 범위 안내) `글꼴`(글꼴 시트 `HWPFormattingFontPicker`), `글자 크기`(비우면 유지, 스테퍼 1pt씩 6–144pt), 스위치 굵게·기울임·밑줄·취소선·위 첨자·아래 첨자(`HWPCharacterEffects`: 선택한 글자 모두에 있을 때만 켜짐으로 시작하고, 건드린 스위치는 처음 값과 같아도 끝난 값을 보내 섞인 선택을 모두 켜거나 끌 수 있다. 위·아래 첨자는 서로 끈다), `글자색`(`유지` + 12색 + `다른 색…`), `강조색`(`유지`·`없음` + 5색 + `다른 색…`), `글자 서식 지우기`. 글꼴·크기·색은 고른 것만 보낸다.
- `문단`(`HWPParagraphFormattingSheet`, `includesAlignment`): `문단 정렬` 세그먼트(왼쪽·가운데·오른쪽·양쪽 정렬·배분 맞춤), `글머리표·번호`(없음·글머리표·번호, `HWPListFormatting.supports`일 때만), 들여쓰기·간격. 리본에서 열면 들여쓰기·간격만이다.
- 표 행 편집 시트(`HWPAccessibleRowEditor`) 끝의 `표 편집`(편집 가능한 문서, 편집할 수 있는 칸이 있는 행)은 입력한 칸을 먼저 적용하고 표 편집 시트(`HWPAccessibleTableEditSheet`)를 연다. 행 카드를 길게 누르거나 VoiceOver 동작 `표 편집`으로도 바로 연다. `기준 칸 고르기`(칸 이름 + 내용) → "<칸> 기준 표 편집": `셀 서식`(`HWPCellFormattingSheet`, `HWPDocumentViewModel.formatAccessibleCell`), `행·열 크기`(`HWPTableSizingSheet`, 되는 칸만), 엔진이 그 칸에서 허용하는 변경(`accessibleTableActions`: 행·열 추가와 삭제, 병합·분할, 표 삭제 — 삭제는 빨강). 할 수 있는 것이 없으면 "이 표는 행·열을 바꿀 수 없습니다.".
- `다른 색…`(`HWPCustomColorSheet`): 리본의 글자색·강조색 메뉴, `글자` 시트의 색 메뉴, 셀 서식의 채우기·선 색상 팔레트 끝에 있다. 시스템 색 고르기와 `색 코드 (#RRGGBB)` 입력칸(VoiceOver로 직접 입력, `HWPColorCode`), `이 색 사용`. 셀 서식 팔레트에 없는 색을 고르면 `다른 색…` 칸이 그 색과 체크로 보인다.

**Android와 다른 곳:**
- 간편 보기에서 문단 카드를 누르면 iPadOS는 고르기만 하고(편집 모드면 아래 "선택한 문단 편집" 칸), 문단 편집 시트는 길게 누르기·VoiceOver 동작·`문단 편집` 버튼으로 연다. Android는 편집 모드에서 누르면 바로 다이얼로그가 열린다.
- 표 행 카드의 길게 누르기·VoiceOver 동작 `표 편집`은 iPadOS에만 있다(Android는 행 편집 다이얼로그 안에서만).
- `다른 색…`은 iPadOS 시스템 색 고르기 + 색 코드이고, Android는 이름 있는 색·색조·채도·밝기 슬라이더 + 색 코드 시트다.

### 찾기·바꾸기

- 원본 보기는 리본 `찾기` 탭(⌘F)이, 간편 보기는 머리 막대 `실행 취소` 앞의 돋보기 `찾기·바꾸기`(`HWPDocumentFindButton`: 열려 있으면 accent 12% 바탕이고 "선택됨"으로 읽음, 누르면 열고 닫음)가 검색 막대(`HWPDocumentSearchBar`)를 연다. 원본은 리본 아래, 간편은 목록 위에 놓인다(Android `HwpSearchBar`). 간편 보기의 ⌘F는 막대를 열고, 열려 있으면 입력칸에 커서를 다시 둔다(`HWPDocumentNavigation.openSearch`). 보기를 바꿔도 막대는 열린 채이고, 원본으로 오면 `찾기` 탭이 된다.
- 막대: `찾을 내용` 입력칸, `검색 옵션`(대소문자 구분), `이전 검색 결과`·`다음 검색 결과`(결과가 없으면 비활성), `검색 닫기`(입력을 지움). 아래 줄은 편집 가능한 문서의 `바꾸기` 펼치기와 결과 문구 — "검색 결과 M / N · P쪽", 없으면 "검색 결과가 없습니다.", 빈 입력이면 "본문과 표에서 찾습니다.". 펼치면 `바꿀 내용`·`바꾸기`(고른 결과를 편집할 수 없으면 비활성, "이 검색 결과는 편집할 수 없습니다.")·`모두 바꾸기`. 입력·옵션이 바뀔 때마다 본문과 표에서 찾는다(`HWPFindReplace.scan`).
- 간편 보기는 고른 결과의 문단 카드(표 칸이면 그 행 카드)를 목록 가운데로 스크롤하고 선택한 카드처럼 표시한다(`HWPDocumentView.foundBlockID`, Android `foundEntry`). 간편 보기에서 편집하면 결과를 다시 찾는다.
- 원본 쪽에 실리지 않은 글의 결과도 버리지 않는다(`HWPDocumentNavigation.results`: 쪽 없는 결과). 결과 수와 `모두 바꾸기`에 들어가고, 결과 문구는 쪽 없이 "검색 결과 M / N"이다. 원본 보기에서 그 결과로 가면 간편 보기로 바꿔 그 카드를 보이고, 상태 줄 "이 검색 결과는 원본 쪽에서 찾지 못해 간편 보기로 보여 줍니다."를 안내로 읽는다(Android `revealInPages`). 쪽 있는 결과를 고른 채 원본으로 돌아오면 그 쪽으로 간다.

### 그림·도형 설정

- 다각형의 `꼭짓점`, 연결선의 `연결점`(`HWPShapeEditingSheet`의 `HWPShapePathPointEditor`, Android `HwpPathPointEditor`): 190pt 칸에 모양 윤곽과 점마다 24pt 손잡이(첫 점은 accent). 손잡이를 끌면 그 점이 움직이고, 누르면 그 점을 고르며 고른 점에는 고리가 보인다. 아래 줄은 `점 추가`(고른 점 뒤에 다음 점과의 가운데로. 연결선의 끝 점을 골랐으면 마지막 두 점 사이에 넣어 끝은 그대로) · "N개" · `선택한 점 삭제`(빨강, 고른 점을 지움), 그다음 줄은 "선택한 점: n / m"과 `왼쪽으로 이동`·`위로 이동`·`아래로 이동`·`오른쪽으로 이동`(48pt, 모양 크기의 5%씩 — `HWPPathPoints.step`), 끝에 도움말 "점을 끌어서 모양을 바꿀 수 있습니다. 점을 눌러 고른 뒤 버튼으로 5%씩 옮기거나 지울 수 있습니다.". 점은 다각형 3–32개, 연결선 2–32개이고(`HWPPathPoints`) 한도에서는 추가·삭제가 비활성이다.
- VoiceOver는 점마다 그리는 순서대로 "점 n / m"과 값 "가로 N%, 세로 N%"로 읽고, 고른 점은 "선택됨"이다. 두 번 탭은 그 점 고르기, 사용자 지정 동작은 `위로 이동`·`아래로 이동`·`왼쪽으로 이동`·`오른쪽으로 이동`·`점 추가`·`선택한 점 삭제`(한도에서는 빠짐)다. 점 수가 바뀌면 "N개"를 안내로 읽는다.
- 값 범위 안내(`HWPRangeNotice`·`HWPRangeProblems`, Android `HwpRangeNotice`): 문서가 가져온 값이 엔진이 받는 범위 밖이면 시트 맨 위에 빨간 각주로 "<항목>: 문서의 값 <값>이(가) 적용할 수 있는 범위(<범위>)를 벗어났습니다."와 "범위 안으로 바꾸면 적용할 수 있습니다."를 보이고, 나타나거나 바뀔 때 안내로 읽는다. 고칠 때까지 `적용`은 비활성이다. 그림 편집은 테두리를 쓸 때의 `굵기`(0.25–32pt), `밝기`·`대비`(-100–100), `투명도`(0–100%, 투명도를 지원하지 않는 그림은 0), 도형 편집(묶음 전체는 제외)은 `굵기`(0.1–32pt)와 그림자를 쓸 때의 `가로 이동`·`세로 이동`(-100–100pt)·`농도`(0–100%)를 본다. 다단 설정(`HWPColumnSetupSheet`)은 1–4단 밖이면 "이 구역은 N단입니다. 1~4단 중에서 고르면 적용할 수 있습니다."(단 수 세그먼트에 그 수가 따로 보임), 단 사이가 0–144pt 밖이면 mm로 쓴 범위 안내와 도움말, 적용 범위의 어느 구역이든 단이 36pt보다 좁아지면 "단 너비가 너무 좁습니다. 단 수나 단 사이를 줄여 주세요."를 보인다.

**Android와 다른 곳:**
- 범위 안내의 수는 소수 둘째 자리까지 쓴다(그림 테두리 "0.25~32 pt"). Android는 첫째 자리까지("0.3~32 pt")다.

### 자동 저장·나가기

- 자동 저장(`HWPDocumentViewModel`의 `scheduleAutosave`·`performSave`·`write`, Android `HwpViewModel` 자동 저장): 편집·실행 취소·다시 실행·AI 적용 뒤 0.9초(`HWPDocumentViewModel.autosaveDelay`) 동안 더 편집이 없으면 저장한다. 나갈 때와 앱이 백그라운드로 갈 때(`scenePhase` `.background`, 화면이 사라질 때도 `flushAutosave`)는 문서 위 편집을 먼저 끝내고 바로 저장하며, 이 저장은 UIKit 백그라운드 작업(`DocumentBackgroundSave.run`, `beginBackgroundTask`/`endBackgroundTask` — 저장이 끝나거나 시스템이 시간 만료를 알리면 끝냄) 안에서 돈다.
- 원본 보기에서 문서 위에 입력 중인 문단(`HWPInlineEditingSession`)도 입력·서식·입력칸 실행 취소가 멈추고 0.9초 뒤 자동 저장한다(`onDraftChange` → `inlineDraftChanged`, `autosaveDraft`를 `inlineDraft`로 읽음). 확정할 때와 같은 자리에 넣어(`HWPBlockEditing.committing`) 파일에만 쓰고, 편집은 끝내지 않으며 커서·입력칸 실행 취소·문서 실행 취소 기록은 그대로다(확정할 때 실행 취소 한 단계가 된다). 파일에 들어간 입력 중 문단은 `savedDraft`로 기억해, 그 문단이 확정·변경되거나 실행 취소로 사라지면 기록이 저장 때와 같아도 다시 "수정됨"이 되어 저장한다. IME가 조합 중(marked text)이면 그 문단은 건너뛰고 다음 변경 때 다시 저장한다. 조합 중에 다른 변경을 저장할 때는 그 문단을 파일에 이미 들어간 입력(`savedDraft`)으로 두어, 더 오래된 글로 되돌려 쓰지 않는다. HWPX는 HWPX로, 바로 편집하는 HWP는 원본 HWP 형식(`HWP5DocumentRewriter`)으로 원본 파일에 쓴다.
- 한 번에 하나만 저장한다. 저장 중에 들어온 저장 요청은 앞 저장이 끝난 뒤 남은 변경을 쓰고, 자동 저장 중에도 편집은 계속된다(`isAutosaving`은 화면을 잠그지 않는다). 저장 중에 한 편집은 문서를 "수정됨"으로 남겨 다음 저장에 쓴다. 표·그림처럼 엔진이 파일을 다시 만드는 편집이 진행 중이면(`isSaving`) 자동 저장은 한 번 더 기다린다.
- 저장해도 실행 취소·다시 실행 기록과 선택·편집 중인 문단은 그대로다. 저장은 연 문서(패키지·HWP 원본)에 지금 문단을 적용해 쓰고, 어느 기록 단계까지 썼는지(`savedHistoryIDs`)를 기억해 그 뒤 편집·실행 취소면 다시 "수정됨"이 된다.
- 상태 줄(`statusBar`): 왼쪽에 마지막 상태 문구, 오른쪽에 저장 상태(`saveStateText`) — 자동 저장 중이면 "자동 저장 중…", 쓰지 않은 변경이 있으면 "수정됨", 다 썼으면 "자동 저장됨". 저장 상태는 보이기만 하고 읽어 주지 않는다(상태 줄에 초점이 가면 함께 읽음). 저장 실패는 상태 문구로 바꾸고 VoiceOver로 알린다(`saveFailure`): "자동 저장하지 못했습니다: 이유"(이 문서에 저장은 "저장하지 못했습니다: 이유").
- 연 뒤 다른 앱이 파일을 바꿨으면(`CoordinatedDocumentFileAccess.replaceContents`가 쓰기 직전 마지막으로 읽거나 쓴 바이트와 비교, `DocumentFileAccessError.documentChanged`) 쓰지 않고 "다른 앱에서 문서가 변경되어 저장하지 않았습니다. 수정 내용을 복사본으로 내보내거나 문서를 다시 열어 주세요."를 띄우며 그 뒤로는 자동 저장하지 않는다. 편집 내용과 실행 취소 기록은 남는다.
- `더보기` → `이 문서에 저장`(`save`, 쓰지 않은 변경이 있거나 변환한 문서일 때 켜짐): 자동 저장 대기를 취소하고 진행 중인 저장을 기다린 뒤 바로 쓴다. 쓰는 동안은 화면이 잠기고("HWPX 저장 중…"/"HWP 저장 중…"), 끝나면 "HWPX 문서에 저장했습니다."(HWP는 "원본 HWP 형식으로 저장했습니다.").
- HWPX로 변환한 HWP(`convertLegacyForEditing`, `requiresSaveAs`): 원본 .hwp에는 절대 쓰지 않는다. 처음 `이 문서에 저장`(또는 `복사본 내보내기`)이 시스템 저장 위치 선택으로 "<이름>-편집본.hwpx"를 만들면 그 파일이 이 문서의 파일이 되고(`adoptSavedCopy`: 보안 범위 접근 유지, 최근 문서에 등록), 그 뒤 편집은 그 파일에 자동 저장한다. 그 전까지는 자동 저장하지 않고 "수정됨"으로 남는다.
- 나가기(머리 줄 뒤로 가기, `documentBackButton` → `prepareToLeave`): 남은 변경을 먼저 저장하고 다 쓰였으면 바로 닫는다. 저장이 실패했거나 쓸 수 없을 때(다른 앱의 변경, 아직 파일이 없는 변환 문서)만 "저장하지 않은 변경 사항" / "저장하지 않은 한글 문서 변경 사항이 있습니다." / `계속 편집`·`변경 내용 버리기`(`discardChanges` 뒤로는 아무것도 쓰지 않고 닫는다).

**Android와 다른 곳:**
- 변환한 HWP의 첫 저장 위치를 iPadOS는 시스템 저장 위치 선택으로 사용자가 고르고(엑셀 XLS 변환과 같은 흐름), 그 전에는 자동 저장하지 않는다. Android는 첫 자동 저장 때 `Documents/VisionCraft`에 새 HWPX를 만든다. 원본에 쓸 수 없을 때 복사본으로 저장하는 Android 동작은 iPadOS에 없다(실패로 알린다).
- iPadOS 상태 줄은 쓰지 않은 변경이 있으면 "수정됨"을 보인다(Android는 저장 중·저장됨만). `이 문서에 저장`이 쓰는 동안 iPadOS는 편집을 잠근다.

## AI 문서 선택

파일: `LLM/AIDocumentSelectionView.swift` (Android `compose/FileSelectScreen.kt`).

- 음성 명령 "AI 문서"에서 들어간다. 머리에는 "파일 선택" 제목, "AI 문서 질의" 안내 패널(`VisionCraftPrimaryActionPanel`), 새 대화·대화 기록 버튼을 둔다.
- 파일 선택기로 PDF·엑셀·한글·TXT를 고르면 문서 내용을 준비해 AI 대화로 연다. 사용자가 폴더 접근을 허용했다면 그 폴더의 최근 문서를 검색하고 바로 고를 수 있다.
- 최근 문서 행을 누르면 AI 대화로 연다. xlsx 행 끝에는 연필 아이콘 버튼 "엑셀에서 편집", hwp·hwpx 행 끝에는 책 아이콘 버튼 "읽기"(48pt, VoiceOver 이름도 같다)가 있어 AI 대화 대신 원본을 엑셀 편집기·한글 문서 화면에서 연다(`AIDocumentOriginalOpener`, `AuthorizedDocumentLibrary.registerOriginalDocument` → 문서 작업과 같은 원본 열기). 행과 버튼은 따로 읽히고, VoiceOver는 행을 먼저, 그 버튼을 다음에 읽는다(`AIDocumentSelectionRow`). 문서를 준비하는 동안에는 행과 버튼이 눌리지 않고 버튼은 흐려진다.

**Android와 다른 곳:**
- iPadOS는 전체 저장소를 스캔하거나 모든 파일 접근 권한을 요청할 수 없다. 사용자가 고른 파일과 허용한 폴더만 나열한다.
- 행 끝 버튼으로 연 원본은 iPadOS에서 문서 작업 "최근에 연 문서"에도 남는다(원본을 다시 여는 권한을 그 기록에 두기 때문). Android는 남기지 않는다.

## 텍스트뷰어

파일: `Documents/TextEditorViewerView.swift` (Android `compose/TextEditorViewerScreen.kt`).

- 클립보드가 비었거나 문서를 직접 열지 않았을 때 뷰어 안에 "텍스트 가져오기" 첫 화면을 보인다. 뒤에는 옅은 `TextOpenSourceIllustration`을 깔고, 클립보드·이미지·문서 버튼을 전폭 최대 320pt로 둔다.
- 본문은 사용자가 고른 고대비 색 조합과 글자 크기를 따른다. 테마 색은 메뉴·다이얼로그 바깥에만 쓴다. 별도 내비게이션 헤더 없이 뒤로가기·메뉴를 같은 줄에 둔다. 두 버튼의 보이는 원은 30pt, 터치 영역은 48pt이며 간격은 6pt다. 읽는 동안 일시정지를 같은 줄에 표시한다. 텍스트 가져오기·로딩·오류 화면에서도 상단 버튼을 유지한다.
- 전체 메뉴는 제목 줄 + 닫기, 패널 안에 도구·모양·읽기·열기/저장 줄을 둔다. 글자 크기 1~20 단계와 16색 미리보기가 있다.
- 본문 글자 크기는 1~20단계(기본 5), 최소 18pt다. 화면 너비를 단계별 목표 글자 수 `[40,36,32,28,24,22,20,18,16,15,14,12,10,8,6,5,4,3,2,1]`로 나눈 크기와 최솟값 중 큰 값을 쓴다. 선택 버튼은 5열·4행이며 전체 설정·저장·리모컨 증감도 1~20을 사용한다. 줄 간격은 1~10단계를 유지한다.
- 같은 보기 설정을 쓰는 `LocalDocumentView`의 추출 본문도 1~20단계(16~96pt)이며 PDF 원본 렌더링은 문서 배율을 따른다.

**Android와 다른 곳:** 텍스트 선택은 시스템 선택·복사 동작을 쓴다. 이미지에서 글자 가져올 때 iPadOS는 OCR 교정 단계가 있다.

## 카메라

파일: `CameraTools/MagnifierView.swift`, `MagnifierViewController.swift`, `VisionCraftCameraControls.swift`, `VisionCraftCameraViews.swift` (Android `camera/RVCameraXActivity.kt`, `CameraControls.kt`, `CameraModes.kt`).

- 미리보기 위 버튼은 테마를 따르지 않는 `VisionCraftCameraUI` 고정색. 미리보기를 가리는 띠는 깔지 않는다. 격자·라이트·전환은 상태 글자가 있는 둥근 사각 타일, 켜면 주황 면. "설정"으로 접고 펴며 접힌 채로 켠 항목이 있으면 주황 테두리로 알린다.
- 촬영과 접이식 설정 버튼은 카메라 화면 안전 영역의 오른쪽 아래에 붙은 한 열이다. 열 너비는 촬영 버튼 크기로 고정하고 모든 타일의 오른쪽 끝을 맞춘다. 타일 높이는 최소치만 두고 아이콘·제목·상태 글자가 커지면 함께 늘어난다. 왼쪽 위에는 뒤로 가기만 표시한다. 촬영/설정/전환/라이트/격자 순서로 읽는다.
- 기본 촬영은 사진 앱에 저장 후 "촬영한 사진" 검토 화면(다시 촬영·작업)으로 이어진다. 저장 실패는 화면과 음성으로 알린다. 장면 설명은 카메라 위에서 결과를 읽고 클립보드에 복사한다. AI 질문 촬영은 사진을 첨부한 음성 질의로 이어진다.
- 격자·라이트·전환 상태를 바꿀 때 큰 글자와 음성 안내가 나온다. 색 조합 변경 시 격자선은 선택한 전경색을 따른다.
- 기능은 홈에서 개별 진입한다. 목록형 홈의 확대 보기·위젯·App Shortcut은 기본 카메라를 바로 열고, 카테고리형 홈의 카메라 타일은 전체 화면의 기능 선택으로 전환한다. 카메라·문서 스캔·실시간 읽기 안에는 기능 전환 경로가 없다. 다른 기능을 쓰려면 카테고리형에서는 카메라/이미지 기능 선택으로, 목록형에서는 홈으로 돌아가 선택한다.
- 카메라·실시간 읽기·문서 스캔에는 기능 이름표가 없다. 미리보기만 안전 영역 바깥까지 펼치고, 뒤로 가기는 안전 영역 위에서 8pt 아래, 왼쪽에서 16pt 안쪽에 놓는다.
- 기본·장면 설명·AI 질문은 같은 카메라 구현을 진입 시 지정한 기능으로 사용한다. 촬영 버튼의 동작은 화면을 연 동안 고정이다.

## 저장된 사진

파일: `CameraTools/MagnifierView.swift` `PhotoReviewView` (Android `camera/PhotoReviewActivity.kt`, `ImageAnalysisActivity.kt`).

- 처음에는 사진을 고른다. 선택을 취소하면 닫는다. 카메라 기본 촬영에서 오면 화면이 나타날 때 전달된 사진을 한 번 받고 제목 "촬영한 사진"과 "다시 촬영" 버튼을 쓴다. 사진 앨범에서 오면 "저장된 사진"과 "다른 사진" 버튼을 쓴다.
- 사진은 손가락으로 확대·원상복귀할 수 있고 제스처를 접근성 이름으로 안내한다. 남는 화면의 약 60%를 사진, 나머지를 결과에 나눠 쓴다.
- 아래 "다시 촬영/다른 사진"과 "작업"은 한 줄에서 같은 높이로 맞추고 너비를 1:1.45로 나눈다.
- "작업" 다이얼로그에는 글자 인식(OCR)·번역·AI와 이 사진으로 대화·텍스트뷰어로 보기·이미지 설명·텍스트 읽기 카드가 아이콘·설명과 함께 나온다. 글자 인식은 한 번만 수행하고 결과를 재사용하며 설정에 따라 OCR 오타 교정을 거친다.
- 처리 중에는 상태 띠와 소리·TTS로 알린다. OCR·이미지 설명 결과는 화면에 보이고 클립보드에 복사되며, 읽기를 다시 누르면 멈춘다. 화면을 나갈 때 TTS를 멈춘다. 홈 카테고리형의 "사진 설명"과 목록형 "장면 설명 > 사진에서"는 사진을 고르면 곧바로 설명한다.

## 문서 스캔

파일: `DocumentScan/CustomScanner/LocalDocumentScannerViewController.swift`, `DocumentScan/DocumentScanRootView.swift` (Android `scanner/DocumentScanActivity.kt`, `DocumentScanResultActivity.kt`). 상세 파이프라인은 `rules/scanner_pipeline.md`.

- 촬영 화면은 미리보기 아래 상태 알약으로 문서 탐색·프레이밍·고정·촬영을 알린다. 문서가 잘렸으면 방향을 말해 준다. 강제 촬영·어두워서 라이트 켬·다음 장 준비도 음성 피드백 설정에 따라 TTS로 말한다. 상태 안내를 시작하면 방향 안내를 중지하고, 상태 안내가 끝난 뒤 현재 방향 안내를 재개해 재촬영 복귀 때 두 음성이 겹치지 않게 한다.
- 한 장 검토 상단은 뒤로가기·“스캔된 문서” 제목·보기 전환 버튼을 한 줄에 둔다. 제목과 T/사진 아이콘은 같은 24pt Dynamic Type 기준이며, 두 아이콘 모두 36pt 원형 테두리와 최소 48pt 터치 영역을 사용한다. 뒤로가기와 제목·아이콘은 라이트/다크의 기본 글자색을 따른다.
- 한 장 검토는 사진/텍스트 전환과 사진 핀치 확대(최대 4배), 인식 중 안내 띠를 둔다. 글자가 없으면 이유를 알리고 글자가 필요한 작업은 열지 않는다.
- "저장"은 사진/PDF/텍스트 복사, "작업"은 AI 대화·번역·텍스트뷰어·이미지 설명·텍스트 읽기. 다이얼로그는 `VisionCraftDialogCard`로 아이콘·설명이 있는 88pt 카드 행이다. 이미지 설명은 화면에 남아 결과를 표시하고 읽는다. 텍스트 읽기는 다시 누르면 멈춘다.

**Android와 다른 곳:** 사용자 지정으로 한 장 검토의 뒤로가기·제목·원형 T/사진 전환을 한 줄에 배치한다. iPadOS에는 자동 촬영 끄기와 곡면 보정 설정, 세분화된 상태·거리 안내, 여러 장 검토, PDF 저장 위치 선택 기능이 더 있다. 시스템 권한·파일 선택 방식은 iPadOS를 따른다.

## 비전링크

- 채널 연결 후 호환 확인을 마쳐야 카메라·파일·텍스트 기능을 사용할 수 있다. 규격 불일치나 응답 없는 개발본은 기존 오류 안내 영역에 양쪽 앱 업데이트를 안내한다. 선택 기능 미지원은 실행 시 수신앱 업데이트를 안내하며 다른 공통 기능은 사용할 수 있다. 영상 상한은 양쪽 지원값 중 작은 값이다. 자세한 기준은 `rules/visionlink_compatibility.md`를 따른다.

- 카메라 공유 중 실제 프레임이 5초간 오지 않으면 연결 복구를 요청하고, ICE 재시작 후 12초간 더 오지 않으면 전체 연결을 다시 만든다. offer 대기는 8초로 제한한다. 복구 뒤 공유하던 카메라는 송신 앱이 전면일 때 자동 재개하며, 사용자가 중지한 카메라는 재개하지 않는다. 백그라운드에서는 영상 워치독을 정지한다.

- 송신 미리보기와 양쪽 수신 화면은 실제 영상의 짧은 변을 `720p`·`1080p`처럼 표시하고 확인된 배율과 `1080p · 1.5x` 한 항목으로 합친다. 자동 화질 문구·가로×세로·fps·전송률·측정 중 문구는 공유 HUD에 표시하지 않는다. 측정 전에는 확인된 배율만 표시한다. 공유 중에는 설정 진입 버튼을 숨기고 중지하면 다시 표시한다. 수신 상태 칩에는 연결됨 접두어 없이 카메라 화면 공유 중 또는 바로 읽기 처리 중만 표시한다. 실제 fps·전송률 측정과 자동 화질 조절은 내부에서 계속하며 수치 변경을 자동 낭독하지 않는다. 첫 영상부터 최대 1080p 상한으로 시작하고, 연결 상태나 인코더 처리 성능이 부족할 때 화질을 낮춘다. 송신 앱이 실제 영상 연결의 전송 여유·지연·손실·인코더 부하에 맞춰 720p·1080p 두 상한을 자동 선택한다. 실제 영상의 짧은 변이 720픽셀 미만이거나 디코딩 속도가 24fps 미만인 상태(측정 불가·정지 포함)가 8초 지속되면 검은 불투명 안내로 영상을 가린다. 안내는 “영상 품질이 충분하지 않아 표시를 잠시 멈췄습니다. 연결 상태가 좋아지면 자동으로 다시 표시합니다.”이다. 영상 디코딩·연결·측정을 유지하고 두 기준을 4초 연속 충족하면 자동으로 다시 표시한다. 짧은 저하에는 가리지 않으며, 5초 넘는 측정 공백은 안정 시간으로 세지 않는다. 안내는 화면 읽기 도구에 한 번 알리고 수치 갱신은 낭독하지 않는다.

파일: `VisionLink/VisionLinkView.swift`, `VisionLink/VisionLinkManager.swift` (Android `visionlink/VisionLinkReceiverActivity.kt`, `VisionLinkSettingsActivity.kt`).

- 제목 없는 전체 화면. 연결 대기에는 파란 원 맥박, 연결 뒤에는 두 노드와 움직이는 점·선. 동작 줄이기 설정을 따르면 멈춘다. 연결 상태·현재 활동(카메라, 바로 읽기, 기능 처리)을 제목과 칩에 텍스트로 적는다.
- 원격 OCR·장면 설명·AI 답변·첨부·번역의 처리 중/완료/실패를 HUD 카드와 접근성 알림으로 보여 준다. 사진/파일 받는 중에는 진행률, 완료 시 이름·크기·저장 위치를 잠시 보여 준다. 최근 수신은 사진·파일·텍스트를 열 수 있다.
- 클립보드 텍스트를 받으면 시스템 클립보드에도 저장하고 완료 카드를 자동으로 닫는다. 설정 시트는 연결된 기기 이름과 등록 해제 확인·진행·오류 안내를 보인다.

**Android와 다른 곳:** 받은 파일은 앱 문서 폴더의 `VisionLink/`에 저장하고 파일 앱·QuickLook에서 연다. iPadOS에는 미리보기·내보내기·삭제와 진단 섹션이 더 있다.

## 음성 질의

- 문서 질문의 로컬 모델 준비가 실패하면 다음 "다시 말하기"에서 준비를 다시 시도한다. 화면을 나가면 음성 인식·응답·모델 준비 대기 작업을 취소한다.

파일: `VoiceQueryResponseView.swift`, `STTManager.swift`, `AuroraListeningOverlay.swift` (Android `ai/voice/VoiceQueryScreen.kt`, `STTHelper.kt`).

- 공유 화면 설정에서 음성 질문을 고르면 전용 음성 질의 화면으로 간다. 위 오른쪽 "닫기", 아래 72pt "다시 말하기" 마이크. 듣는 중에는 오로라 오버레이를 유지한다.
- 라이트/다크를 따르고, PDF·웹·엑셀·한글·텍스트·이미지처럼 받은 형식을 안내한다. 답은 스트리밍으로 표시하고 문장 단위로 읽으며 마크다운 기호는 읽지 않는다.
- 음성 인식은 앱 언어를 따르고, 인식된 문장이 2.5초 동안 바뀌지 않거나 소리가 3.5초 동안 조용하면 자동으로 끝낸다. 인식 실패는 이유별 텍스트와 실패음으로 알린다.

**Android와 다른 곳:** 보라 Orb 대신 기존 오로라를 유지한다. 자유 채팅 답변은 로컬 AI를 우선하고 클라우드 웹 검색이 실패하면 로컬 AI로 대신 답한다.

## 리모컨 빠른 메뉴

파일: `RivoRemote/RivoRemoteControlCenter.swift`, `RivoRemote/RivoRemoteModeOverlay.swift` (Android `menu/RemoteRibbonOverlay.kt`, `RemoteModeOverlay.kt`).

- 리모컨 L1으로 앱 안 빠른 메뉴를 연다. 접힌 화면은 아래 카드 3개와 키 안내, 펼친 화면은 목록과 조절 항목의 −/+ 버튼. 사용자가 고른 메뉴 색 조합을 강조색으로 쓴다.

**Android와 다른 곳:** iPadOS에서 다른 앱 위에 뜨는 가장자리 메뉴바, 시스템 화면 확대·반전·회전 잠금, TalkBack 토글은 만들 수 없다. 하단 카드형 빠른 메뉴는 기존 iPadOS 방식을 유지한다.

## 위젯

- 텍스트뷰어 바로가기는 `rivopad://open/text-viewer`로 진입한다. 클립보드에 글이 있으면 그 글을 열고, 없으면 텍스트 원본 선택 화면을 연다.

파일: `rivoWidget/RivoStatusWidget.swift` (Android `widget/*`).

- WidgetKit small/medium 리모컨 상태 위젯, 고르는 바로가기 위젯, 로컬 AI 사용량/클라우드 AI 토큰 잔량 위젯과 제어 센터 컨트롤. 이름은 "데이지 플레이어", "카메라", "새 대화", "실시간 읽기"처럼 앱 화면과 맞춘다.
- AI 사용량은 하루 100만 클라우드 토큰의 남은 비율과 막대도 보여 준다. 글자는 12pt 이상, 상태는 글자와 접근성 이름으로도 알린다.

**Android와 다른 곳:** WidgetKit 크기·구성 방식에 맞춰 바로가기 기능을 선택한다. 화면 확대·TalkBack·회전 잠금·음소거 시스템 토글 위젯은 iPadOS에서 만들 수 없다.

### VisionLink 공유 확대 조작

`VisionLinkView` / `VisionLinkReceiverActivity`와 송신 미리보기는 `1080p · 1.5x`처럼 화질과 배율을 하나의 작은 HUD에 표시한다. 화질은 실제 영상의 짧은 변이고 측정 전에는 배율만 표시한다. 자동 화질·가로×세로·fps·전송률은 표시하지 않는다. 확대·축소·1배 복원 버튼 없이 핀치로 조작하며, 배율은 16pt/sp 이상이고 VoiceOver/TalkBack 조절 동작을 제공한다. 공유 중 설정 버튼은 숨기고 공유 중지 시 복구한다. 수신 상태 칩은 연결됨 접두어 없이 현재 활동만 표시한다. iPad는 별도 내비게이션 헤더 없이 뒤로가기·활동 칩을 한 줄에 두고, 아래에 화질·배율 HUD를 둔다. 큰 글씨에서는 줄바꿈한다.

### VisionLink 영상 방향

송신 앱의 홈·설정은 정방향 세로다. 카메라 공유 중에만 화면의 가로 회전을 허용해 영상·제목·버튼·화질/배율 HUD가 함께 돌아간다. 송신 영상은 cover로 화면을 꽉 채우며 비율은 유지한다. 화면과 영상 비율 차이만큼 가장자리는 잘릴 수 있다. 가로 공유 중지 버튼은 전체 폭을 쓰지 않고 안전 영역 안의 오른쪽 아래에 내용 폭(최대 320dp)으로 배치한다. 세로에서는 기존 가운데 아래 버튼을 유지한다. 공유 중지·연결 종료·화면 종료 시 세로로 복귀한다. 리보패드·리보탭은 프레임 방향을 적용하고 전체 영상을 비율 유지로 표시하며, 송신 폰 때문에 수신 앱의 화면 방향을 강제로 바꾸지 않는다. 송신 홈 설정 버튼은 테두리 없이 기존 배경·그림자·52dp 터치 영역을 유지한다.

## Ratio 앱 내부 홈

- 진입: 설정 → 런처 변경 → 위젯 런처. `RatioLauncherView`는 Debug·Release 공통이며 기존 앱 홈도 선택할 수 있다. 다른 두 런처 테마는 아직 제공하지 않는다.
- 단일 잉크 팔레트, 상단 통합 검색, 선택색을 표시하는 모서리 8의 타일, 기능 타일 아래 앱 이름 버튼. 홈에서 문서 작업·스캔은 제외하지만 기능 목록·검색에서 실행할 수 있다.
- 입력 중에는 이름 부분 일치를 표시한다. 전송·음성 완료 시 정확한 단일 이름은 실행, 동명·부분 일치는 선택, 미일치는 로컬 MLX가 chat/browser/unclear로 분류한다. chat은 원문으로 새 대화를 시작하고 자동 낭독하지 않는다. browser는 쉬운 브라우저에 원문을 전달한다. 로컬 모델 준비 과정은 기존 준비 화면을 사용한다. 실패·모호함은 두 경로를 직접 선택할 수 있다. 입력 수정·화면 이탈은 대기 작업을 취소한다.
- 전체 목록은 앱/기능 전환과 검색, 기본 앱. iPad에서는 앱을 열거하지 않고 설정에서 이름·앱 링크를 등록한다. 열 수 없는 링크는 오류를 표시한다. 같은 이름의 링크만 주소로 구분한다.
- 설정: 시계·날짜 위젯(기본 끔), 아이콘 표시, 글자 24~40pt, 홈 항목 추가·삭제·위/아래 이동, 앱 링크 추가·삭제, 전체 설정, 기존 홈으로 복귀. 변경은 UserDefaults에 저장한다. 뒤로는 아이콘이고 VoiceOver escape도 지원한다.

### Ratio 홈 규격 문서

현재 구성요소 명칭과 격자 추천 규격은 [Ratio 홈 격자·위젯 사양](08_ratio_home_grid_proposal.md)을 따른다. 현재 홈은 4열 단위의 크기 선택·순서 기반 줄 배치를 사용한다. 전체 앱 목록에는 사용자 프로필 안내 문구를 표시하지 않는다.

### Ratio 런처 설정 구성

설정은 홈 디자인 → 홈 편집(편집 진입·시계·아이콘) → 글자 크기(실제 크기 미리보기·조절) 순서의 그룹이다. Android는 이어서 기본 홈 상태·변경, 앱 테마, 기기 설정·전체 설정을 제공한다. iPad는 앱 링크 등록·삭제 그룹, 전체 설정·기존 홈 복귀를 제공한다. iPad 글자 크기 증감은 Android와 같은 4 단위다. Android 런처 내부는 전체 앱·설정·편집·추가 모두 화면 안 뒤로 버튼이 없고 시스템 뒤로가기를 사용한다. iPad는 뒤로 아이콘과 VoiceOver escape를 유지한다. 다른 두 테마의 설정 디자인은 기존 구성을 유지한다.

### Ratio 위젯 편집

홈의 각 앱·기능은 사각형(기본 2×2) 또는 이름만(기본 4×1)으로 선택한다. 사각형 크기는 아이콘·이름 배율도 바꾸고 텍스트 바로가기는 공통 글자 크기를 조절한다. 검색은 이동·삭제·재추가할 수 있는 위젯이며 3×1·4×1·4×2 중 선택한다. 편집에서 유형·크기·순서·삭제 및 앱·기능 추가를 제공한다. 목록 글자 크기와 홈 텍스트 바로가기 공통 글자 크기는 별도 설정이다. iPad 앱 아이콘은 앱 링크 등록 시 사용자가 선택한 이미지이며 미선택 시 앱 기호다. 자세한 구현 규격은 `08_ratio_home_grid_proposal.md`.

### 런처의 쉬운 브라우저 연결

기능 목록·이름 검색·위젯 추가에서 `쉬운 브라우저`로 직접 실행한다. 직접 실행은 브라우저 기본 홈, 검색 의도 또는 브라우저 검색 버튼은 입력 원문을 브라우저 주소/검색 처리에 전달한다. Android의 실행 대상은 `LauncherBrowser`가 공통으로 만들며 설치 빌드에 브라우저 Activity가 있을 때만 기능 목록에 표시한다. Android 브라우저는 main 소스에 있으며 iPad Ratio 홈·브라우저는 DEBUG 조건 없이 컴파일한다. 외부 설치 브라우저 앱은 별도 항목으로 유지한다.

Ratio 홈 하단 전체 앱·기능/설정 버튼은 56×56, 모서리 16, 1.5 두께의 밝은 테두리, 투명한 안쪽 면을 사용한다. 오른쪽 정렬·버튼 간격 8·접근성 이름을 유지하며 위쪽 가로 구분선은 표시하지 않는다.

### 쉬운 브라우저 라이트·다크 모드

브라우저는 두 모드만 제공하며 다크를 기본 선택한다. 주소창과 도구·메뉴·웹 콘텐츠·구글 간단히 보기가 같은 모드의 색을 사용한다. 두 모드에서 사진·영상 원래 색과 배치·입력값을 유지하고, 원본 보기를 통해 사이트 원래 표현으로 복원할 수 있다.

### Ratio 페이지와 개별 위젯 설정

빈 공간 길게 누르기는 전체 위젯 편집을 열고 뒤로 가면 홈으로 돌아온다. 텍스트 바로가기는 표시·배치 폭을 보존하면서 시작 쪽 한 열 × 88dp/pt만 탭·길게 누르기 입력 영역으로 사용한다. 나머지 부분은 빈 공간이며 접근성 이름·실행·개별 편집은 한 칸 컨트롤에서 한 번 제공한다. 상세 규격은 `08_ratio_home_grid_proposal.md`의 홈의 빈 공간과 텍스트 터치 영역 절을 따른다.


홈은 세로 스크롤 없이 실제 위젯 높이로 줄 단위 페이지를 구성한다. 하단 도구막대만 고정하며 좌우 스와이프와 하단 도구막대의 페이지 점으로 이동한다. 점은 전체 앱·설정 버튼 왼쪽에 두고 선택 12/나머지 6, 터치 48을 사용한다. 별도 페이지 줄·번호·화살표는 없다. 앱·기능 위젯과 검색창을 길게 누르면 해당 항목의 설정만 표시하며 뒤로 가면 홈으로 복귀한다. 설정에서 들어가는 위젯 편집은 전체 목록을 유지한다. 검색 결과·앱 목록·설정은 스크롤할 수 있다. 세부 규격은 `08_ratio_home_grid_proposal.md`를 따른다.

Ratio 페이지는 손가락을 따라 좌우 이동하고 놓으면 감쇠된 스프링으로 정착한다(Android 감쇠 .92·강성 420, iPad 공통 페이지 띠/점 선택 spring .34초·감쇠 .92). 전체 앱·설정 등 화면 진입은 짧은 페이드와 0.97→1 확대, 앱 목록은 아래 56에서 올라오는 전환을 사용한다(Android 280ms, iPad spring .36초·감쇠 .92). Android 시스템 애니메이션 배율을 따르고 iPad 동작 줄이기에서는 이동·확대를 제거한다.

Ratio 검색 위젯은 일반 순서 목록에 포함하며 페이지 안에서 이동·삭제·재추가한다. 탭하면 입력·검색 결과 화면을 열고 뒤로 가면 홈으로 돌아온다. 앱 아이콘형은 기본 1×1(아이콘 48, 이름 16)이며 신규 앱 추가의 기본 유형이다. 모든 위젯에 12색+기본 색상 선택을 제공하고 대비·색상 코드·저장 규칙은 `08_ratio_home_grid_proposal.md`를 따른다.


### Ratio 바로가기 글자 표현

유형 이름은 타일 바로가기·텍스트 바로가기·아이콘 바로가기·통합 검색으로 통일한다. 텍스트 바로가기는 12색을 글자에 적용하며 배경은 투명하다. 앱에는 흰색을 제외한 아이콘의 최빈색을 글자에 단색으로 적용하는 ‘앱 아이콘 색’ 옵션을 제공한다. iPad는 등록한 아이콘 이미지가 있는 앱만 지원한다. 12색 선택은 자동 추출색을 해제한다. 기본 크기·저장·접근성 규격은 `08_ratio_home_grid_proposal.md`를 따른다.


텍스트 바로가기의 글자 크기는 런처 설정의 “텍스트 바로가기 글자 크기”에서 전체에 공통 적용한다. 기본 36, 24~56 범위에서 4씩 조절하며 시스템 글자 배율을 따른다. 위젯별 편집에는 글자 크기 증감이 없다. 과거 개별 textSize는 호환 데이터로만 유지하고 렌더링에는 사용하지 않는다. 색상·아이콘 대표색도 모두 동일한 공통 글자 크기를 사용한다. 목록 글자 크기는 별도 설정이다.


### Ratio 쉬운 브라우저 위젯

`widget:browser`는 카드가 아닌 전체 페이지다. 높이는 현재 가용 화면을 사용한다. 세부 동작은 `08_ratio_home_grid_proposal.md` 전체 페이지 위젯 절을 따른다.

### Ratio 데이지 플레이어 위젯

`widget:daisy`는 현재 페이지를 채우는 독립 독서 화면이다. 기존 서재·독서 UI와 진행 저장소를 사용하며 페이지 이동에도 본문을 유지한다. 재생 중이면 이어 재생하고 유휴 오디오 자원은 해제한다. iPad에서는 중첩 내비게이션 스택 없이 도서 선택 상태로 서재·독서를 전환한다. 서재로 돌아가기와 목차·검색·보기 설정은 위젯 안의 버튼으로 제공한다.


### Ratio 전체 페이지 위젯

유튜브·브라우저 페이지에는 별도 하단 `이전 화면` 버튼을 표시하지 않는다. Android 시스템 뒤로가기와 iPad 접근성 탈출을 사용한다. 유튜브의 쇼츠는 로딩·재생 상태에서 바로 유튜브 홈으로 돌아간다. 일반 영상은 재생창 닫기 → 웹 방문 기록 → 새 창 닫기 순서로 돌아가고, 브라우저는 웹 방문 기록 → 새 창 닫기 순서다. 돌아갈 곳이 없으면 첫 홈 페이지로 복귀한다. 첫 홈의 일반 바로가기에서는 기존 앱 뒤로 동작을 유지한다.

쉬운 유튜브·쉬운 브라우저·데이지 플레이어를 각각 독립된 한 페이지에 표시한다. 기존 바로가기 뒤에 최초 한 번 추가하며 재실행 때 중복 생성하지 않는다. 시스템 안전 영역 안에서 홈 상단 24dp/pt, 전용 위젯 좌우 16dp/pt를 띄운 나머지 폭·높이를 사용한다. 일반 바로가기의 좌우 여백은 32dp/pt이며 하단 탐색 도구는 유지한다. 현재 페이지의 콘텐츠를 활성화하고 웹 미디어는 이탈 시 정지한다. 데이지는 방문한 본문을 유지하며 재생 중인 경우 홈 페이지 이동에도 이어 재생한다. 웹 화면은 페이지 이동 애니메이션 중에도 유지한다. 세 위젯의 캔버스는 투명하며 홈의 현재 사진 배경을 사용한다. 위젯 설정 버튼과 쉬운 유튜브 제목 헤더는 표시하지 않는다. 주소 입력·카드·재생 조작부는 유지하며 유튜브·브라우저 독립 실행 화면도 리보 테마를 기본 사용하고 데이지 독립 화면의 테마는 유지한다. 하단 런처 설정 → 위젯 편집에서 순서·제거를 제공한다. 상세 규격과 플랫폼 범위는 `08_ratio_home_grid_proposal.md` 전체 페이지 위젯 절을 따른다.

### 쉬운 유튜브 피드·위젯 스크롤

영상 카드는 별도 “영상 보기” 문구 없이 전체 영역으로 재생한다. 같은 경로의 피드는 원본 DOM이 일시적으로 비거나 썸네일을 늦게 제공해도 이미 보이는 카드·이미지·스크롤 위치를 유지하며 기본 영상 썸네일로 대체한다. 구독·쇼츠는 숨긴 원본 메뉴의 텍스트와 공개 경로로 이동하고 빈 구독은 안내한다. 유튜브 표면의 가로 드래그는 옆 홈 페이지로 이동하고 세로·대각선 드래그는 웹 스크롤로 처리한다. 입력칸·재생 위치 슬라이더·공식 영상 위/아래 조작 영역은 페이지 넘기기에서 제외하며 영상 가운데의 좌우 드래그는 홈 페이지를 넘긴다. 브라우저도 가로 드래그는 옆 홈 페이지로 이동하고 세로 드래그는 웹 스크롤로 처리한다. 넓은 콘텐츠는 위젯 폭 안에서 줄바꿈·세로 배치하며 두 페이지 모두 하단 점으로 이동할 수 있다. 상세 규격은 `08_ratio_home_grid_proposal.md`를 따른다.

영상 카드의 제목 아래에는 채널·조회수를 표시하고, 업로드 시점은 그 아래 줄에서 길이와 함께 표시한다(예: `2일 전 · 길이 12:34`). 상대 시점은 원래 공개 메타데이터에서 읽고, 길이는 공개 썸네일 배지에서 읽는다. 화면과 접근성 이름 모두 `길이`로 표기한다. 제목·채널 등 정보·길이를 카드 버튼 하나의 접근성 이름으로 합치고 이미지는 장식, 내부 글자는 중복 탐색에서 제외한다. 길이는 `12분 34초`처럼 읽으며 원본에 없는 길이는 추측하지 않는다. 홈·구독·검색·채널 목록의 초기 로딩은 카드·썸네일 자리 표시 없이 비어 있는 목록 영역의 중앙 인디케이터만 표시하고, 추가 로딩은 기존 카드·포커스·스크롤을 유지한 채 인디케이터만 표시한다. 불러오는 동안 `영상 더 불러오기` 버튼은 숨기고 중복 실행을 막는다. 스크린리더에는 하나의 상태만 알리며 동작 줄이기에서는 인디케이터의 움직임을 멈춘다. 12초가 지나도 결과가 없으면 안내와 다시 시도를 제공한다. 상세 크기와 로딩·쇼츠 규격은 `08_ratio_home_grid_proposal.md`를 따른다.

### 쉬운 유튜브 영상 재생·채널·댓글

쇼츠 선택은 기본 여백 안의 가용 화면을 최대한 채우는 9:16 플레이어를 바로 열어 재생을 요청한다. 쇼츠의 제목·별도 재생바/시간/배속·로딩 인디케이터는 숨기고 공식 영상 조작·오류 안내를 유지한다. 일반 영상은 공개 영상 페이지의 16:9 플레이어를 사용한다. 추천 복귀·시험판 배지·별도 10초 이동/재생/자막 버튼 없이 공식 영상 내부 조작, 재생 위치, 재생바 오른쪽의 `1×`·`1.5×` 형식 재생속도 선택을 제공한다. 속도는 테두리·배경 없는 텍스트로 표시하되 56px 터치 영역과 접근성 이름 `재생속도`·각 배율 이름을 유지한다. 아래에는 실제 채널 로고(52px 원형)와 이름을 투명한 한 줄 버튼으로 표시해 채널 영상 목록으로 이동한다. 로고는 원래 YouTube 공개 이미지에서 읽으며 장식으로 중복 낭독하지 않고, 없거나 불러오지 못하면 이름을 유지한다. 채널 행에는 평상시 테두리와 배경색을 두지 않는다. 댓글은 작성자·본문을 여백으로 구분하고 카드의 테두리·배경색을 두지 않는다. 댓글 3개를 제공하고 `댓글 더 보기`는 5개씩 확장한다. 채널·댓글은 원본 공개 DOM으로 구성하고 로딩·사용 불가 상태를 안내한다. 세부 크기·뒤로가기·저장 규격은 `08_ratio_home_grid_proposal.md`를 따른다.

### Ratio 런처 공통 스타일

모든 홈 페이지는 잉크 + 레몬 공통 팔레트와 모서리 8의 사각형 타일을 사용한다. 홈·검색의 뒤에는 숲 안개 사진을 표시하고 타일·선택색은 유지한다. 비교용 복제 페이지 없이 저장한 위젯을 원래 순서로 표시하며 선택한 색이 실제 홈에 적용된다. 세부 규격은 `08_ratio_home_grid_proposal.md` 런처 공통 스타일 절을 따른다.

### Ratio 홈 카드 표시

실행 타일은 테두리 없이 면·간격·이름으로 구분하고 검색 미리보기는 모서리 32의 둥근 면·1px 테두리로 구분한다. 타일 제목은 기본 34dp/pt, 면적 배율 후 24~56, 앱 아이콘형 이름은 18, 홈 검색 미리보기는 기본 20다. 시스템 글자 확대와 자연 높이 측정·줄바꿈·페이지 재계산을 유지한다. 텍스트 바로가기의 사용자 설정과 하단 탐색 도구는 기존 규격을 유지한다.

### 웹 위젯 로딩과 연속 페이지 이동

웹 위젯도 일반 홈과 같은 페이지 이동 경로를 사용한다. 가로 방향을 인식한 뒤에는 실제 웹 화면과 이웃 페이지가 손가락을 따라 연속 이동하고, 놓으면 동일한 스프링으로 한 페이지에 정착한다. 짧은 이동·취소는 원래 페이지로 돌아가며 처음·마지막 페이지 바깥은 이동량을 25%로 줄인다. 넘기는 동안 원래 웹 화면을 제거하지 않고, 현재 페이지와 가까운 웹 세션을 미리 준비한다. 비활성 페이지는 미디어를 정지하고 접근성 탐색에서 제외한다. 하단 페이지 점과 iPad VoiceOver의 페이지 스크롤 동작도 유지한다. iPad는 일반 홈과 웹 위젯을 같은 가로 페이지 띠로 배치하며 동작 줄이기에서는 정착 애니메이션을 생략한다.

브라우저의 네이티브 진행 막대는 웹 화면 상단에 겹쳐 표시하므로 로딩 전후 웹뷰 높이는 유지된다. 같은 팔레트·확대 값은 스타일을 다시 만들지 않으며 초기 DOM 구성 완료 때만 전체 색상 분류를 한 번 보완한다. 일반 웹 문서에는 폭 보정 스캔·준비용 본문 숨김을 적용하지 않는다. 유튜브는 본문 생성 때 검색·메뉴 위치를 먼저 준비하며 초기 목록 로딩에는 카드 모양을 만들지 않는다. 로딩 영역은 높이 `clamp(180px,36vh,360px)`의 빈 공간에 인디케이터 하나만 중앙 표시하고, 준비된 첫 목록은 180ms로 나타낸다. 추가 로딩은 기존 목록을 유지하며 동작 줄이기에서는 페이드를 생략한다. 유튜브의 네이티브 중앙 로딩 표시는 Google 로그인 등 외부 인증 문서에만 사용한다.

### 런처 날씨·타이머 전용 위젯 / 검색 줄

날씨·타이머는 앱/기능 목록 없이 런처 위젯 편집/추가에서만 제공한다. 모서리 8·선택색을 유지하며 검색은 투명한 줄·밑줄·음성 원 버튼으로 구분한다. 세부 데이터·크기·알림·검색 규격은 `08_ratio_home_grid_proposal.md`의 해당 절을 따른다.

### 유튜브 구독 빈 화면·쇼츠·상단 검색

구독 목록이 비었음이 원본 화면에서 확인되면 구독 영상 캐시와 목록을 비우고 `영상 더 불러오기`를 숨긴다. 중앙에 장식용 구독 아이콘(96px 원 안의 64px 선 아이콘), 제목 `아직 구독 영상이 없어요`, 짧은 안내를 여백으로 구분해 표시한다. 바깥 카드 테두리는 없으며 제목은 24~30px, 안내는 19px다. 하나의 polite 상태로 알리고 아이콘은 중복 낭독하지 않는다. 로딩·통신 실패와 확인된 빈 목록을 구분한다.

검색은 별도 메뉴·입력 화면 없이 영상 목록 상단의 입력칸과 검색 버튼으로 제공한다. 검색창 아래에는 홈·구독·쇼츠 세 메뉴가 있으며 구독·검색 결과·채널 목록에서도 같은 입력칸을 사용한다. 입력칸의 연결된 접근성 라벨은 유지한다. 원본 검색 폼이 아직 준비되지 않았으면 입력한 검색어를 인코딩한 공개 `/results?search_query=` 경로로 이동한다. 쇼츠 진입 준비 중에는 기존 검색·메뉴·목록을 유지하며, 플레이어가 준비되면 검색창을 포함한 기존 화면을 180ms로 사라지게 한다. 로그인 화면에서는 검색창을 표시하지 않는다.

쇼츠는 작은 썸네일 카드·별도 목록·흰 테두리 없이 큰 9:16 공식 플레이어 하나로 표시한다. 기본 위젯 여백과 재생창 안쪽 12px를 유지하며, 아래 두 버튼의 높이와 간격 14px를 뺀 화면 안에 영상을 맞춘다. 쇼츠 아래에는 `이전`·`다음` 두 버튼만 두고 별도 채널·댓글·재생바·제목은 표시하지 않는다. 버튼은 최소 56px이고 준비 전·버퍼링 중에는 자리를 유지한 채 시각·접근성 탐색에서 제외한다. 재생 가능 상태에서만 나타나며 원본 이전/다음 이용 가능 상태를 따른다. 쇼츠 진입은 원본 메뉴의 페이지 내 이동을 우선 사용하고, 플레이어 준비 전까지 기존 검색·메뉴·목록을 유지한다. 공식 플레이어 준비 이벤트 뒤에만 포커스·접근성 탐색을 플레이어로 옮기고 기존 화면과 180ms로 교차 전환한다. 동작 줄이기에서는 페이드를 생략한다. 이전·다음 쇼츠는 동일한 공식 iframe에서 영상 ID만 바꾸며 화면을 닫았다 다시 만들지 않는다. 전환 대기 중에는 현재 재생을 멈추고 아래 버튼을 숨기며 새 영상 재생 준비 뒤 복원한다. 이전 영상이 다시 열리지 않게 하는 ID 제한은 유지한다. 시스템 뒤로가기·접근성 탈출은 로딩 중에도 쇼츠를 종료하고 유튜브 홈(`/`)으로 돌아간다. 일반 영상의 채널·댓글·재생 위치·속도와 뒤로가기는 기존 규격을 유지한다.

### 위젯 추가 화면

편집 화면에서 추가 동작은 `위젯 추가` 버튼 하나로 제공한다. 진입하면 `VisionCraft 위젯`·`모든앱`을 나란히 표시하고 VisionCraft 탭을 기본 선택한다. VisionCraft 위젯은 기능·날씨·타이머/알람·검색·쉬운 유튜브·쉬운 브라우저·데이지를 한 목록으로 표시한다. 앱/기능 구분 탭은 두지 않고 `앱 바로가기` 항목에서만 앱 선택 하위 화면으로 이동한다. 앱을 고르면 기본 1×1 아이콘 바로가기로 추가하며 실행하지 않는다. 이미 추가한 항목은 추가됨 상태를 표시하고 중복 저장하지 않는다. 추가에 성공하면 추가 화면·편집·개별 설정 창을 닫고 해당 위젯이 놓인 홈 페이지로 이동한다. 위젯 ID를 실제 행 높이와 페이지 배치에 대응시켜 찾으며 앱 바로가기 대상은 실행하지 않는다. Android 외부 앱 위젯은 제공자 승인·설정이 완료된 뒤 같은 동작을 수행하고 취소·실패 시 이동하지 않는다. 목록 안에서 검색하며 하위 앱 목록의 뒤로/완료는 VisionCraft 위젯 목록, 최상위 추가 화면의 뒤로/완료는 편집으로 돌아간다. 홈에서 편집에 진입한 복귀 맥락도 유지한다.

`모든앱`은 Android 설치 앱의 위젯 미리보기·제공자 추가 승인 경로를 직접 표시한다. 별도의 `다른 앱 위젯 추가` 버튼은 편집에 두지 않는다. iPadOS는 외부 앱 위젯 호스팅이 불가능하므로 같은 탭 안에서 시스템 홈에 위젯을 추가하는 안내를 표시한다. iPad의 `앱 바로가기`는 기존에 등록한 앱 링크를 사용한다. 날씨·타이머를 일반 실행용 앱/기능 목록에 추가하지 않고 위젯 추가의 VisionCraft 목록에만 포함한다. 기존 위젯의 크기·색·순서·저장 형식은 유지한다.

구현: Android `LauncherScreen`의 widget_add/widget_apps, iPad `RatioLauncherView.widgetAddCatalog`·`widgetAppShortcuts`.

### 유튜브 자막 기본 끔·채널과 댓글 구분

일반 영상과 쇼츠 모두 새 플레이어의 준비·자막 모듈 변경·최초 재생 이벤트에서 자막을 기본 꺼짐으로 요청한다. `cc_load_policy=0`만으로 강제 꺼짐을 보장하지 않으므로 실행 중 노출되는 모듈 API의 자막 트랙 비우기·자막 모듈 해제를 함께 사용한다. 트랙 옵션은 실제로 노출될 때만 설정하며 프레임 내부 DOM·로그인·계정 설정을 읽거나 바꾸지 않는다. 모듈 해제가 확인되면 초기 처리를 끝내고, 최대 4회·최초 재생 후 8초 범위로 제한해 반복 이벤트와 사용자의 이후 직접 조작을 방해하지 않는다. 모듈 기능이 없는 플레이어는 기본 자막 꺼짐 요청만 유지한다. 영상 픽셀에 포함된 글자는 변경하지 않는다.

일반 영상의 채널 행은 로고 52px·이름 23px 굵게·보조 문구 `채널 영상 보기` 14px·장식용 꺾쇠로 구성한 투명 버튼이다. 최소 높이 80px와 연결된 접근성 이름을 유지한다. 댓글은 별도의 `댓글` 제목(18px)과 유튜브 원본 헤더·댓글 진입 버튼·현재 영상의 공개 페이지 데이터에서 읽은 전체 댓글 수(14px) 아래 본문을 20px/행간 1.7로 먼저 표시하고, 작성자는 그 아래 14px의 보조색으로 구분한다. 댓글 사이에는 여백 30px를 두며 카드 테두리·채움색은 사용하지 않는다. 원래 댓글 본문·작성자와 더 보기 동작은 유지한다. 쇼츠 아래 버튼의 보이는 이름과 접근성 이름은 `이전`·`다음`이며 다른 쇼츠 재생 동작과 로딩 중 숨김은 유지한다.

### 홈 복귀와 위젯 편집 선택창

위젯 편집은 현재 값이 표시되는 `형태`·`크기`·`색상` 가로 전체 행으로 구성한다. 각 행을 누르면 해당 선택창이 열리고, 선택을 저장한 뒤 닫힌다. 앱 아이콘 대표색도 색상 선택창에 포함한다. 형태는 일반 바로가기, 크기는 텍스트형을 제외한 크기 조절 가능한 위젯, 색상은 자체 위젯에 제공한다. 전체 페이지 위젯은 고정 안내만 표시한다. 위로·아래로·삭제는 편집 카드에 그대로 둔다. `위젯 추가` 버튼은 편집 화면 가로 전체를 채운다.

런처 화면에서 리모컨 홈을 누르면 편집·검색·선택창을 닫고 첫 페이지로 돌아간다. 런처 밖에서는 기존 앱 홈으로 이동한다. iPadOS 시스템 홈 버튼은 앱이 가로챌 수 없으며 다른 앱 위젯도 앱 내부에 호스팅할 수 없다.

### 회전과 낮은 화면의 런처 배치

회전·창 크기 변경 시 현재 페이지의 첫 위젯을 새 페이지 구분에서 찾아 같은 위젯이 계속 보이게 한다. 페이지 번호가 달라져도 유튜브·브라우저의 세션과 표시 뷰를 유지하며 회전으로 홈 복귀나 재탐색을 요청하지 않는다. 전체 페이지 위젯은 새 안전 영역 안의 가용 폭·높이를 사용한다. 일반 위젯은 높이 제한 없이 자연 높이를 먼저 측정해 페이지를 나누고, 한 줄이 화면보다 크면 해당 줄을 한 페이지에 놓아 세로 스크롤한다. 글자·버튼을 화면 높이에 맞춰 축소하거나 잘라내지 않는다. 저장한 순서·열·행·색은 바꾸지 않으며 회전 중 가로 드래그는 취소한다.

### 유튜브 목록의 물결 인디케이터

초기 로딩은 144×80px의 장식용 물결과 아래 17px 상태 문구를 중앙에 표시한다. 강조색의 가는 SVG 곡선 세 겹이 3.6·4.8·6초 주기로 서로 다른 방향과 속도로 흐른다. 한 주기 144 단위를 반복한 경로로 이음새를 맞추며 양끝은 점차 투명해진다. 바탕에는 정적인 은은한 빛만 두고 카드·테두리 패널은 추가하지 않는다. 추가 로딩은 80×48px의 작은 물결을 상태 문구 옆에 표시한다. CSS 위치 이동만 애니메이션하며 별도 타이머·캔버스·영상·블러 필터는 사용하지 않는다. 숨김·동작 줄이기에서는 정적인 물결을 표시하고 강제 색상에서는 시스템 글자색 선을 표시한다. 상태 문구·접근성 알림·기존 로딩 영역 높이는 유지하며 쇼츠에는 별도 로딩 표시를 추가하지 않는다.

### 현재 위치 날씨와 2×2 기본 크기

날씨·타이머는 2×2로 추가한다. 작은 위젯에는 시간과 큰 재생·설정 버튼만 표시하고 모드·시간 조절은 별도 설정 창에서 제공한다. 지역 선택은 없고 날씨는 현재 위치만 사용한다. 위치 권한·서비스가 없으면 안내와 재시도/설정 경로를 제공한다. 세부 위치·캐시 규격은 `08_ratio_home_grid_proposal.md`를 따른다.

### 유튜브·브라우저 공통 리보 테마

유튜브 로그인 안내·플레이어 바깥 조작은 기존 런처 리보 테마를 유지한다. 브라우저는 독립 실행·홈 위젯 모두 라이트/다크 두 모드를 사용하고 다크를 기본 선택한다. 홈 브라우저의 다크 모드는 이전의 어두운 숲 사진 배경 위에 투명한 캔버스와 흰 글씨를 사용한다. 일반 홈 페이지는 밝은 산 사진을 유지하며 쉬운 유튜브는 어두운 숲 사진을 사용한다. 주소창·도구·메뉴·웹 콘텐츠·구글 간단히 보기도 선택 모드의 색을 따른다. 유튜브 목록·로그인·플레이어의 별도 색 규격은 유지한다.

### 유튜브 홈 영상 목록 새로고침

홈 추천 목록의 `지금 불러온 추천 N개` 문구 대신 `영상 목록 새로고침` 버튼을 표시한다. 기존 안내 위치에 투명 바탕·밑줄·18px 글자·최소 높이 56px의 글자 너비 버튼으로 제공한다. 누르면 유튜브 홈 원본 문서를 다시 불러와 카드 캐시와 목록을 새로 구성한다. 새로고침 진행 중 중복 실행을 막고 로딩을 안내한다. 로그인은 기존 웹 저장소를 유지하며 구독·검색·채널 목록의 결과 안내와 추가 로딩은 유지한다. 버튼은 홈에만 표시하고 로그인 전·목록 로딩 중에는 비활성화한다. 기존 오류 메시지는 상태 영역으로 계속 제공한다.

### 날씨·타이머 요약과 큰 조작 버튼

2×2 기본 크기에서 여백은 12, 간격은 6이다. 긴 지역명은 두 줄과 말줄임으로 표시하며 접근성에는 원래 이름을 유지한다. 날씨는 지역명 20·기온 56·상태 22로 표시하고 새로고침은 오른쪽 아래 지름 56·아이콘 28의 원형 버튼이다. 상태 아래에 16 크기의 마지막 갱신 시각을 표시한다. 기온·상태를 누르면 체감·최저/최고·갱신 시각·출처의 상세 창을 연다. 타이머는 제목 없이 72 크기 고정폭 시간을 크게 표시한다. 오른쪽 아래에 지름 56·아이콘 28의 원형 재생/일시정지와 시간 설정 버튼을 간격 8로 나란히 놓는다. 설정 버튼은 재생 중에도 표시하며 적용하면 기존 타이머를 취소하고 새 설정으로 바꾼다. 알람 종류는 시간의 접근성 이름에 포함하고 종료 안내·오류는 별도로 유지한다. 시간 숫자는 한 줄을 유지하고 아주 큰 글자에서 가로 스크롤하며 시스템 글자 배율을 줄이지 않는다. Android 기온은 68sp·타이머 시간은 88sp 행간, 18sp 본문은 24sp, 16sp 본문은 22sp 행간을 명시한다. iPad의 시간 설정·날씨 상세 창은 고정 다크 면과 밝은 글자·조작 색을 사용해 선택한 위젯 색과 독립적으로 읽히게 한다. 위젯 색·크기·순서 편집은 길게 누르기와 화면 읽기의 위젯 설정 동작, 기존 전체 위젯 편집에서 제공한다.

### 브라우저 홈의 검색·음성·즐겨찾기

구글 기본 홈(`/`·`/webhp`)에서는 네이티브 주소창·도구 줄을 표시하지 않는다. 기본 검색은 구글만 사용하며 일반 페이지와 검색 결과에서는 기존 주소창·도구가 유지된다. 독립 실행의 닫기와 시스템 뒤로가기·접근성 탈출은 유지한다. 검색 입력은 브랜드명 없이 `검색`이며 통합 검색창과 같은 최소 56px 음성 버튼·입력 후에만 나타나는 52px 위쪽 화살표 전송 버튼으로 구성한다. 좁은 폭에서도 버튼은 최소 48px다. URL 또는 도메인을 입력하면 해당 HTTPS 사이트로 이동하고 일반 문장은 공개 구글 `/search?q=`로 이동한다. `javascript:`·`file:`·`data:` 등은 실행하지 않고 오류를 표시한다. 키보드 검색도 같은 처리를 사용한다.

음성 버튼은 `rivo-browser://voice`라는 값 없는 동작 링크를 사용한다. 네이티브는 활성 웹뷰의 HTTPS 구글 홈/검색 결과 또는 쉬운 유튜브 페이지에서 온 상위 프레임 요청만 처리한다. 유튜브 인증·임베드 문서는 제외한다. Android는 앱·기능 검색과 같은 시스템 음성 입력 화면, iPad는 같은 `STTManager`의 기기 내 인식을 사용한다. 결과는 네이티브 주소/검색 처리에 전달하며 원래 웹 검색 입력이나 인증 정보를 읽지 않는다. 취소·실패를 처리하고 iPad는 화면 이탈·백그라운드 진입 시 자신이 시작한 녹음을 정지한다.

즐겨찾기 네이버·다음·유튜브·위키백과는 사이트별 컬러 면 72px·모서리 24 안의 로컬 벡터 기호 48px 아래 이름 18px를 가운데 정렬한다. 즐겨찾기 목록의 칸은 왼쪽부터 배치한다. 큰 카드 면·도메인·이동 화살표는 두지 않는다. 투명 링크는 최소 높이 136, 간격 12, 검색창 전체 폭을 사용하며 기본 4열·480px 이하 2열이다. 키보드 포커스는 3px 외곽선으로 표시하고 호버는 3px 상승하며 동작 줄이기에서는 정지한다. 기호는 장식으로 접근성 중복 읽기를 막고 외부 파비콘 요청 없이 기존 네 링크의 목적지를 유지한다. Browser 로고·검색창·즐겨찾기 영역을 세로 중앙에 배치하며 즐겨찾기 항목은 왼쪽 정렬한다. 내용이 길면 세로 스크롤한다. 원본 구글의 인증·동의·보안 문자·미인식 화면으로 복귀하는 규격은 유지한다.

### 유튜브 목록 팔레트와 통합 검색창

유튜브 홈·구독·검색·채널 목록의 기본 팔레트는 밝은 바탕 `#F5F3EE`·흰 면·글자 `#252B28`·보조 글자 `#4C5D54`·초록 강조 `#17644E`·경계 `#69786F`, 어두운 바탕 `#101714`·면 `#1B2821`·글자 `#F1F5F2`·보조 글자 `#BCCDC2`·민트 강조 `#A8DEC0`·경계 `#9BAFA2`다. 위젯은 어두운 목록 색과 투명 캔버스를 유지한다. 목록의 물결 인디케이터는 위젯·어두운 화면에서 리보 테마의 연한 노란 강조색, 독립 밝은 화면에서 청회색 `#405A7A`를 사용하며 빛 번짐도 같은 색이다. 영상 재생창과 로그인 안내는 리보 테마를 유지한다. 영상 카드는 화면 모드·위젯 여부와 관계없이 옅은 회색 면 `#D1D5DB`·진한 글자 `#252B28`·보조 글자 `#4C5D54`·경계 `#69786F`·포커스 `#17644E`를 사용한다. 썸네일 아래 제목·채널·시점·길이도 이 카드 색을 따른다.

### 날씨 일러스트·외부 위젯·브라우저 즐겨찾기

날씨 기온 옆에 64dp/pt 컬러 벡터 일러스트를 표시한다. 맑음·구름·비·눈·안개·뇌우 코드를 실제 상태와 맞추며 노랑 해·밝은 구름·파랑 강수·노랑 번개를 사용한다. 그림은 장식으로 화면 읽기에서 제외하며 상태 텍스트는 유지한다. 로컬 Canvas로 그려 이미지 다운로드나 새 권한이 없다. Android 외부 위젯은 이름·설정 도구줄 없이 전체 영역을 사용하며 제공자 최소/최대 크기 계산에서도 도구줄을 빼지 않는다. 편집은 길게 누르기와 접근성 동작·전체 편집으로 제공한다. iPad는 외부 위젯 호스팅이 지원되지 않아 해당 변경이 없다. 브라우저 홈 즐겨찾기는 사이트별 색의 72px 아이콘 면·48px 벡터·18px 이름을 사용하고 도메인·화살표·큰 카드 면은 제거한다.

### 런처 홈 검색창 통일

홈 검색 미리보기와 입력 화면은 유튜브·브라우저와 같은 모서리 32의 둥근 검색창이다. 기본 높이 88, 왼쪽 여백 20·오른쪽/위아래 6, 검색 기호 28, 기본 글자 20, 음성 버튼 56을 사용한다. 기본 면은 #101010의 75% 불투명도이며 밝은 1px 테두리(70%)를 두고 별도 밑줄·음성 버튼 면은 표시하지 않는다. 선택색은 저장값을 유지해 면에 적용하고 어두운 글자·기호·테두리로 읽는다. 입력 중에는 기존 52 크기 위쪽 화살표 전송 버튼을 제공한다. 검색·음성·키보드·AI/브라우저 분기·길게 눌러 편집과 포커스 표시, 저장 크기·순서는 유지한다.

### Browser 홈과 즐겨찾기 추가

브라우저 기본 홈은 `Browser` 영문 로고(38~56px, 굵기 600, 자간 -2px, 작은 장식 점)·검색창·즐겨찾기를 하나의 영역으로 구성해 가용 웹 높이의 세로 중앙에 놓는다. 로고와 검색창은 가운데, 즐겨찾기 칸은 왼쪽부터 배치하고 각 칸의 아이콘 아래 이름은 가운데 정렬하며 검색창과 같은 전체 폭을 사용한다. 내용이 길거나 키보드가 열리면 세로 스크롤한다. 즐겨찾기 목록 마지막의 점선 테두리 `추가` 아이콘은 앱의 웹 주소 입력창을 연다. 이름 입력은 요구하지 않고 추가 중 사이트 정보를 가져오는 진행 상태를 표시한다. HTTPS 주소·이름을 저장한 사용자 즐겨찾기는 최대 24개이며 재실행에도 유지한다. 같은 주소를 다시 추가하면 이름을 갱신한다. 사용자 항목은 페이지의 og:site_name·application-name·og:title·title 순서로 이름을 정하고, apple-touch-icon·icon·favicon.ico 순서의 이미지를 96px 이하 PNG로 저장해 72px 면 안에 48px로 표시한다. 정보가 없거나 접근에 실패하면 도메인 이름과 이름 첫 글자의 로컬 기호를 사용하며 기본 네 사이트 링크는 유지한다.

일반 위젯 추가는 마지막 홈에서 측정한 실제 줄 높이·페이지 가용 높이·줄 사이 간격을 사용한다. 현재 페이지의 남는 열에 들어가고 줄 높이 증가도 수용할 수 있는 자리를 먼저 선택하며, 없으면 같은 페이지에 새 줄을 넣을 위치를 확인한다. 삽입 후의 줄 묶음·높이·페이지를 다시 계산해 현재 페이지의 기존 항목과 새 항목이 함께 들어가는 후보만 사용한다. 현재 페이지에 맞는 자리가 없으면 다른 일반 페이지를 확인하고, 모두 부족하거나 측정 정보가 없으면 첫 전체 페이지 위젯 앞에 추가한다. 기존 항목의 상대 순서·크기·색은 유지하며 새 항목만 선택한 위치에 삽입한다. 앱 자체 위젯과 Android 외부 앱 위젯 모두 이 기준을 사용하고, 외부 위젯은 승인·설정 성공 후 배치를 확정한다. 추가가 성공하면 편집 화면을 닫고 실제 추가된 위젯의 페이지를 표시한다. 기존 전체 페이지 뒤의 날씨·타이머는 최초 한 번 일반 홈 영역으로 옮기며 이후 사용자 순서를 보존한다.

위젯 추가 성공 문구는 홈이나 추가 화면에 별도로 표시하지 않는다. 추가 목록의 `추가됨` 상태와 오류·취소 안내는 유지한다. 브라우저 즐겨찾기는 왼쪽부터 배치하는 격자 안에서 각 항목 폭 112px(좁은 칸에서는 칸 폭 이하), 아이콘과 아래 이름을 같은 중심에 정렬하며 긴 이름은 줄바꿈한다.

날씨·타이머는 일반 네모 버튼 타일과 같은 열 너비·행당 88 및 사이 간격 12(2행 기본 높이 188)를 사용한다. 같은 줄의 버튼 타일이 긴 이름·큰 글자로 더 높아지면 날씨·타이머의 바깥 면도 그 줄의 높이에 맞춘다. 내부의 큰 글자·조작 버튼·스크롤, 저장된 열·행·선택색은 유지한다.

영상 댓글 수는 원본의 전체 댓글 수를 사용하며 천·만·K·M 등 원본의 축약 표기는 유지한다. 처음 보여주는 3개와 더 보기로 늘린 목록 길이를 전체 수로 표시하지 않는다. 전체 수를 읽지 못했지만 댓글 본문이 있으면 숫자를 생략하며, 로딩·사용 불가·불러오기 실패 안내는 유지한다. 읽은 전체 수는 해당 영상을 닫을 때까지 보존한다.

### 데이지 위젯의 본문 유지와 메모리

데이지는 최초 방문 뒤 같은 런처의 홈 페이지 이동 동안 선택한 책과 독서 화면·정확한 스크롤을 유지한다. 숨은 페이지는 터치·접근성 탐색에서 제외한다. 이미 재생 중이면 홈 페이지 이동에도 이어 재생하고, 멈춘 상태로 이동하거나 앱이 배경으로 가면 유휴 오디오 재생 자원을 해제한다. 앱 배경에서는 재생을 일시 정지한다. 책 변경·서재 복귀·위젯 제거·런처 종료 시 기존 독서 세션을 정리한다.

내장 웹 본문은 현재 화면과 앞뒤 약 두 화면의 블록만 렌더링한다. 멀어진 블록은 높이를 보존한 빈 껍질과 가벼운 HTML 문자열로 남기고 자손·이미지 노드를 제거하며, 스크롤·목차·검색·재생 위치 이동 때 복원한다. 표·목록·그림 묶음은 원래 구조를 보존하는 단위로 유지하며 블록이 큰 경우 화면 수보다 더 남을 수 있다. 키보드 포커스·선택 텍스트·재생 강조 블록은 제거하지 않는다. TalkBack/VoiceOver 사용 중에는 읽기 순서와 접근성 포커스를 위해 블록 제거를 끄고 본문을 복원한다. iPad의 일반 텍스트 보기는 기존 현재 장의 LazyVStack을 유지한다.

메모리 부족 시 다른 홈 페이지 또는 앱 배경에 있는 비재생 데이지 본문을 해제하고 책·읽던 위치를 보존한다. 다음 방문에서 기존 진행 저장소로 복원하며 이 복원만으로 자동 재생하지 않는다. 일반 페이지 이동에는 파일을 다시 열거나 스크롤을 재설정하지 않는다. 목차·검색용 텍스트와 인덱스는 화면 블록과 별도로 유지한다. 실제 메모리 절감량은 기기에서 측정하지 않았다.

즐겨찾기 메타데이터는 추가할 때 HTTPS로만 조회하며 웹뷰의 로그인 쿠키·인증정보를 사용하지 않는다. 전체 조회 예산은 12초이며 HTML은 256KiB, 아이콘은 512KiB까지 읽고 원본 스크립트는 실행하지 않는다. 아이콘은 로컬 PNG 데이터로 저장해 홈을 열 때마다 사이트에 다시 요청하지 않는다. 추가 취소 후에는 항목을 저장하지 않는다. 기존 아이콘 없는 즐겨찾기도 계속 표시한다.

### 유튜브 재생 화면의 회전 맞춤

일반 영상은 공식 iframe의 16:9 비율을 유지하며 실제 위젯의 가용 폭과 높이 중 더 작은 제한에 맞춘다. 제목·재생 위치·속도·시간 줄과 내부 여백을 위한 높이를 남겨 가로 회전에서도 영상 아래가 잘리지 않게 한다. 쇼츠는 9:16과 이전/다음 버튼 공간을 유지한다. 실제 컨테이너·조작부 크기와 창·visualViewport 변경 때 치수를 다시 맞추며 기존 iframe·재생 위치를 유지한다. 채널·댓글은 같은 세로 스크롤 안에서 계속 표시하고 플레이어를 닫을 때 크기 관찰과 이벤트를 해제한다.

쇼츠는 공식 플레이어의 영상 종료(ENDED) 때 기존 `다음` 동작으로 다음 쇼츠를 자동 재생한다. 영상별 종료 처리를 한 번만 실행하며 전환 대기 중 반복 종료 신호는 무시한다. 다음 항목이 없거나 비활성이면 현재 영상에 머문다. 일반 영상 종료 동작은 유지한다. 타이머·알람의 시간 숫자는 72dp/pt(Android 행간 88sp)이며 큰 글자와 가로 스크롤을 유지한다. 날씨 기온은 56 크기·68 행간이다.

데이지 읽기 강조는 노랑 #FFF3B0 면과 검정 #111111 글자의 조합이다. Android 원본 문서의 강조한 문장·단어와 자식 글자에도 글자색·text-fill을 적용해 다크 본문 흰 글자와 구분하며 강조가 해제되면 원래 스타일로 돌아간다. iPad의 읽는 단어·문장도 같은 검정 글자를 유지한다. 하단 재생 패널은 모서리 24, 1px 보조색 25% 테두리, 그림자 8과 바깥 가로 12·세로 8 여백을 사용한다. 슬라이더·재생·이동 단위 버튼의 크기와 접근성 이름은 유지한다.

### 구글 검색 결과의 AI 근거와 사이트 설명

Google의 원본 AI 개요와 출처 링크·펼치기 동작을 유지한다. 출처의 캐러셀/목록과 서로 다른 외부 링크가 있는 카드 행을 찾아 표시용 속성만 붙이고, 해당 행과 조상 래퍼의 가로 이동·음수 오프셋·고정 폭·클리핑을 해제한다. 화면에 펼친 근거 카드의 캐러셀용 접근성 숨김·비활성 탐색 속성은 복원 가능하게 조정해 링크를 모두 탐색할 수 있게 하며 원본 보기에서는 되돌린다. 원본 노드를 복제하거나 이벤트를 다시 연결하지 않는다. 근거는 최대 폭 760px 안에서 최소 260px 열과 간격 14px의 격자로 배치해 공간이 충분하면 두 개씩, 좁으면 한 개씩 표시한다. 제목·그림과 형제인 빈 링크가 접근성 이름으로 카드를 덮는 Google 구조도 목록 항목으로 인식한다. 고정 폭 내부 카드 껍질을 열 너비로 맞추고 원본 덮개 링크의 클릭 영역은 카드 전체에 유지한다. 카드의 내부 여백은 14px·모서리 14px·글자 18px이며 강한 색 면 대신 중성 회색 8% 면을 쓴다. 선택한 모드의 글자·포커스 색을 유지한다. 단순화를 끄면 출처용 표시 속성도 제거한다.

사이트 상위 5개는 호스트 16px → 제목 23px → 원문 설명 18px/행간 1.7 순서로 표시한다. 큰 채움 면과 사각 테두리는 없애고 투명 바탕·위아래 여백·얇은 구분선으로 결과를 구분한다. 제목은 선택한 팔레트의 기본 글자색, 설명·호스트는 같은 글자의 보조 농도다. 설명은 각 결과의 원본 설명 요소 또는 해당 결과 안의 본문 텍스트에서 최대 420자로 읽으며 설명이 없으면 생략한다. 다른 결과·광고·버튼·사이트 이동 링크의 문구를 설명으로 합치거나 새 요약을 생성하지 않는다. 결과 하나의 링크 안에 제목·호스트·설명을 두고 원래 URL을 유지한다. 늦게 도착한 설명은 URL별 기존 노드를 갱신해 포커스와 스크롤을 유지한다.

영상에서 뒤로 돌아오면 기존 추천·구독·검색·채널 목록과 목록 스크롤을 복원한다. 현재 탭의 sessionStorage에 경로별 최대 120개 카드의 공개 제목·주소·썸네일 URL·길이·보조 문구와 스크롤을 최대 4개 목록까지 보관한다. 복원한 목록은 원본의 새 추천으로 자동 교체하지 않으며 영상 시청 중의 추천은 목록 캐시에 섞지 않는다. 유튜브를 떠나거나 앱이 비활성인 시간이 30분을 넘으면 다음 목록 진입 때 갱신하고, 홈의 `영상 목록 새로고침`을 누르면 즉시 캐시를 비우고 새로 불러온다. 영상 시청 중에는 목록 만료 때문에 영상을 중단하지 않는다. 로그아웃 상태가 확인되면 목록 캐시를 지운다.

댓글 첫 로딩·추가 로딩 중에는 `댓글 더 보기`를 숨기고 본문 영역에 로딩 접근성 상태를 표시한다. 처음 15초 동안 댓글을 읽지 못하면 상태 안내와 `댓글 다시 불러오기`를 제공하며, 사용 불가·전체 0개 상태에서는 더 보기·재시도를 표시하지 않는다. 새로고침 버튼은 글자 너비의 터치 영역과 56 높이를 사용하고 눌림·호버·포커스 때 배경을 채우거나 탭 하이라이트를 표시하지 않는다. 키보드 포커스 외곽선은 유지한다.

### 브라우저 검색 입력 포커스

브라우저 구글 홈·검색 결과의 검색 입력에는 포커스 시 별도의 사각 외곽선·그림자를 표시하지 않는다. 입력 포커스는 검색창 바깥의 모서리 32 둥근 테두리로 표시하며, 전송·음성·즐겨찾기 버튼의 키보드 포커스 표시는 유지한다.

전체 댓글 수는 모바일 댓글 캐러셀 제목(`carouselTitleViewModel.subtitle`)과 댓글 패널 헤더(`engagementPanelTitleHeaderRenderer.contextualInfo`)의 원본 값을 함께 읽는다. 화면에 숫자가 아직 렌더링되지 않았으면 현재 영상 ID와 일치하는 `ytInitialData`의 같은 필드를 사용한다. 페이지 데이터는 객체·JSON 문자열을 모두 지원하고 데이터 참조·영상 ID별로 결과를 재사용하며, 수가 없을 때만 2초 뒤 다시 확인한다. 답글·현재 펼친 댓글 수를 전체 수로 대신 표시하지 않으며 별도 API·새 네트워크 요청·계정 데이터 접근은 없다.

### 브라우저 광고 차단

일반 쉬운 브라우저·홈 브라우저 위젯은 광고 차단을 기본으로 켠다. 도구 메뉴의 `광고 차단`에서 켜짐·꺼짐을 읽고 바꿀 수 있으며 변경하면 현재 페이지를 새로 불러온다. 선택은 다음 실행에도 유지한다. 번들에 있는 광고 서버 목록·명시적인 광고 컨테이너 선택자만 사용하고 외부 필터 목록·VPN·방문 내역 전송은 없다. Android는 하위 리소스 요청을 로컬에서 차단하고, iPad는 WKContentRuleList의 광고 리소스 차단 규칙을 사용한다. 같은 스크립트가 광고 컨테이너·광고 iframe을 화면과 접근성 탐색에서 숨기며 새로 추가된 광고에도 적용한다. 기사 사진·본문·메뉴·일반 iframe은 유지하고 클래스 이름에 단순히 ad가 들어간다는 이유로 숨기지 않는다.

현재 필터는 Google·NAVER Ad Manager·DigitalCamp·MCI 등의 광고 서버와 소년한국일보의 `/adManager/` 자원, `.ad-template` 등의 광고 슬롯을 포함한다. 쉬운 유튜브 전용 세션·도서 웹뷰에는 적용하지 않고 YouTube·Google 계정·reCAPTCHA 문서는 예외로 둔다. 모든 사이트의 광고를 보장하는 기능이 아니며 본문 접근을 제한하는 구독·유료 장벽을 해제하지 않는다. iPad 규칙은 최초 준비 때 컴파일한 뒤 재사용하고 CSS 숨김은 문서 시작부터 적용한다. 구현: Android `BrowserAdBlocker.kt`·`browser-ad-block.json`·`browser-ad-block.js`·`AccessibleWebSession`; iPad `BrowserAdBlocker.swift`·`AccessibleWebBrowserModel`. 양쪽의 호스트·경로·선택자 목록은 같은 규격으로 갱신한다.

### 브라우저 위젯의 원본 배치

브라우저 위젯은 사이트의 반응형 배치·격자·표·이미지 비율·고정 위치를 유지하고 선택한 비례 확대만 적용한다. 가로 넘침만으로 캐러셀·숨긴 콘텐츠를 세로로 펼치거나 표·행·셀과 접근성 역할을 다시 쓰지 않는다. 넓은 문서나 가로 스크롤 영역에서는 웹 스크롤을 우선하고 하단 페이지 점으로 홈 페이지를 이동한다. 입력·링크·이벤트 처리·접근성 이름·사이트 주소는 원본을 유지하며 사이트 이름에 따른 배치 예외나 자동 모바일 주소 전환은 두지 않는다. 구현은 Android `launcher-widget.js`, iPad `LauncherWebAppearance`다.

### 밝은 배경에서 브라우저 다크 모드 비교

Ratio 홈의 고정 배경은 밝은 산 사진(`launcher_ratio_blue_mist` / `RatioBlueMist`)에 검정 8%·하단 추가 10% 그라데이션이다. 기존 숲 사진은 자산에 보존한다. 브라우저의 기존 `dark` 선택을 `다크 모드`로 표시하며 바탕 #202124·면 #292A2D·글자와 링크 #F1F3F4·경계 #9AA0A6을 구글 간단히 보기와 일반 사이트에 함께 적용한다. 사진·영상·브랜드 미디어의 색과 원래 배치는 유지한다. 홈 브라우저의 다크 모드 캔버스는 투명하며 그 뒤에 어두운 숲 사진(검정 60%·하단 추가 25%)을 표시한다. 다른 페이지와 브라우저 라이트 모드의 홈 배경은 밝은 산 사진을 유지한다. 선택 메뉴에는 라이트 모드·다크 모드만 두며 초기 선택은 다크 모드다. 홈 브라우저는 다크 모드에서 투명하고 라이트 모드에서 밝은 면을 사용하며 원본 보기 전환·광고 차단·검색·확대 기능을 유지한다.

### 브라우저 모드 선택

선택지는 라이트 모드(`light`)·다크 모드(`dark`) 두 가지이며 새 세션의 기본은 다크 모드다. 선택은 기존처럼 세션 동안 유지한다. Ratio 홈은 기본 산 사진을 유지하고 브라우저 다크 모드와 쉬운 유튜브 페이지에서 이전의 어두운 숲 사진으로 바꾼다. 홈 브라우저의 다크 웹 캔버스는 투명하고 라이트 웹 캔버스는 밝은 면을 사용한다. 원본 보기 토글은 모드 선택과 별도로 유지한다.

### 홈 브라우저 다크 모드의 사진 배경

홈 브라우저 다크 모드와 쉬운 유튜브 페이지에 숲 사진(`launcher_ratio_forest_mist` / `RatioForestMist`)과 검정 60%·하단 추가 25% 막을 적용한다. 웹 루트·본문·기본 바탕은 투명해 이 사진이 비치며 본문 뒤에 불투명한 검정/회색 면을 추가하지 않는다. 카드·입력창·메뉴·미디어와 원래 배치는 유지한다. 브라우저 라이트 모드와 일반 홈 페이지는 기존 밝은 산 사진을 유지하고, 쉬운 유튜브의 목록·영상·댓글은 어두운 숲 사진을 사용한다. 두 모드 선택·기본 다크·광고 차단 규격은 유지한다.

### 쉬운 유튜브의 고정 배경

홈의 쉬운 유튜브는 목록·영상·쇼츠·댓글 화면 모두 어두운 숲 사진과 검정 60%·하단 추가 25% 막을 사용한다. 홈의 기본 사진이 바뀌어도 이 배경은 독립적으로 유지한다. 기존 투명 캔버스·댓글 글자·영상 픽셀·재생 동작은 유지하며 불투명한 검정 면을 추가하지 않는다. 브라우저 다크 모드에도 같은 사진을 사용한다.

### 날씨 자동 갱신과 원형 새로고침

날씨 자동 갱신은 마지막 성공 시각 기준 30분 간격으로 보이는 페이지·앱 활성 상태에서만 실행한다. 화면 복귀 때 30분 미만의 자료는 위치 재조회 없이 재사용하고, 오래됐거나 자료가 없으면 즉시 위치 한 번과 예보를 요청한다. 수동 새로고침은 신선도·재시도 대기를 한 번만 무시하며 로딩 중 중복 입력은 막는다. 실패하면 지역명·날씨를 함께 보존하고 갱신 시각·오류를 표시하며 5분 뒤 재시도한다. 실패 대기는 메모리에만 유지하고 페이지 복귀가 대기를 초기화하지 않는다. 캐시는 최대 6시간까지만 표시하며 미래 시각·6시간 이상 자료는 제거한다. 위치 권한이 거부되면 이전 날씨를 숨기고 권한 설정을 안내한다. 위치와 예보는 성공 시 함께 교체하며 주기 위치 구독·백그라운드 예약 작업은 없다.

날씨는 지역명 20·행간 26, 기온 56·행간 68, 상태 22·행간 28로 표시한다. 오른쪽 아래의 지름 56·아이콘 28 원형 새로고침은 타이머 조작과 같은 12% 글자색 면을 사용한다. 상태 옆 아래에는 16·행간 22의 마지막 갱신 시각을 표시한다. 기온·상태를 누르면 기존 상세 창을 열고 새로고침은 별도 접근성 이름·비활성 상태를 제공한다. 기본 2×2 높이와 저장 크기는 유지하며 큰 시스템 글자·긴 지역명은 내부 세로 스크롤로 보존한다.

### 웹 문서 기본 캔버스와 테마 충돌

웹 색상 통일이 켜진 동안 문서 루트에 `color-scheme: normal !important`를 적용한다. 네이버 블로그처럼 사이트가 자체 밝은 모드를 지정해도 흰 기본 캔버스에 흰 글자가 겹치지 않게 하며, 홈 다크 모드의 투명 캔버스 뒤로 숲 사진을 유지한다. 사진·레이아웃·입력값은 유지한다. 원본 보기에서는 앱 스타일시트를 비활성화해 사이트의 원래 color-scheme으로 복원한다. Android `accessible-web.js`와 iPad `AccessibleWebAppearance`가 같은 규칙을 사용한다.

### 구글 검색 전송 화살표

구글 간단히 보기의 원형 검색 전송 버튼은 선택 모드의 링크색 면과 바탕색 화살표를 사용한다. 버튼 내부 SVG와 경로의 stroke를 바탕색으로 명시해 공통 아이콘의 글자색 변환이 덮어쓰지 않게 한다. 다크 모드에서는 밝은 면·짙은 화살표, 라이트 모드에서는 갈색 면·흰 화살표다. 마이크·즐겨찾기 그림·본문 아이콘과 검색 동작·접근성 이름은 유지한다. Android `accessible-google.js`와 iPad `AccessibleGooglePage`가 같은 규칙을 사용한다.

### 투명 바탕과 마스크 아이콘

홈 브라우저의 어두운 기본 바탕을 투명하게 만드는 규칙은 CSS 마스크가 있는 요소를 제외한다. 마스크의 background-color는 패널이 아니라 기호를 그리는 전경색이므로 공통 웹 테마의 글자색을 유지한다. 사이트 주소·클래스 이름과 무관하게 마스크 속성으로 구분하며 사진·로고의 픽셀과 원본 보기 동작은 유지한다. Android `launcher-widget.js`와 iPad `LauncherWebAppearance`가 같은 규칙을 사용한다.

### 팔레트 전환의 원본 색 분류

색상·아이콘을 분류할 때 공통 웹 테마와 런처 투명 캔버스 스타일시트를 같은 작업 안에서 잠시 비활성화하고, 원래 비활성 상태를 복원한다. 앱이 만든 투명색을 원본 색으로 다시 읽지 않는다. 중성 배경의 main·role=main은 문서 기본 바탕으로 분류하므로 처음 다크 모드로 열기와 라이트를 거쳐 다크로 돌아오기에서 같은 투명 캔버스를 사용한다. 내부 카드·입력창의 표면과 사진·마스크 아이콘은 별도 규격을 유지한다. Android `accessible-web.js`와 iPad `AccessibleWebAppearance`가 같은 규칙을 사용한다.

### 웹 캔버스와 메뉴 표면

런처의 투명 처리는 중성 배경의 문서 구조(main·상위 래퍼·일반 흐름에서 뷰포트를 덮는 최상위 래퍼)에만 적용한다. 중성색이라는 이유로 내부 카드·고정 메뉴·대화상자를 투명하게 만들지 않는다. 위치가 고정/절대인 층과 dialog·menu·popover 안의 main은 캔버스 후보에서 제외하고 마스크의 전경색은 보존한다. 체크·펼침·포커스 상태가 바뀌면 입력 문자마다 전체 문서를 다시 읽는 대신 해당 컨트롤 그룹의 원본 색을 묶어서 재분류한다. 메뉴·체크 상태·입력값·이벤트는 원본 노드를 유지한다.

### 다크 모드의 수식 대체 이미지

MathML 또는 role=math와 같은 의미 컨테이너에 있는 투명 수식 대체 img·svg는 원본 수식의 글자색이 어두운 중성색일 때 다크 모드에서 흰 받침을 사용한다. 사이트·렌더러 클래스 이름으로 구분하지 않고 수식 이미지의 픽셀·비율·수식 의미·대체 텍스트는 유지한다. 일반 사진·로고에는 이 처리를 적용하지 않으며 라이트 모드·원본 보기에서는 받침 규칙을 적용하지 않는다.

### 새 창의 네이티브 바탕

홈 브라우저의 새 창도 기존 창과 같은 투명 네이티브 바탕을 사용한다. Android는 WebViewTransport가 새 창의 렌더러를 연결한 뒤 초기 흰 캔버스를 남기지 않도록 페이지 시작·첫 콘텐츠 표시 시 네이티브 바탕을 투명으로 재적용한다. 웹 문서의 라이트 면과 사진·메뉴 표면은 해당 CSS 규칙을 따른다. iPad는 모든 내장 WKWebView에 isOpaque=false와 웹뷰·스크롤뷰의 clear 배경을 설정한다. 독립 브라우저의 바탕과 팝업의 opener·로그인·뒤로 복귀 동작은 유지한다.

### 웹 자체 가로 제스처

실제 가로 넘침이 있는 auto/scroll 영역뿐 아니라 overflow:hidden/clip으로 가로 트랙을 감추고 pan-y·자식 transform·더 넓은 다중 항목 트랙으로 직접 드래그를 처리하는 영역도 웹 조작을 우선한다. 사이트의 제스처 초기화 전에도 가로 목록 구조와 header·nav·navigation·tablist·slider 영역을 보호한다. touch-action:none을 지정한 지도·그리기 등의 표면 역시 런처가 가로 드래그를 가로채지 않는다. 원래 사이트가 정한 동작과 하단 페이지 점을 유지하며, 일반 본문에서의 런처 페이지 넘김은 유지한다. 일반 사이트 이름·클래스 이름에 따른 예외는 없다. 앱이 직접 구성한 구글 기본 홈(`data-rivo-google-simple=home`)은 검색 입력·선택·편집 필드를 제외한 전체 표시 영역을 홈 넘기기에 사용한다. 즐겨찾기 격자와 아래 빈 공간은 일반 웹의 가로 탐색·캐러셀 보호 판정에서 제외하며, 해당 위치에 DOM 요소가 없는 빈 뷰포트도 넘김을 허용한다. 검색 입력의 드래그·선택·키보드 동작과 일반 사이트의 가로 스크롤 보호는 유지한다.

### 원본 보기의 배경 복원

일반 홈 브라우저의 캔버스 투명 처리는 색상 통일이 켜진 다크 모드에서만 적용한다. 원본 보기에서는 원래 사이트의 글자색과 배경을 함께 복원하고, 다시 다크 색상 통일을 켜면 문서 캔버스가 숲 사진 위로 투명해진다. 라이트 모드의 밝은 면과 쉬운 유튜브의 독립 투명 표현은 유지한다.

### 읽기 쉬운 브라우저 주소

주소창은 편집하지 않을 때 HTTPS 스킴·쿼리·fragment·사용자 정보를 생략하고 원래 도메인(포트 포함)과 한글 경로를 한 줄로 표시한다. HTTP 주소에는 http://를 남긴다. 경로의 퍼센트 인코딩은 보이는 유니코드만 풀고 예약 ASCII 구분자·공백·제어·방향 문자 인코딩은 유지한다. 도메인 문자열은 디코딩하지 않는다. 포커스를 받으면 현재 원본 전체 URL을 편집하며, 이동·복사·선택은 그 전체 주소에 적용된다. 포커스를 잃으면 현재 페이지의 짧은 표시로 돌아가며 실제 URL·쿼리·탐색 기록은 바꾸지 않는다. Android `AccessibleWebAddress.display`·`BrowserScreen`, iPad `BrowserAddressDisplay`·`AccessibleWebBrowserView`가 표시와 편집을 분리한다.

### 광고 슬롯의 갱신과 복원

번들 광고 목록 v2는 NAVER Ad Manager 광고 전용 naverads.net·veta.naver.com 서버와 data-ad-unit/placement/format, ad-slot/ad-unit 등 명시적 광고 슬롯, 광고라는 접근성 이름의 요소를 포함한다. 기사나 사이트 이름에 따른 레이아웃 예외를 추가하지 않는다. 동적으로 삽입된 광고와 iframe src·광고 속성·class/id 변경을 묶어서 처리한다. 스타일시트 삽입을 거부하는 문서에도 광고 요소 자체의 inline display를 적용한다. 비활성화하거나 광고 표시가 사라지면 기존 inline display 값을 복원하고, 사이트가 그 값을 바꾼 경우 덮어쓰지 않는다. 연결이 끊긴 요소의 기록은 해제한다. 일반 iframe과 부모 컨테이너는 임의로 숨기지 않는다. iPad 규칙 식별자는 rivo-browser-ads-v2이며 광고 전용 서버의 하위 리소스는 같은 사이트에서 요청해도 차단한다. 직접 여는 최상위 주소는 이 리소스 규칙으로 차단하지 않는다.

광고 제공자 참고: [NAVER Ad Manager SDK](https://naver.github.io/nam-sdk-guide/web-instream/basic/get_started/). 필터 정책 참고: [List-KR 광고 도메인 논의](https://github.com/List-KR/List-KR/issues/1094). 외부 목록의 실시간 다운로드는 하지 않는다.

### 전체 페이지 뉴스 위젯

뉴스 위젯 `widget:news`(Android NEWS)는 유튜브와 같은 독립된 전체 페이지이며 호환 크기는 4×10이다. 기본 안전 영역·홈 상단 여백·전체 페이지 좌우 16에 내부 20 여백을 유지하고 어두운 숲 배경 위에 투명한 캔버스를 사용한다. 최초 한 번 기존 순서 뒤에 추가하며 삭제 후 자동 보충하지 않는다. 위젯 추가 목록에서 뉴스의 삭제·재추가·순서 이동을 제공하고 성공한 재추가는 편집 화면을 닫아 실제 뉴스 페이지로 이동한다. 크기·색·바로가기 유형 변환은 제공하지 않는다. 좌우 넘김은 기존 네이티브 홈 애니메이션, 세로는 기사 목록 스크롤을 사용한다. 기사 원문에서 돌아오면 뉴스 페이지와 기존 목록 위치를 유지한다.

상단은 최신·사회·경제·문화 선택과 지름 56·기호 28의 원형 새로고침이다. 좁은 폭·큰 글자에서 조작 버튼을 여러 줄로 배치하며 가로 스크롤하지 않는다. 기사는 화면 폭과 관계없이 한 행에 한 기사만 놓는 투명한 단일 열 목록이다. 기사 배경 면·둥근 모서리·외곽 테두리는 없고 좌우 2·위 22·아래 24의 여백을 둔다. 기사 사이에만 두께 1·경계색 `#7F93AB` 28%의 구분선을 놓고 처음·마지막 바깥 선은 표시하지 않는다. 제목은 기존 밝은 글자색, 소개는 같은 색 92%, 언론사·발행 시각은 75%로 표시한다. 구분선은 장식으로 접근성 탐색에서 제외한다. 제목 23·소개 18·언론사/발행 상대 시각 16이며 모두 시스템 글자 확대와 줄바꿈을 따른다. 기사 하나는 제목·소개·실제 언론사·발행 시각을 한 번의 접근성 이동으로 읽고 기사 행 전체가 원문 열기 버튼이다. 사진·장식용 빈 카드·영상 보기 같은 중복 버튼·별도 뒤로 버튼은 없다. 원문은 기존 쉬운 브라우저로 열며 Android의 내장 브라우저가 없는 Release에서는 기본 웹 브라우저로 연다. 위젯 편집은 기존 전체 편집 경로를 사용한다.

뉴스 목록은 `docs/news_publishers.json`의 74개 매체 등록부에서 확인된 **분야 전용 RSS만** 사용한다. 최신은 별도 전체 RSS를 요청하지 않고 사용자가 고른 분야의 캐시만 합친다. 기본 선택은 사회·경제·문화이고, 상단 ‘뉴스 분야 설정’에서 정치·국제·IT·과학·건강·스포츠·연예를 포함한 9개 분야를 복수 선택해 저장한다(‘IT·과학’은 한 분야). 설정은 재시작 후에도 유지하며 모든 분야를 끄면 안내만 표시하고 수신하지 않는다. 분야 탭도 선택한 것만 표시한다. 현재 사회·경제·문화에는 기존 8개 매체, 정치·국제·스포츠에는 뉴시스·SBS·동아일보, 연예에는 뉴시스·SBS, IT·과학에는 뉴시스·동아일보, 건강에는 동아일보를 연결한다. 뉴시스 IT·바이오와 동아일보 IT·의학은 IT·과학에 포함한다. 매체가 분류한 분야를 따르며 별도의 의미 분류는 하지 않는다. 분야 피드가 없는 매체는 전체/다른 분야로 대체하지 않는다. 전체 피드 주소는 등록부의 참고 자료로만 보존하며 자동 수신에는 사용하지 않는다. 사용자별 언론사 선택 화면은 포함하지 않는다. 제목과 소개는 길이를 자르기 전에 HTML 엔티티 해제와 태그 제거를 최대 6회 반복하고 마지막 잔여 태그·이미지 자리 문자·공백을 정리한다. script/style 본문과 닫히지 않은 태그도 제거하며 숫자 엔티티와 중첩 인코딩을 처리한다. 저장된 분야 캐시에도 같은 정리를 적용한다. HTML 렌더러나 외부 이미지 요청은 사용하지 않는다. 각 피드에서 제목·원문 HTTPS 링크·소개 최대 160자·발행 시각·언론사를 읽는다. 원문 URL(가능하면 RSS guid)·정규화한 동일 제목을 중복 제거한다. 숫자가 같고 제목 길이 비율 85% 이상·발행 간격 6시간 이내인 16자 이상 제목은 문자 쌍 유사도 90% 이상일 때만 같은 기사로 취급한다. 매체별 후보 최대 30개에서 최대 15개, 전체 최대 1200개를 발행 시각 내림차순으로 섞고 시각 미제공 기사는 뒤에 놓는다. 정렬·중복 제거는 백그라운드에서 처리하고 제목 비교용 자료는 후보당 한 번만 만든다. 동일 제목·URL은 집합으로, 유사 제목은 같은 숫자 묶음 안에서만 비교한다. 중요도 순위는 제공하지 않는다. 본문 전문·사진·AI 생성 요약·의미 기반 사건 묶음은 추가하지 않는다. 처음 불러오는 동안 중앙 144×80의 세 겹 물결과 상태 문구를 제공하고, 실패는 재시도 안내와 새로고침으로 구분한다. 화면은 캐시를 먼저 표시하고 보이는 동안의 보충 간격도 2시간이다. 자동 수신한 새 목록은 대기 상태로 두고 ‘새 뉴스가 있어요 · 보기’를 누를 때 적용한다. 수동 새로고침·분야 변경·새 뉴스 적용은 맨 위로 이동하며 그 외에는 기존 읽기 위치를 보존한다. 실패는 이전 목록과 갱신 시각을 유지하고 5분 뒤 재시도한다. 자동 기사 넘김·개별 기사 WebView/이미지 로딩은 없다. 동시 수신은 세 개로 제한하고 나머지는 대기하며 필요한 목록 행만 그린다. 각 매체를 독립적으로 요청하고 일부만 실패하면 성공한 뉴스와 그 매체의 24시간 이내 기존 기사를 함께 표시한다. 실패한 매체의 저장 시각을 갱신하지 않아 오래된 기사를 계속 연장하지 않는다. 일부 실패 안내를 표시하고 5분 뒤 다시 시도하되 각 출처의 마지막 성공부터 2시간 이내인 결과는 재사용한다. 수동 새로고침은 이 재사용을 우회하며 모두 성공하면 2시간 간격으로 돌아간다. 상단 갱신 시각은 여러 언론사 목록의 수신 시각이고 기사 행에는 실제 언론사와 발행 시각을 표시한다.

뉴스 위젯이 배치되어 있으면 사용자가 선택한 분야만 약 2시간마다 화면 밖에서 미리 받아 저장한다. 최신용 전체 피드를 별도로 받지 않는다. 분야를 바꾸면 표시 중인 최신·대기 목록을 비우고 새 선택으로 합치며 진행 중인 수신도 비선택 분야의 추가 요청·결과 반영을 중단한다. 이미 시작한 요청은 종료/취소될 수 있으나 비선택 기사가 최신에 섞이지 않는다. 앱/런처 진입 시에도 예약과 별도로 조용히 보충하되 2시간 이내 캐시는 재사용한다. 정기 예약이 실제 실행될 때는 다시 수신해 예약 경계에서 갱신이 4시간으로 밀리지 않게 한다. 화면은 저장된 목록을 먼저 표시하며 캐시가 전혀 없으면 최초 성공한 출처부터 표시하고 이후 12개 출처 처리마다 중간 결과를 저장한다. 읽는 중 들어온 후속 목록은 ‘새 뉴스가 있어요 · 보기’로 적용해 읽기 위치를 유지한다. 동시 수신은 3개이고 캐시가 없거나 가장 오래된 출처부터 수신한다. 작업이 중단되어도 이미 저장된 결과는 남는다. 수동 새로고침은 캐시 신선도와 관계없이 수신한다. 뉴스 위젯 삭제 시 백그라운드 예약·진입 시 보충을 중지한다. 최초 설치·장시간 오프라인 등으로 캐시가 없으면 통신이 필요하다. 예약 시각은 운영체제의 절전·네트워크 상태에 따라 늦어질 수 있어 정확한 2시간 실행을 보장하지 않는다.

### 브라우저 기본 홈 전체 영역 넘기기와 뉴스 목록

브라우저 기본 홈은 즐겨찾기 위·아래의 빈 공간과 즐겨찾기 항목에서 모두 좌우 드래그로 옆 홈을 넘긴다. 검색 입력에서는 편집 동작을 유지하고, 즐겨찾기를 탭하면 기존 링크를 연다. 뉴스는 Android LazyColumn·iPad LazyVStack으로 한 행에 한 기사를 표시하며, 기사 전체 클릭·접근성 묶음·발행 시각·스크롤 복귀·갱신 동작은 유지한다.

### 뉴스 백그라운드 — Android와 다른 곳

iPadOS는 BGProcessingTask와 `processing` 백그라운드 모드, Android는 WorkManager를 사용한다. iPad는 시스템이 허용한 실행 시간에만 통신하고 시간 만료 시 현재 작업을 취소한다. 양쪽 모두 2시간은 목표 간격이며, 마지막 중간 저장을 유지하고 앱 활성 진입 시에도 보충한다.

## 런처 선택과 미디어 탐색 (Debug·Release 공통)

설정의 ‘런처 변경’은 기존 홈 / 위젯 런처 두 가지이며 선택 즉시 해당 홈으로 이동하고 다음 앱 실행에서도 유지한다. 기존·신규 사용자의 기본값은 기존 홈이다. 기존 홈의 목록형·카테고리형 선택은 별도로 유지한다. 위젯의 배치·추가·개별 설정은 런처 내부에서만 연다. Android 시스템 기본 HOME 지정은 앱 안의 홈 선택과 독립적이며 자동으로 기본 HOME 권한창을 띄우지 않는다. 사용자가 시스템 설정에서 직접 지정한다. iPad는 앱 내부 시작 화면만 바뀌며 OS 홈을 대신하지 않는다.

기존 홈의 목록형과 카테고리형에 ‘미디어 탐색’을 제공하며 ‘쉬운 브라우저’와 ‘쉬운 유튜브’ 두 항목이 각각 단독 화면을 연다. 설정의 ‘미디어 탐색 표시’는 기본 켬이며 두 홈 구성에 동시에 적용하고 재시작 후에도 유지한다. 숨기기는 해당 그룹 표시만 제어하며 기존 위젯·로그인·즐겨찾기를 삭제하지 않는다. 런처 앱·기능 목록에는 브라우저·유튜브·앱 설정·기존 홈 진입을 제공한다. 기존 홈 진입은 저장된 위젯 런처 선택을 바꾸거나 다시 런처로 튕기지 않는다.

브라우저·유튜브·뉴스·날씨·타이머·데이지 위젯은 릴리즈에도 포함한다. Android 브라우저 코드·리소스·JavaScript는 main 소스셋이며 릴리즈의 브라우저 위젯도 실제 웹뷰를 만든다. iPad Launcher와 AccessibleWeb 코드는 DEBUG 조건 없이 컴파일한다. 개발 화면과 로컬 모델 실험·문서 비교 도구의 빌드 조건은 유지한다. 뉴스 백그라운드 수신도 릴리즈에서 같은 선택 분야·2시간 정책으로 동작한다.

로그인·사이트 저장소와 사용자 즐겨찾기는 위젯·단독 화면에서 공유한다. 일반 브라우저와 쉬운 유튜브는 서로 다른 전용 영속 웹 저장소를 쓰고 문서용 웹뷰와도 분리한다. 비밀번호·쿠키를 네이티브 코드로 추출/복사하지 않는다. 방문 페이지·뒤로가기 목록·스크롤·영상 위치는 열린 화면의 세션에만 두며 단독 화면을 다시 열면 기본 홈에서 시작한다. 이미 열려 있는 위젯의 화면 내 상태 유지 규격은 그대로다. 브라우저가 다시 활성화되면 즐겨찾기 표시를 갱신한다.

새 설정은 기존 설정 값과 섞이지 않으며 기존 위젯 ID·배치·YouTube 로그인 저장소·즐겨찾기 키는 유지한다. 네이티브 설정 선택과 숨기기 스위치는 기존 설정 컴포넌트, 접근성 이름·선택/켜짐 상태·큰 글자·터치 기준을 따른다.
