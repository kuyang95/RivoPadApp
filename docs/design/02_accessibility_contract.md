## Visual

- 모든 텍스트 크기는 Dynamic Type을 따르게 지정한다(`visionCraftAndroidText(size, relativeTo:)` 또는 시스템 텍스트 스타일). `.system(size:)` 고정 크기는 카메라 미리보기 위 버튼과 타일 제목(자체 배율 계산)에만 쓴다.
- 본문 텍스트는 16pt 이상을 기본값으로 삼고, 매우 보조적인 메타 정보도 12pt 미만으로 내리지 않는다(`.caption2`는 11pt라 쓰지 않는다. `VisionCraftUI.minTextSize`).
- 사용자 시스템 글씨 크기에서 레이아웃이 깨지면 텍스트를 줄이는 대신 줄바꿈, 높이 확장, 콘텐츠 우선순위 조정을 먼저 한다.
- 텍스트 대비는 최소 4.5:1을 목표로 한다.
- 아이콘, 구분선, 테두리, 토글 상태 같은 비텍스트 UI는 최소 3:1 대비를 목표로 한다.
- 색만으로 상태를 전달하지 않는다. 라벨, 아이콘, 상태 텍스트, 접근성 값 중 하나 이상을 함께 제공한다.

## Touch And Motor

- 누를 수 있는 항목은 실제 터치 영역 기준 최소 48pt를 확보한다(`VisionCraftUI.minTouchTarget`). 공용 뒤로 가기 `VisionCraftBackButton`도 48pt다.
- 리스트 행 전체를 누를 수 있게 만들고, 보조 아이콘 버튼은 행 클릭과 역할이 충돌하지 않게 한다.
- 스와이프, 길게 누르기, 드래그가 필요한 기능은 항상 대체 버튼을 제공한다. VisionLink 공유 카메라 확대는 사용자 지정으로 보이는 조작 버튼을 생략하며, 핀치와 배율의 화면 읽기 조절 동작을 제공한다.
- 반복 작업은 같은 위치, 같은 이름, 같은 역할로 유지한다.

## Screen Reader

- 화면에 보이는 라벨과 접근성 이름은 최대한 일치시킨다.
- 장식 아이콘은 `.accessibilityHidden(true)`로 둔다.
- 버튼은 동사 중심으로 읽혀야 한다. 예: `문서 스캔 시작`, `음성 명령 실행`, `채팅 기록 열기`.
- 토글은 값이 함께 읽혀야 한다. 예: `효과음 피드백, 켬`(`.isToggle` 특성 + `accessibilityValue`).
- 화면 제목은 `.isHeader`로, 다이얼로그가 열리면 `UIAccessibility.post(.screenChanged, 제목)`으로 제목을 읽어 준다.
- 로딩, 실패, 권한 필요, 빈 상태는 화면 텍스트로도 제공한다.

## Audio Feedback

- 효과음은 보조 신호다. 실패 이유, 권한 부족, 빈 입력, 네트워크 문제는 텍스트 또는 TTS로 설명한다.
- 효과음 피드백 설정이 꺼져 있으면 효과음은 재생하지 않는다.
- 음성 피드백 설정은 효과음 설정과 분리되어 있다. 안내 TTS는 음성 피드백이 켜져 있을 때만 말한다(VoiceOver 켜짐 여부와 무관하게).
- TTS는 긴 설명보다 짧고 행동 가능한 문장을 우선한다.

## Settings

- 시스템 설정을 앱 설정으로 덮어쓰지 않는다.
- 앱 설정은 VisionCraft 고유 기능에 대한 선호만 둔다.
- 설정 라벨은 사용자가 결과를 예측할 수 있게 쓴다.
- 기본값은 대부분의 사용자에게 안전하고, 배터리/데이터/방해를 최소화하는 쪽으로 둔다.

## QA Checklist

- VoiceOver로 홈, 전체 설정, 대화기록, 데이지, 문서 스캔 진입을 읽어본다.
- 시스템 글씨 크기를 크게 하고 버튼/카드/위젯 텍스트가 잘리지 않는지 본다.
- 다크/라이트 모드에서 텍스트와 상태 대비를 확인한다.
- 권한 없음, 파일 없음, 네트워크 실패, 음성 인식 실패를 일부러 발생시켜 안내를 확인한다.
- 위젯은 small 크기에서 이름이 잘리지 않는지 확인한다.

## 기준을 벗어난 곳 (사용자가 정한 예외)

- 뉴스의 백그라운드 수신은 Android WorkManager 대신 iPadOS BGProcessingTask를 사용한다. 시스템이 네트워크·절전·앱 사용 패턴에 따라 실행 시점을 정하므로 2시간은 earliestBeginDate 목표이며 동일한 실행 간격을 보장하지 않는다. 앱 활성 진입의 조용한 보충과 저장 캐시 우선 표시는 공통이다.

코드와 대조해 확인한 것 중 사용자가 그대로 두기로 한 것. 바꾸기로 하면 이 목록을 고친다.

- 런처의 리모컨 홈은 첫 페이지로 복귀한다. iPadOS 시스템 홈 버튼은 앱에서 가로챌 수 없으며 시스템 홈으로 나간다. 다른 앱 위젯 호스팅은 Android 전용이다.

- Android 기본 HOME 등록·설치 앱 열거는 리보탭 전용이다. iPad는 Debug 개발 화면에서 앱 내부 Ratio 홈을 제공하며 설치 앱 목록 대신 사용자가 등록한 앱 링크를 표시한다. 전체 목록의 뒤로가기는 iOS에서 chevron 아이콘(56pt), Android에서 시스템 뒤로가기를 사용한다. iPad의 검색 의도 판단은 로컬 MLX, Android는 Gemini를 사용한다. 텍스트 바로가기의 앱 아이콘 색는 Android 설치 앱 아이콘, iPad 사용자가 등록한 아이콘 이미지로 표시하며 iPad는 다른 앱 아이콘을 자동 추출하지 않는다.

- 두 플랫폼의 Debug 개발 화면과 접근성 웹은 설정에서 진입하는 개발 도구이며 Release에 포함하지 않는다. 네이티브 컨트롤의 접근성 기준은 일반 화면과 동일하게 적용한다. 접근성 웹은 사이트의 폼·접근성 의미를 유지하며 글자만 강제로 키우거나 모든 컨트롤의 높이를 덮어쓰지 않는다. 페이지 전체 확대는 글자·이미지·버튼을 함께 키운다. 선택 가능한 차분하게 보기는 사진·브랜드 색과 어두운 면을 보존한다. 밝은 종이/어두운 먹색은 사진·영상·지도·색 견본도 흑백으로 표시하므로 색 확인은 원본 보기로 되돌려 한다. 사진 소스와 명암은 반전하지 않는다.

- Debug 접근성 웹은 iPad에서 `WKWebView.pageZoom`, Android에서 WebView의 textZoom을 100으로 고정한 뒤 주 문서의 CSS layout zoom을 사용한다. 기기의 큰 글씨 선호는 기본 페이지 배율에 반영한다. Android 방식은 Chrome 엔진의 페이지 줌과 동일한 API가 아니며 viewport 단위·미디어쿼리·사이트 스크립트에 따라 배치 차이가 남을 수 있다.

- 스캔 한 장 검토의 상단은 사용자 지정으로 뒤로가기·제목·원형 T/사진 전환을 한 줄에 둔다. 제목과 아이콘은 24pt Dynamic Type 기준이며 버튼은 최소 48pt 터치 영역을 유지한다.
- 카테고리 내부 기능 선택 화면의 상단 뒤로 가기 버튼은 iPad에서 유지한다. Android는 시스템 뒤로 가기로 홈에 돌아가고 상단에는 제목만 표시한다. iPad에는 같은 시스템 뒤로 가기 버튼이 없다.
- 테두리를 뺀 요소는 경계 대비가 3:1에 못 미친다: 2x2 타일(면/배경 1.04:1, 그림자로 경계를 만듦), 채팅 칩·입력칸(1.12:1, 안의 글자로 식별).
- Ratio 홈의 실행 타일·검색 미리보기는 사용자 지정으로 평상시 테두리 없이 면·간격·큰 이름으로 식별한다. 글자 대비·시스템 글자 확대·기존 터치 영역과 접근성 이름은 유지한다. Android의 키보드·리모컨 포커스는 반전·포커스 테두리를 유지하며 하단 탐색 버튼은 테두리를 유지한다.
- 카메라 확대와 사진 분석·문서 스캔 결과의 사진 확대는 두 손가락 제스처로만 된다. 화면 위 대체 버튼이 없다.
- 문서 편집기(엑셀·워드·한글)의 문서 본문 렌더링 글자·손잡이 크기는 문서 내용이므로 12pt/48pt 하한을 적용하지 않는다.

- iPad의 Rivo 리모컨 연결은 사용자 지정으로 매번 기기를 선택하는 수동 연결이다. 앱 재시작·Bluetooth 재활성화·연결 끊김 때 자동 연결하지 않는다(`RivoRemoteManager.swift` · `RivoRemoteManager`).


- 구글 홈·일반 검색 결과는 사용자 지정으로 검색 입력·기본 즐겨찾기 또는 AI 개요·사이트 목록으로 재구성한다. 이 범위는 원래 사이트 배치·폼을 그대로 유지하는 일반 웹 보기의 예외다. 원래 AI 개요의 출처·펼치기는 보존하며, 구글 원본 보기로 복귀할 수 있다. 본인 확인·동의 안내는 가리지 않는다.

## Source Anchors

- Android Accessibility: `sp`, 12sp 하한, 4.5:1 텍스트 대비, 3:1 비텍스트 대비, 48dp 터치 타깃.
- Apple HIG Accessibility: Dynamic Type, VoiceOver 특성, 동작 줄이기.
- WCAG 2.2: Label in Name, Pointer Cancellation, Target Size, Consistent Identification.

## Debug 이지 유튜브

전용 화면의 네이티브 주소창·웹 도구는 표시하지 않는다. 닫기·주요 메뉴·플레이어 바깥 버튼은 이름과 포커스를 유지한다. 공식 iframe은 접근성·Tab 탐색에 열어 두며, 영상 내부의 탭·세로 스크롤과 위/아래 조작 영역을 유지하고 가운데 좌우 드래그는 홈 페이지 이동에 사용한다. 로그인 원본 화면에서도 기능을 닫을 수 있어야 한다. 일반 접근성 웹의 임시 세션 계약은 유지하며 이지 유튜브에만 별도 영속 로그인 저장소를 사용한다.

이지 유튜브의 Google 이메일·비밀번호 입력 단계는 원래 입력·라벨·자동완성·오류·제출 동작을 유지하고 보조 링크를 숨긴다. 인증 입력값을 읽거나 복제하지 않는다. 추가 본인 확인·보안 문자·동의·대화상자·미인식 단계는 원본 표시로 복귀한다. 상세 범위는 `05_screen_specs.md` 이지 유튜브 절을 따른다.

## Ratio 브라우저의 폭 맞춤

브라우저 위젯은 사이트의 반응형 배치·격자·표·이미지 비율·고정 위치를 유지하고 선택한 비례 확대만 적용한다. 가로 넘침만으로 캐러셀·숨긴 콘텐츠를 세로로 펼치거나 표·행·셀과 접근성 역할을 다시 쓰지 않는다. 넓은 문서나 가로 스크롤 영역에서는 웹 스크롤을 우선하고 하단 페이지 점으로 홈 페이지를 이동한다. 입력·링크·이벤트 처리·접근성 이름·사이트 주소는 원본을 유지하며 사이트 이름에 따른 배치 예외나 자동 모바일 주소 전환은 두지 않는다.

웹 위젯 페이지는 드래그 중 원래 웹 화면을 유지하며 선택하지 않은 페이지는 접근성 탐색에서 제외한다. 하단 페이지 점과 iPad VoiceOver 페이지 스크롤 동작으로도 이동할 수 있다. 로딩 표시는 웹 화면의 크기를 바꾸지 않고 상태를 한 번에 제공한다. 최초 본문·영상 목록의 짧은 페이드는 동작 줄이기에서 생략한다.

### 런처 날씨·타이머 전용 위젯 / 검색 줄

위젯 조작은 최소 48×52, 설정은 48이며 큰 글자에서는 줄바꿈·위젯 내부 세로 스크롤을 사용한다. 검색 줄은 투명 배경·1.5 밑줄·검색 기호와 독립 음성 버튼을 제공한다. 시간은 분·초로 읽고 매초 강제 낭독하지 않으며 모드 선택 상태·실패·권한 안내는 텍스트로 제공한다. 세부 데이터·크기·알림·검색 규격은 `08_ratio_home_grid_proposal.md`의 해당 절을 따른다.

유튜브 구독 빈 화면은 장식 아이콘과 제목·안내를 하나의 상태로 제공하고 더 불러오기는 숨긴다. 목록 상단 검색창의 접근성 라벨을 유지한다. 쇼츠 로딩 중에는 이전·다음 버튼이 낭독·포커스되지 않으며, 뒤로가기는 유튜브 홈으로 바로 복귀한다. 일반 영상의 채널·댓글 규격은 유지한다.

일반 영상과 쇼츠는 초기 자막 기본 꺼짐을 적용하며 공식 플레이어 내부의 접근성·키보드 조작은 보존한다. 채널은 로고와 이동 안내가 있는 버튼으로, 댓글은 본문과 작은 작성자 표시로 구분한다. 쇼츠의 이전·다음 버튼은 이름에 쇼츠를 반복하지 않는다.


유튜브 초기 목록 로딩에는 장식용 빈 카드 없이 인디케이터 상태 하나만 제공한다. 쇼츠 진입은 기존 화면을 유지하다 공식 플레이어 준비 뒤 포커스·탐색을 옮기고 180ms로 교차 전환한다. 동작 줄이기는 전환을 즉시 적용하며, 이전·다음은 동일 iframe을 유지한다.

유튜브 목록의 물결 인디케이터는 장식용으로 탐색에서 제외하고 상태 문구 하나만 알린다. 동작 줄이기에서는 물결을 정적으로 표시하며, 강제 색상 모드에서는 선을 시스템 글자색으로 유지한다.

유튜브 로그인 안내·플레이어 바깥 조작은 기존 런처 리보 테마를 유지한다. 브라우저는 독립 실행·홈 위젯 모두 라이트/다크 두 모드를 사용하고 다크를 기본 선택한다. 홈 브라우저의 다크 모드는 이전의 어두운 숲 사진 배경 위에 투명한 캔버스와 흰 글씨를 사용한다. 다른 홈 페이지는 밝은 산 사진을 유지한다. 주소창·도구·메뉴·웹 콘텐츠·구글 간단히 보기도 선택 모드의 색을 따른다. 유튜브 목록·로그인·플레이어의 별도 색 규격은 유지한다.

브라우저의 구글 홈에서는 중복 네이티브 주소/도구 줄을 숨기고 검색·음성·즐겨찾기를 제공한다. 검색 입력의 접근성 이름은 `검색`, 음성 버튼은 `음성 검색`이다. 입력이 비었으면 전송 버튼은 시각·탐색에서 제외하며 키보드 검색을 유지한다. 즐겨찾기 하나는 사이트 이름으로 한 번 이동하고 장식 기호·주소는 중복 낭독하지 않는다. 음성은 알려진 구글 홈/검색 결과 또는 이지 유튜브 페이지의 상위 프레임에서 보낸 고정 동작 링크만 처리하고, 임의 사이트·하위 프레임은 음성 요청을 실행할 수 없다. 입력·로그인 값을 읽는 네이티브 메시지 브리지는 추가하지 않는다.

유튜브·브라우저 검색창은 통합 검색과 같은 원형 전송·마이크 버튼을 사용한다. 빈 입력은 전송 버튼을 탐색에서 제외하고, 공백만 입력하면 표시하되 비활성화한다. 키보드 검색과 연결된 입력 이름을 유지한다. 유튜브 음성 결과는 공개 영상 검색 경로로 이동하며 페이지 내용·인증 입력을 네이티브로 읽지 않는다.

### 데이지 위젯의 본문 유지와 메모리

데이지는 최초 방문 뒤 같은 런처의 홈 페이지 이동 동안 선택한 책과 독서 화면·정확한 스크롤을 유지한다. 숨은 페이지는 터치·접근성 탐색에서 제외한다. 이미 재생 중이면 홈 페이지 이동에도 이어 재생하고, 멈춘 상태로 이동하거나 앱이 배경으로 가면 유휴 오디오 재생 자원을 해제한다. 앱 배경에서는 재생을 일시 정지한다. 책 변경·서재 복귀·위젯 제거·런처 종료 시 기존 독서 세션을 정리한다.

내장 웹 본문은 현재 화면과 앞뒤 약 두 화면의 블록만 렌더링한다. 멀어진 블록은 높이를 보존한 빈 껍질과 가벼운 HTML 문자열로 남기고 자손·이미지 노드를 제거하며, 스크롤·목차·검색·재생 위치 이동 때 복원한다. 표·목록·그림 묶음은 원래 구조를 보존하는 단위로 유지하며 블록이 큰 경우 화면 수보다 더 남을 수 있다. 키보드 포커스·선택 텍스트·재생 강조 블록은 제거하지 않는다. TalkBack/VoiceOver 사용 중에는 읽기 순서와 접근성 포커스를 위해 블록 제거를 끄고 본문을 복원한다. iPad의 일반 텍스트 보기는 기존 현재 장의 LazyVStack을 유지한다.

메모리 부족 시 다른 홈 페이지 또는 앱 배경에 있는 비재생 데이지 본문을 해제하고 책·읽던 위치를 보존한다. 다음 방문에서 기존 진행 저장소로 복원하며 이 복원만으로 자동 재생하지 않는다. 일반 페이지 이동에는 파일을 다시 열거나 스크롤을 재설정하지 않는다. 목차·검색용 텍스트와 인덱스는 화면 블록과 별도로 유지한다. 실제 메모리 절감량은 기기에서 측정하지 않았다.

### 구글 검색 결과의 AI 근거와 사이트 설명

Google의 원본 AI 개요와 출처 링크·펼치기 동작을 유지한다. 출처의 캐러셀/목록과 서로 다른 외부 링크가 있는 카드 행을 찾아 표시용 속성만 붙이고, 해당 행과 조상 래퍼의 가로 이동·음수 오프셋·고정 폭·클리핑을 해제한다. 화면에 펼친 근거 카드의 캐러셀용 접근성 숨김·비활성 탐색 속성은 복원 가능하게 조정해 링크를 모두 탐색할 수 있게 하며 원본 보기에서는 되돌린다. 원본 노드를 복제하거나 이벤트를 다시 연결하지 않는다. 근거는 최대 폭 760px 안에서 최소 260px 열과 간격 14px의 격자로 배치해 공간이 충분하면 두 개씩, 좁으면 한 개씩 표시한다. 제목·그림과 형제인 빈 링크가 접근성 이름으로 카드를 덮는 Google 구조도 목록 항목으로 인식한다. 고정 폭 내부 카드 껍질을 열 너비로 맞추고 원본 덮개 링크의 클릭 영역은 카드 전체에 유지한다. 카드의 내부 여백은 14px·모서리 14px·글자 18px이며 강한 색 면 대신 중성 회색 8% 면을 쓴다. 선택한 모드의 글자·포커스 색을 유지한다. 단순화를 끄면 출처용 표시 속성도 제거한다.

사이트 상위 5개는 호스트 16px → 제목 23px → 원문 설명 18px/행간 1.7 순서로 표시한다. 큰 채움 면과 사각 테두리는 없애고 투명 바탕·위아래 여백·얇은 구분선으로 결과를 구분한다. 제목은 선택한 팔레트의 기본 글자색, 설명·호스트는 같은 글자의 보조 농도다. 설명은 각 결과의 원본 설명 요소 또는 해당 결과 안의 본문 텍스트에서 최대 420자로 읽으며 설명이 없으면 생략한다. 다른 결과·광고·버튼·사이트 이동 링크의 문구를 설명으로 합치거나 새 요약을 생성하지 않는다. 결과 하나의 링크 안에 제목·호스트·설명을 두고 원래 URL을 유지한다. 늦게 도착한 설명은 URL별 기존 노드를 갱신해 포커스와 스크롤을 유지한다.

### 브라우저 검색 입력 포커스

브라우저 구글 홈·검색 결과의 검색 입력에는 포커스 시 별도의 사각 외곽선·그림자를 표시하지 않는다. 입력 포커스는 검색창 바깥의 모서리 32 둥근 테두리로 표시하며, 전송·음성·즐겨찾기 버튼의 키보드 포커스 표시는 유지한다.

유튜브·브라우저 검색 입력은 검색 의미·키보드 검색 동작을 유지하며 브라우저 기본 검색어 지우기(X) 버튼을 표시하지 않는다.

위젯 추가는 현재 페이지의 남은 열·측정 높이를 우선 사용한다. 기존 위젯의 상대 순서와 크기를 유지하고, 성공 후 편집 화면을 닫아 새 위젯이 배치된 페이지를 표시한다.

### 브라우저 모드 선택

선택지는 라이트 모드(`light`)·다크 모드(`dark`) 두 가지이며 새 세션의 기본은 다크 모드다. 선택은 기존처럼 세션 동안 유지한다. Ratio 홈은 기본 산 사진을 유지하고 브라우저 페이지의 다크 모드에서만 이전의 어두운 숲 사진으로 바꾼다. 홈 브라우저의 다크 웹 캔버스는 투명하고 라이트 웹 캔버스는 밝은 면을 사용한다. 원본 보기 토글은 모드 선택과 별도로 유지한다.

### 홈 브라우저 다크 모드의 사진 배경

홈 브라우저를 다크 모드로 표시하는 페이지에만 숲 사진(`launcher_ratio_forest_mist` / `RatioForestMist`)과 검정 60%·하단 추가 25% 막을 적용한다. 웹 루트·본문·기본 바탕은 투명해 이 사진이 비치며 본문 뒤에 불투명한 검정/회색 면을 추가하지 않는다. 카드·입력창·메뉴·미디어와 원래 배치는 유지한다. 라이트 모드와 다른 홈 페이지는 기존 밝은 산 사진을 유지한다. 두 모드 선택·기본 다크·광고 차단 규격은 유지한다.

### 날씨 자동 갱신과 원형 새로고침

날씨 자동 갱신은 마지막 성공 시각 기준 30분 간격으로 보이는 페이지·앱 활성 상태에서만 실행한다. 화면 복귀 때 30분 미만의 자료는 위치 재조회 없이 재사용하고, 오래됐거나 자료가 없으면 즉시 위치 한 번과 예보를 요청한다. 수동 새로고침은 신선도·재시도 대기를 한 번만 무시하며 로딩 중 중복 입력은 막는다. 실패하면 지역명·날씨를 함께 보존하고 갱신 시각·오류를 표시하며 5분 뒤 재시도한다. 실패 대기는 메모리에만 유지하고 페이지 복귀가 대기를 초기화하지 않는다. 캐시는 최대 6시간까지만 표시하며 미래 시각·6시간 이상 자료는 제거한다. 위치 권한이 거부되면 이전 날씨를 숨기고 권한 설정을 안내한다. 위치와 예보는 성공 시 함께 교체하며 주기 위치 구독·백그라운드 예약 작업은 없다.

날씨는 지역명 20·행간 26, 기온 56·행간 68, 상태 22·행간 28로 표시한다. 오른쪽 아래의 지름 56·아이콘 28 원형 새로고침은 타이머 조작과 같은 12% 글자색 면을 사용한다. 상태 옆 아래에는 16·행간 22의 마지막 갱신 시각을 표시한다. 기온·상태를 누르면 기존 상세 창을 열고 새로고침은 별도 접근성 이름·비활성 상태를 제공한다. 기본 2×2 높이와 저장 크기는 유지하며 큰 시스템 글자·긴 지역명은 내부 세로 스크롤로 보존한다.

### 웹 자체 가로 제스처

실제 가로 넘침이 있는 auto/scroll 영역뿐 아니라 overflow:hidden/clip으로 가로 트랙을 감추고 pan-y·자식 transform·더 넓은 다중 항목 트랙으로 직접 드래그를 처리하는 영역도 웹 조작을 우선한다. 사이트의 제스처 초기화 전에도 가로 목록 구조와 header·nav·navigation·tablist·slider 영역을 보호한다. touch-action:none을 지정한 지도·그리기 등의 표면 역시 런처가 가로 드래그를 가로채지 않는다. 원래 사이트가 정한 동작과 하단 페이지 점을 유지하며, 일반 본문에서의 런처 페이지 넘김은 유지한다. 일반 사이트 이름·클래스 이름에 따른 예외는 없다. 앱이 직접 구성한 구글 기본 홈(`data-rivo-google-simple=home`)은 검색 입력·선택·편집 필드를 제외한 전체 표시 영역을 홈 넘기기에 사용한다. 즐겨찾기 격자와 아래 빈 공간은 일반 웹의 가로 탐색·캐러셀 보호 판정에서 제외하며, 해당 위치에 DOM 요소가 없는 빈 뷰포트도 넘김을 허용한다. 검색 입력의 드래그·선택·키보드 동작과 일반 사이트의 가로 스크롤 보호는 유지한다.

### 전체 페이지 뉴스 위젯

뉴스 위젯 `widget:news`(Android NEWS)는 유튜브와 같은 독립된 전체 페이지이며 호환 크기는 4×10이다. 기본 안전 영역·홈 상단 여백·전체 페이지 좌우 16에 내부 20 여백을 유지하고 어두운 숲 배경 위에 투명한 캔버스를 사용한다. 최초 한 번 기존 순서 뒤에 추가하며 삭제 후 자동 보충하지 않는다. 위젯 추가 목록에서 뉴스의 삭제·재추가·순서 이동을 제공하고 성공한 재추가는 편집 화면을 닫아 실제 뉴스 페이지로 이동한다. 크기·색·바로가기 유형 변환은 제공하지 않는다. 좌우 넘김은 기존 네이티브 홈 애니메이션, 세로는 기사 목록 스크롤을 사용한다. 기사 원문에서 돌아오면 뉴스 페이지와 기존 목록 위치를 유지한다.

상단은 최신·사회·경제·문화 선택과 지름 56·기호 28의 원형 새로고침이다. 좁은 폭·큰 글자에서 조작 버튼을 여러 줄로 배치하며 가로 스크롤하지 않는다. 기사는 화면 폭과 관계없이 한 행에 한 기사만 놓는 투명한 단일 열 목록이다. 기사 배경 면·둥근 모서리·외곽 테두리는 없고 좌우 2·위 22·아래 24의 여백을 둔다. 기사 사이에만 두께 1·경계색 `#7F93AB` 28%의 구분선을 놓고 처음·마지막 바깥 선은 표시하지 않는다. 제목은 기존 밝은 글자색, 소개는 같은 색 92%, 언론사·발행 시각은 75%로 표시한다. 구분선은 장식으로 접근성 탐색에서 제외한다. 제목 23·소개 18·언론사/발행 상대 시각 16이며 모두 시스템 글자 확대와 줄바꿈을 따른다. 기사 하나는 제목·소개·실제 언론사·발행 시각을 한 번의 접근성 이동으로 읽고 기사 행 전체가 원문 열기 버튼이다. 사진·장식용 빈 카드·영상 보기 같은 중복 버튼·별도 뒤로 버튼은 없다. 원문은 기존 이지 브라우저로 열며 Android의 내장 브라우저가 없는 Release에서는 기본 웹 브라우저로 연다. 위젯 편집은 기존 전체 편집 경로를 사용한다.

뉴스 목록은 `docs/news_publishers.json`의 74개 매체 등록부에서 확인된 **분야 전용 RSS만** 사용한다. 최신은 별도 전체 RSS를 요청하지 않고 사용자가 고른 분야의 캐시만 합친다. 기본 선택은 사회·경제·문화이고, 상단 ‘뉴스 분야 설정’에서 정치·국제·IT·과학·건강·스포츠·연예를 포함한 9개 분야를 복수 선택해 저장한다(‘IT·과학’은 한 분야). 설정은 재시작 후에도 유지하며 모든 분야를 끄면 안내만 표시하고 수신하지 않는다. 분야 탭도 선택한 것만 표시한다. 현재 사회·경제·문화에는 기존 8개 매체, 정치·국제·스포츠에는 뉴시스·SBS·동아일보, 연예에는 뉴시스·SBS, IT·과학에는 뉴시스·동아일보, 건강에는 동아일보를 연결한다. 뉴시스 IT·바이오와 동아일보 IT·의학은 IT·과학에 포함한다. 매체가 분류한 분야를 따르며 별도의 의미 분류는 하지 않는다. 분야 피드가 없는 매체는 전체/다른 분야로 대체하지 않는다. 전체 피드 주소는 등록부의 참고 자료로만 보존하며 자동 수신에는 사용하지 않는다. 사용자별 언론사 선택 화면은 포함하지 않는다. 제목과 소개는 길이를 자르기 전에 HTML 엔티티 해제와 태그 제거를 최대 6회 반복하고 마지막 잔여 태그·이미지 자리 문자·공백을 정리한다. script/style 본문과 닫히지 않은 태그도 제거하며 숫자 엔티티와 중첩 인코딩을 처리한다. 저장된 분야 캐시에도 같은 정리를 적용한다. HTML 렌더러나 외부 이미지 요청은 사용하지 않는다. 각 피드에서 제목·원문 HTTPS 링크·소개 최대 160자·발행 시각·언론사를 읽는다. 원문 URL(가능하면 RSS guid)·정규화한 동일 제목을 중복 제거한다. 숫자가 같고 제목 길이 비율 85% 이상·발행 간격 6시간 이내인 16자 이상 제목은 문자 쌍 유사도 90% 이상일 때만 같은 기사로 취급한다. 매체별 후보 최대 30개에서 최대 15개, 전체 최대 1200개를 발행 시각 내림차순으로 섞고 시각 미제공 기사는 뒤에 놓는다. 정렬·중복 제거는 백그라운드에서 처리하고 제목 비교용 자료는 후보당 한 번만 만든다. 동일 제목·URL은 집합으로, 유사 제목은 같은 숫자 묶음 안에서만 비교한다. 중요도 순위는 제공하지 않는다. 본문 전문·사진·AI 생성 요약·의미 기반 사건 묶음은 추가하지 않는다. 처음 불러오는 동안 중앙 144×80의 세 겹 물결과 상태 문구를 제공하고, 실패는 재시도 안내와 새로고침으로 구분한다. 화면은 캐시를 먼저 표시하고 보이는 동안의 보충 간격도 2시간이다. 자동 수신한 새 목록은 대기 상태로 두고 ‘새 뉴스가 있어요 · 보기’를 누를 때 적용한다. 수동 새로고침·분야 변경·새 뉴스 적용은 맨 위로 이동하며 그 외에는 기존 읽기 위치를 보존한다. 실패는 이전 목록과 갱신 시각을 유지하고 5분 뒤 재시도한다. 자동 기사 넘김·개별 기사 WebView/이미지 로딩은 없다. 동시 수신은 세 개로 제한하고 나머지는 대기하며 필요한 목록 행만 그린다. 각 매체를 독립적으로 요청하고 일부만 실패하면 성공한 뉴스와 그 매체의 24시간 이내 기존 기사를 함께 표시한다. 실패한 매체의 저장 시각을 갱신하지 않아 오래된 기사를 계속 연장하지 않는다. 일부 실패 안내를 표시하고 5분 뒤 다시 시도하되 각 출처의 마지막 성공부터 2시간 이내인 결과는 재사용한다. 수동 새로고침은 이 재사용을 우회하며 모두 성공하면 2시간 간격으로 돌아간다. 상단 갱신 시각은 여러 언론사 목록의 수신 시각이고 기사 행에는 실제 언론사와 발행 시각을 표시한다.

뉴스 위젯이 배치되어 있으면 사용자가 선택한 분야만 약 2시간마다 화면 밖에서 미리 받아 저장한다. 최신용 전체 피드를 별도로 받지 않는다. 분야를 바꾸면 표시 중인 최신·대기 목록을 비우고 새 선택으로 합치며 진행 중인 수신도 비선택 분야의 추가 요청·결과 반영을 중단한다. 이미 시작한 요청은 종료/취소될 수 있으나 비선택 기사가 최신에 섞이지 않는다. 앱/런처 진입 시에도 예약과 별도로 조용히 보충하되 2시간 이내 캐시는 재사용한다. 정기 예약이 실제 실행될 때는 다시 수신해 예약 경계에서 갱신이 4시간으로 밀리지 않게 한다. 화면은 저장된 목록을 먼저 표시하며 캐시가 전혀 없으면 최초 성공한 출처부터 표시하고 이후 12개 출처 처리마다 중간 결과를 저장한다. 읽는 중 들어온 후속 목록은 ‘새 뉴스가 있어요 · 보기’로 적용해 읽기 위치를 유지한다. 동시 수신은 3개이고 캐시가 없거나 가장 오래된 출처부터 수신한다. 작업이 중단되어도 이미 저장된 결과는 남는다. 수동 새로고침은 캐시 신선도와 관계없이 수신한다. 뉴스 위젯 삭제 시 백그라운드 예약·진입 시 보충을 중지한다. 최초 설치·장시간 오프라인 등으로 캐시가 없으면 통신이 필요하다. 예약 시각은 운영체제의 절전·네트워크 상태에 따라 늦어질 수 있어 정확한 2시간 실행을 보장하지 않는다.

### 브라우저 기본 홈 전체 영역 넘기기와 뉴스 목록

브라우저 기본 홈은 즐겨찾기 위·아래의 빈 공간과 즐겨찾기 항목에서 모두 좌우 드래그로 옆 홈을 넘긴다. 검색 입력에서는 편집 동작을 유지하고, 즐겨찾기를 탭하면 기존 링크를 연다. 뉴스는 Android LazyColumn·iPad LazyVStack으로 한 행에 한 기사를 표시하며, 기사 전체 클릭·접근성 묶음·발행 시각·스크롤 복귀·갱신 동작은 유지한다.
