# 다나와·에누리 수집 경로 조사

점검일: 2026-11-04 · 기준 코드: `fa08e353`+작업 트리 (판매처와 공식 연동 경로 조사)

## 결론과 범위

두 서비스는 판매자가 제공하는 구조화 상품 데이터 경로를 공개 문서로 설명한다. 소비자 화면의 공개 JavaScript와 응답에서도 상품 묶음, 판매처별 가격, 배송·카드 조건, 판매처 이동 경로를 확인했다. 따라서 단순히 검색 화면의 텍스트만 추출하는 것보다 깊게 분석할 수 있다. 다만 이를 서버 수집 프로그램·상품 매칭 엔진을 복원한 것으로 표현하면 안 된다.

이번 조사는 공개 페이지·공개 정적 스크립트·실제 페이지에 등장한 요청과 링크만 사용했다. 상품 조회 HTTP 요청은 쿠키·인증·사용자 지정 User-Agent 없이 실행했다. 원판매처 이동은 일반 Chrome에서 판매처 링크를 눌러 확인했다. 로그인·구매·관리자 기능 호출·접근 제한 우회는 하지 않았다. 데스크톱 표본 관찰이며 기기 앱 전체 연동 검증과 구별한다.

2026-11-02 조사 시점의 양쪽 Debug 앱은 공개 검색 HTML 추출 방식이었다. 현재 앱은 [shopping_products.md](shopping_products.md)의 판매처 직접 검색으로 전환했고, 비교 사이트 검색/발견/판매처 확인 경로를 실행 코드에서 제거했다. 이 문서의 비교 사이트 JSON·공급 경로는 연구 기록이며 현재 앱 수신 경로가 아니다. 공개 호출 성공은 외부 개발자를 위한 공식 API 지원 계약이나 장기 안정성을 뜻하지 않는다.

## 공개 여부와 확인 수준

| 영역 | 판정 | 직접 확인한 근거와 한계 |
|---|---|---|
| 소비자 검색·판매처 JSON 요청 | 공개 응답 확인 | 아래 5개 GET이 인증 없이 HTTP 200. 공개 클라이언트가 사용하는 경로이며 외부 SDK로 문서화된 API는 아님 |
| 상품 묶음·판매처 식별자·가격 조건 | 공개 응답 확인 | 다나와 productSeq/pcode, shopCode/shopProductCode, 에누리 catalogNo/plno, 가격·배송·카드 필드 |

| 공급 데이터 형식 | 공개 문서 확인 | 다나와 엔진페이지 안내, 에누리 EP 2.0 안내. 실제 업체별 피드 주소를 확보한 것은 아님 |
| 에누리 판매자 SDU 관리 | 로그인 경계 확인 | 소비자 사이트 하단 링크가 비밀번호 입력을 갖춘 판매자 로그인 화면으로 연결됨. 로그인 이후 내용은 조사하지 않음 |
| 업체별 피드 URL·인증·수신 설정·계약 | 미확보 | 공개 규격만으로 실제 접근 가능성이나 제공 범위를 판단할 수 없음 |
| 서버 수집·정제·매칭·색인·순위 코드 | 서버 내부, 미관측 | 브라우저에 결과와 일부 옵션만 노출됨. 내부 알고리즘·가중치·작업 큐·실제 운영 주기는 복원하지 못함 |
| 다나와 구형 상세 페이지의 일반 HTTP 403 | 클라이언트별 접근 차이 | 같은 페이지가 일반 Chrome에서는 열림. 403만으로 비공개 데이터라고 분류하지 않음 |

`/api`라는 경로명 자체는 비공개를 의미하지 않는다. 반대로 공개 응답만으로 공급자 전용 데이터에 대한 접근 권한이나 양 사이트의 서버 구조가 같음을 추론하지 않는다.

## 공급 데이터는 어떻게 들어오는가

### 다나와

[공식 고객센터의 독립몰 엔진페이지 안내](https://help.danawa.com/serviceHelpList.php?cate1=53&cate2=0)는 전체 상품과 신규·갱신 상품 목록을 서로 다른 URL로 제공하는 방식을 설명한다. 각 레코드는 상품 식별자·분류·상품명·제조사·상품/이미지 URL·가격·배송료 등을 구분자로 나눈 형식이다. 판매자가 만든 구조화 목록을 받는 경로가 있다는 근거다. 모든 판매처가 이 형식만 사용한다는 근거는 아니다.

[현재 입점 안내](https://help.danawa.com/bizCenter/index.php?depth1=1)는 PC·가전의 기존 연동몰·독립몰을 스토어 다나와로 개편하며 신규 입점을 제한한다고 안내한다. 따라서 기존 FAQ의 형식을 현재 모든 신규 제휴의 최신 계약 규격으로 간주하면 안 된다. 개별 업체의 실제 엔진 URL·갱신 설정은 이번에 확보하지 않았다.

### 에누리

[공식 가격비교 FAQ](https://www.enuri.com/faq/customer_faq.jsp?faq_type=1&kind=2)는 자동 처리와 수작업을 혼합한 누리봇, 판매자의 SDU 업데이트, 수신 시차에 따른 가격 차이를 설명한다. FAQ의 과거 운영 횟수를 현재 실측 주기로 사용하지 않는다.

[공식 호스트의 EP 2.0 v1.51 문서](https://seller.enuri.com/sdul/enuri_EP2.0_guide_v1.51.pdf)는 전체·변경 목록의 별도 TXT URL, 탭 구분과 헤더, 식별자·PC/모바일 가격·링크·이미지·배송 및 조건 필드를 설명한다. 전체/변경 데이터의 갱신 절차도 설명되어 있다. 공개 URL에서 인증 없이 내려받았으나 문서에는 CONFIDENTIAL 표시가 있으므로, 공개 노출된 공급자용 설명서로 분류한다. 비공개 판매처 데이터나 내부 프로그램을 획득한 것으로 표현하지 않으며 원문 전체·필드 표 전체를 재배포하지 않는다. 실제 공급 파일 주소·인증·업체 설정은 별개다.

이 자료들로 확인되는 것은 **판매처 제공 목록을 받아 가공하는 경로가 존재한다**는 점이다. 모든 원천 데이터가 공개 페이지 크롤링으로만 만들어진다거나, 모든 판매처가 같은 방식으로 연결된다는 결론은 내리지 않는다.

## 실제 확인한 소비자 요청

검색어는 `무선 헤드폰`. 공개 검색 HTML의 초기 데이터에서 실제 매개변수를 추출하고, 공개 스크립트에서 요청 작성 방식을 읽었다. 코드를 실행하거나 숨겨진 주소를 추측해 탐색하지 않았다. 검색·판매처 목록은 시점별 응답이며 거래 가능한 전체 상품 수를 보증하지 않는다.

| 사이트·요청 | 실제 결과 | 식별자와 주요 필드 |
|---|---|---|
| 다나와 `https://search.danawa.com/api/search/product-list/` 1페이지 | HTTP 200, products 40개 | productSeq, productName, makerCode, category, 가격 관련 필드 |
| 같은 다나와 검색 2페이지 | HTTP 200, products 40개 | page=2. 두 응답의 전체 건수는 조회 시점에 달라져 고정 스냅샷이라고 간주하지 않음 |
| 다나와 `https://search.danawa.com/api/search/mall-min-price/` | HTTP 200, items 5개 | shopCode, shopProductCode, price, deliveryFee, deliveryFeeText, productUrl |
| 에누리 `https://price.enuri.com/api/product/catalog/price-comparison` 1페이지 | HTTP 200, priceList 20개, total=77 | plno, shopCode/name, productName, price/mobilePrice/cardPrice/cardInfo, deliveryPrice/text, isAd/isOverseas |
| 같은 에누리 판매처 2페이지 | HTTP 200, priceList 20개 | page=2. 페이지 경계의 중복 여부는 저장 응답의 요약 파일에 기록 |

다나와 검색은 공개 초기 데이터에 있던 keyword/originalKeyword, sort=saveDESC, page, limit=40, addDelivery=N, platform=P 및 분류·필터 값을 재현했다. 전체 URL은 로컬 `api-manifest.json`에 보존한다.

다나와 판매처 요청의 실제 매개변수:

```text
productCode=99736994
categoryCode=37350&group=12&depth=2
physicsCate1=224&physicsCate2=49729&physicsCate3=49739&physicsCate4=0
includeDeliveryFee=false&productType=standard&makerCode=1156&makerName=BOSE
```

분류 코드 `12237350`은 공개 클라이언트의 `parseCategoryCode`로 group=12, depth=2, categoryCode=37350으로 분해됨을 확인했다. 판매처 이름이 빈 문자열인 항목도 있어 이름을 추측해서 채우면 안 된다.

에누리 판매처 요청의 실제 매개변수:

```text
catalogNo=100786235&delivery=N&card=N&quick=N&official=N
selshop=&selcard=&sort=price_asc&page=1&size=20
```

저장한 페이지 1/2를 식별자로 대조하면 다나와는 페이지 간 중복 0개였다. 에누리는 `plno=30900790873` 하나가 양쪽 페이지에 나타나 40개 항목 중 고유 판매처 항목은 39개였다. 두 페이지가 동일 시점의 고정 스냅샷이라는 보장이 없으므로 합칠 때 offer ID로 중복 제거해야 한다.

에누리 `/api/search/list`, `/api/search/list/meta`, `/api/search/list/count`는 공개 스크립트에서 경로·매개변수 작성만 확인했다. 이번에 직접 호출하여 성공을 확인한 목록에는 포함하지 않는다.

## 원판매처까지 추적한 두 사례

### 다나와 → 롯데ON / 롯데백화점

1. 다나와 상품 `pcode=99736994`, BOSE QC 울트라 헤드폰 2세대.
2. 판매처 응답의 `shopCode=TLC16`, `shopProductCode=LE1220529642`와 일반 판매처 이동 링크를 대조.
3. Chrome에서 해당 판매처 링크를 눌러 롯데ON 상품 `LE1220529642`로 이동. 도착 URL에는 선택 항목 식별자 `LE1220529642_1323575105`와 유입 매개변수가 포함됨.
4. 원판매처의 정규 주소 `https://www.lotteon.com/p/product/LE1220529642`를 인증 없이 직접 조회해 HTTP 200 확인.
5. 원판매처 HTML의 JSON-LD에서 sku·상품명·모델 정보·479,000원·KRW·재고 상태·판매자 롯데백화점 확인. 브라우저 본문에서는 무료배송도 확인. 배송 정보의 근거는 JSON-LD가 아닌 표시 본문이다.

이 사례는 비교 사이트에서 발견한 상품번호를 이용해 원판매처 데이터를 별도로 다시 읽을 수 있음을 보여 준다. 색상 미선택 상태의 관찰이므로 모든 옵션의 재고·최종 가격이 같다고 확대하지 않는다.

### 에누리 → 현대Hmall

1. 에누리 상품 묶음 `catalogNo=100786235`, 판매처 항목 `plno=31495381993`, `shopCode=57`.
2. 공개 페이지의 `https://www.enuri.com/move/Redirect.jsp` 링크에 modelno/pl_no/vcode가 포함됨을 확인하고 정상 클릭.
3. 도착한 현대Hmall의 상품번호는 `slitmCd=2252647284`. **plno는 에누리 판매처 항목 ID이며 현대Hmall 상품번호가 아니다.**
4. 정규 주소는 `https://www.hmall.com/md/pda/itemPtc?slitmCd=2252647284`. 일반 HTTP는 200이지만 초기 HTML은 화면 껍데기여서 상품 가격 JSON-LD가 없었다. 일반 브라우저에서 렌더링한 본문과 JSON-LD로 확인했다.
5. 원판매처 본문은 321,000원과 304,950원을 함께 표시하며 후자를 **로그인 시 최대 혜택가**, 바로사용쿠폰 16,050원 조건으로 설명했다. 별도의 KB국민카드 할인도 표시되지만 선택안함 상태였다. 무료배송을 확인했다. 구매·로그인은 하지 않았다.
6. 렌더링된 Product JSON-LD의 offers.price도 304,950원이어서 구조화 가격만 읽으면 조건 없는 가격으로 오인할 수 있다.

에누리 응답은 같은 304,950원을 cardPrice/KB카드로 설명했다. 원판매처와의 조건 표기 차이가 관찰됐으며 유입·시점·혜택 맥락을 분리하지 않고 어느 한쪽이 틀렸다고 단정하지 않는다. 추적 매개변수가 없는 주소의 혜택이 항상 같다는 것도 검증하지 않았다.

## 실제 비공개 경계와 미확인 부분

소비자 사이트의 판매자 SDU 링크는 `https://www.enuri.com/member/login/login.jsp?cmdtype=sdu`로 연결되며 비밀번호 입력을 요구하는 로그인 화면을 확인했다. 별도 오픈마켓 SDUL 링크 `https://www.enuri.com/sdul/mallregister/SellerMain.jsp?sm=1`는 `https://seller.enuri.com/`으로 이동했다. 이 후자의 초기 HTML에 비밀번호 필드는 없었으므로 두 경로를 동일한 로그인 화면으로 기록하지 않는다.

이번 관찰에서 확보하지 못한 것은 다음과 같다. 모두 공개 문서에 일부 개념이 소개되더라도 실제 값·구현을 확인한 것으로 취급하지 않는다.

- 업체별 원천 EP/엔진 URL, 접근 제한이나 인증 설정, 계약과 제공 범위.
- 실제 수신 작업·재시도·중복 처리·캐시·검색 색인의 서버 코드와 운영 설정.
- 동일 모델/옵션 매칭, 정품/해외구매 분리, 오등록 검수의 상세 규칙·모델·가중치.
- 업체별 실제 갱신 시각과 수집 주기, 크롤러가 담당하는 범위, 수작업 처리 기준.

다나와 상세 HTML과 일부 상세 스크립트의 일반 HTTP 요청은 403이었지만 일반 브라우저 상세 화면은 공개되어 있었다. 이를 로그인 전용이라고 주장하지 않는다. 에누리 공식 문서의 공개 노출도 판매자 계정이나 개별 공급 데이터까지 공개됐다는 뜻은 아니다.

InnoSearch의 기존 공개 클라이언트 분석으로 확인한 부분 결과·중복 제거·화면 동작과 이번 공급 경로 조사는 별개다. InnoSearch가 같은 EP를 받는지, 판매처별 API와 크롤링을 어떤 비율로 쓰는지는 이번 결과로 확인되지 않는다.

## 구현에 반영할 판단 기준

- 비교 사이트의 상품 묶음·판매처 링크는 발견 경로로 활용할 수 있고, 검증된 원판매처 주소에서 가격·배송·모델을 별도로 확인하는 수집기를 만들 근거가 생겼다. 이번 두 사례만으로 전 판매처 지원을 선언하지 않는다.
- catalog/product ID, 비교 사이트 offer ID, 판매처 SKU, 옵션 ID를 따로 보존한다. 이름이나 최저가 하나로 동일 상품을 합치지 않는다. 공개 목록에 패키지·색상·SE 표기가 섞인 사례가 있었다.
- 표시가, 쿠폰/로그인 혜택가, 카드가, 모바일가, 배송비와 조건을 분리한다. 원판매처 JSON-LD도 무조건적인 결제가로 취급하지 않는다. 각 필드에 출처·조회 시각·적용 맥락을 붙인다.
- 전체 판매처 목록을 공급받으려면 실제 제공 경로와 접근 조건을 확보해야 한다. 공개 규격만으로 비공개 피드 주소를 추측하거나 공급자 권한이 생겼다고 간주하지 않는다.
- 현재 앱의 허용 주소·전송 계층은 다섯 쇼핑 도메인 기준이다. 원판매처를 앱에 추가할 때는 양쪽 플랫폼에서 주소 검증·리다이렉트·가격 조건 처리를 별도 설계·구현·빌드해야 한다.

## 재현 근거와 검증 한계

원시 응답은 Android 작업 폴더의 Git 제외 경로 `output/diagnostics/shopping/reverse-20261102/`에 저장했다. 이 폴더는 소스 저장소 배포물이나 iPad 저장소에 복제하지 않는다. 추적 URL 등이 들어 있으므로 파일 권한을 제한했다.

| 기록 | 내용 |
|---|---|
| `pages-manifest.json`, `assets-manifest.json` | 원본 URL·HTTP 상태·바이트·SHA-256, 공개 검색 스크립트 99개 |
| `api-manifest.json`, `*-api.json` | 실제 호출한 GET 5개와 원본 응답, 페이지 1/2 |
| `*-querykeys.json`, `*-public-data.json` | 공개 초기 데이터에서 읽은 키·상품/판매처 관련 데이터 |
| `retailer-direct-manifest.json`, `lotteon-original.html`, `hmall-original.html` | 원판매처 정규 주소 HTTP 상태·해시·HTML |
| `boundaries-manifest.json` | 판매자 진입·로그인 화면과 공식 공급/입점 안내의 정상 비인증 조회 |
| `detail-assets-manifest.json` | 일반 HTTP에서 403인 상세 스크립트. 성공 사례로 계산하지 않음 |
| `enuri-EP2.0-v1.51.pdf`, `ep-guide-04.png`, `ep-guide-05.png` | 공급 문서 원본과 실제 렌더링해 확인한 4·5페이지 |
| `verification-summary.json`, `browser-observations.json` | 저장 응답의 수량·페이지 중복 요약과 원판매처 브라우저 관찰 |

실제 Chrome에서 두 비교 사이트 상세와 두 원판매처를 확인했다. 원판매처 가격과 조건은 이 날짜·상품·유입 맥락의 표본이다. 2026-11-02 조사 단계에서는 연구 문서만 양쪽에 추가했으므로 앱 빌드·기기 설치·자동 테스트를 새로 수행하지 않았다. 이후 원판매처 확인 기능의 구현·검증 기록은 shopping_products.md와 2026-11-03 완료 보고를 기준으로 한다.

## 옥션·지마켓 직접 수신 추가 조사 (2026-11-03)

- 같은 `키보드` 검색 주소를 데스크톱 Chrome에서 열면 기존 추출기가 대상으로 삼는 옥션 `.itemcard` 100개, G마켓 `.box__component-itemcard` 133개가 보였다. 카드는 광고·추천을 포함하므로 유효한 고유 상품 수와 구별한다. Tab S9 쇼핑 검색 기록에는 옥션 모바일 검색 주소와 G마켓 검색 주소의 메인 문서 HTTP 403이 남았다. 맥에서 두 판매처의 www 검색 주소를 직접 요청했을 때는 Cloudflare 차단 본문과 HTTP 403을 확인했다. 앱에서 받은 403의 본문과 세부 차단 규칙은 확인하지 못했다.
- [다나와 로지텍 K380S 판매처 목록](https://prod.danawa.com/info/?pcode=28555004)에서 두 판매처의 가격·배송비가 표시된다. 저장된 에누리 판매처 목록의 두 번째 응답에도 옥션(`shopCode=4027`)과 G마켓(`shopCode=536`)의 별도 가격·배송 항목이 들어 있다. [ESM 상품 API](https://etapi.gmarket.com/20)는 외부 제휴 채널 상품 노출 설정을 명시하고, G마켓·옥션 공식 파워클릭 안내는 다나와·에누리를 키워드 광고 제휴 매체로 명시한다. 이를 일반 가격비교 상품 전체의 공급 계약, 파일 주소, 공급 형식으로 확대 해석하지 않는다.
- **옥션 공식 상품 검색**. [GetSearchResults](https://api.auction.co.kr/APIv1/Auctionservice.asmx?op=GetSearchResults) HTTPS 문서와 WSDL이 HTTP 200을 반환했다. 같은 HTTPS 주소로 검색어만 담은 읽기 요청 한 건을 보내자 SOAP 권한 오류와 HTTP 500이 반환됐다. [등록 안내](https://developer.auction.co.kr/Information.aspx?menu=sub2)는 DevID, AppID, 인증티켓 절차를 설명한다. 검색 응답 스키마에는 상품번호, 이름, 가격, 이미지, 배송, 후기 관련 속성이 있지만 실제 응답의 값·정의·재표시 범위는 인증 후 검증해야 한다. 인증 값은 앱이나 저장소에 넣지 않는다.
- **G마켓 ESM 상품 조회**. [상품 목록 조회](https://etapi.gmarket.com/160)는 ESM+에 등록된 판매자 상품을 조회한다. ESM 마스터·판매자 계정에 연결된 권한을 사용하는 경로다. 제3자 앱이 전체 판매처 상품을 키워드로 검색하는 공개 API는 이번 조사에서 확인하지 못했다. 전체 상품 검색이 필요하면 앱 내 재표시가 가능한 제휴 상품 피드나 검색 API의 제공 여부를 확인한다. 공식 개발자 문서의 문의처는 [ESM API 홈](https://etapi.gmarket.com/)에 있다.

이 조사에서는 양쪽 앱의 수신 경로를 변경하지 않았다. 인증 상품 검색 성공이나 앱에서의 정상 수신은 아직 검증되지 않았다.

### G마켓 국내·글로벌 검색 및 제휴 경로 대조

- 국내 PC 검색, 모바일 검색, 모바일 스타배송 검색에 `키보드`를 일반 HTTPS로 요청했다. 세 주소 모두 Cloudflare를 거쳐 HTTP 403을 반환했다. 일반 데스크톱 Chrome에서 모바일 주소를 열면 PC 검색 주소로 이동해 기존 상품 카드 133개가 표시됐다. 공개 검색 주소를 모바일 주소로 교체하는 것만으로 앱의 수신 실패를 해결한다는 근거는 없다.
- [G마켓 글로벌](https://global.gmarket.co.kr/) 홈은 HTTP 200이었다. 홈 검색창에서 `키보드`를 제출하면 `gsearch.gmarket.co.kr/Listview/Search`로 이동한다. 데스크톱 Chrome과 별도 HTTPS 요청에서 상품 응답을 얻지 못했으며, 국내 상품·가격과 같은 범위를 보장하는 경로도 확인하지 못했다.
- [링크프라이스 공식 API 안내](https://www.linkprice.com/affiliate/views/affiliate_marketing/plus_service_api.html)는 광고주 인기·특가 상품 목록과 딥링크 변환을 제공한다. G마켓 전체 판매자의 상품을 키워드로 검색하는 기능이나 리보 앱에 대한 피드 제공 범위는 확인되지 않았다.
- ESM에 문의할 내용은 가격비교용 검색 API 또는 상품 피드 제공 여부, 앱 내 가격·배송비·후기 재표시 권한, 승인 조건과 갱신 한도다. 연락처 `etapihelp@gmail.com`은 [지마켓 공식 ESM 문서](https://etapi.gmarket.com/)에 기재되어 있다. 외부 문의 제출이나 실제 앱 수신 경로 변경은 하지 않았다.

## 네이버 스마트스토어·쿠팡 상품 검색 사전 확인 (2026-11-03)

- 네이버는 기존 쇼핑 검색 API를 2026-07-31 종료 대상으로 명시했다. [이관 공지](https://developers.naver.com/notice/article/32530)에는 쇼핑 상품 검색이 NAVER API HUB 이관 대상에서 제외된다고 적혀 있다. [커머스 API 상품 목록](https://apicenter.commerce.naver.com/docs/commerce-api/current/search-product)은 권한을 부여한 판매자의 상품 조회로 분류한다. 일반 요청으로 네이버쇼핑 PC 검색에서 HTTP 418, 모바일 검색에서 로그인 페이지 이동을 확인했다. 여러 스마트스토어의 상품을 키워드로 조회할 수 있는 공식 데이터 제공 경로는 확인하지 못했다.
- [쿠팡 파트너스 공식 가이드](https://partners.coupang.com/#help/open-api)의 문서 탭에서 `GET /v2/providers/affiliate_open_api/apis/openapi/products/search`와 최대 10개 상품을 확인했다. 같은 HTTPS 주소에 인증 없이 읽기 요청을 보내 HTTP 401을 받았다. 일반 쿠팡 검색 페이지는 같은 검색어에 HTTP 403이었다. 공식 검색 응답에는 상품번호·상품명·가격·무료배송/로켓배송 여부·이미지·파트너스 링크가 정의돼 있으며 후기 수·평점은 검색 응답에서 확인되지 않았다.
- 쿠팡 파트너스 키는 최종 승인 후 발급할 수 있다. 공식 가이드는 승인 전에 필요하면 AF ID와 광고 게재 위치·형태를 제출해 사전 검토를 요청할 수 있다고 안내한다. 승인 키가 있는 경우 Android 저장소의 `tools/shopping/check-coupang-partners.cjs`로 로컬 검색을 한 건 검증할 수 있다. 키와 서명은 앱 자산이나 저장소에 넣지 않는다.
- 이 단계에서는 두 앱의 판매처 선택·수신 경로를 수정하지 않았다. 인증된 실상품 응답과 앱에서의 수신은 검증 전이다.
