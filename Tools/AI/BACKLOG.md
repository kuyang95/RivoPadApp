# 로컬 AI·웹 기능 백로그

최종 갱신: 2026-07-30

Android VisionCraft의 AI 기능을 M4 iPad에서 로컬 우선으로 옮기되,
URL 본문과 최신 검색처럼 네트워크가 본질적으로 필요한 입력만 명시적으로
온라인 처리한다. 사용자가 조작해야 하는 품질 확인은 구현을 막지 않고
아래 실기기 목록에 모은다.

## 구현 완료

- M4 MLX 텍스트·비전 모델 로드와 스트리밍 대화
- 대화 기록 저장·복원·삭제
- 이미지, OCR, PDF·TXT 문서 질문
- 온디바이스 음성 인식 질문과 답변 TTS
- 앱 기능을 여는 로컬 규칙 기반 음성 명령
- 한국어·영어·일본어 대상의 전용 로컬 번역 화면
- 번역 원문 16,000자 제한, `<think>` 제거, 스트리밍 결과와 중지
- 명시적 클립보드 붙여넣기, 결과 복사·선택·읽기
- 앱 언어를 기본 번역 대상으로 사용하고 음성 번역 명령을 화면에 연결
- 직접 입력·붙여넣기·다른 앱 공유 URL을 하나의 웹페이지 질문 화면으로 연결
- HTTP(S) 검증, HTTP redirect와 내장 JS/meta redirect 2회, 10/15초 제한
- 응답 2MB 상한, charset 해석, script/style/navigation 제거와 HTML entity 복원
- 정적 본문이 200자보다 짧을 때만 15초 비공개 WebKit 렌더링 fallback
- 제목·최종 URL·24,000자 본문을 보존하고 원문 Safari 열기 제공
- 웹 본문 경계 문자열을 무력화하고 신뢰하지 않는 외부 자료로 M4 로컬 AI에 전달
- Brave `LLM Context`의 출처 제목·URL·관련 발췌만 온라인으로 받고
  최종 답변은 M4 로컬 모델에서 생성하는 선택적 웹 검색
- 개인 Brave API 키를 기기 전용 Keychain에 저장하고 기본 비활성화
- 첫 활성화 전 검색어 전송·최대 90일 로그 보관·현재 요금 고지와 명시적 동의
- 400자·50단어, 30초, 1MB, 최대 5개 출처 제한과 인증·결제·요청 한도 오류
- 검색 발췌를 비신뢰 경계로 격리하고 답변에 `[1]` 형식의 출처 번호 요구
- 출처 카드·원문 링크와 검색 결과·답변 비저장·비캐시 정책
- 일반 화면의 출처 사전 검토와 음성 검색의 검색→로컬 답변→TTS 자동 흐름
- Android처럼 대화 제목을 직접 고치고 이후 메시지 저장에도 사용자 제목 유지
- 제목과 전체 메시지를 대소문자·악센트·전각 차이 없이 여러 검색어로 필터링
- 대화·메시지 수 표시, 개별 삭제와 확인형 전체 삭제 및 실패 시 목록 복원
- 모든 대화 원문은 보존하면서 M4 메모리 등급에 따라 최근 2,800자 또는
  6,400자만 재개 문맥으로 복원하고 제외 메시지 수를 화면에 안내
- 활성 대화는 MLX의 4,096/8,192 토큰 회전 KV 캐시로 메모리 상한 유지
- 완성된 AI 답변을 언어 인식 문장 경계와 줄 단위로 나눠 순서대로 TTS 재생
- 화면에서 이전·현재 다시 읽기·전체 읽기/정지·다음 문장을 제어하고
  현재 문장 번호 표시
- 새 답변 생성·음성 입력·화면 이탈 때 기존 TTS를 취소해 중복 발화 방지
- 로컬 AI 화면에서 Rivo `4/5/6`을 이전·현재·다음 문장,
  `R3`를 답변 전체 읽기·정지로 우선 처리
- Android처럼 현재 대화 안에서 PDF·TXT 문서, 명시적 클립보드 텍스트와
  사진을 추가하고 첨부 상태를 화면에 표시
- TXT·클립보드 문맥은 최대 256KB까지 누적하고, 사진 또는 PDF 원본은
  하나만 유지하면서 새 원본으로 교체
- PDF 원본은 14MB까지 앱 내부에 보존하고 PDFKit 내장 텍스트 또는
  Vision OCR을 로컬 추출해 텍스트 모델에 전달
- 사진 원본은 32MB까지 앱 내부에 보존하고 최대 2,048px로 축소 디코딩해
  M4 비전 모델에 전달
- 첨부 이름·추출 문맥·원본 참조를 대화 기록과 저장·복원하고 원본 누락을
  안내하며, 교체·대화 삭제·전체 삭제 때 더 이상 쓰지 않는 원본 정리
- 첨부가 바뀌면 기존 MLX 대화 세션을 비우고 텍스트·비전 모델을 전환한 뒤
  M4 등급별 문맥 한도 안에서 최근 대화와 첨부를 다시 구성
- 첨부 경계 문자열을 무력화하고 비신뢰 참고 자료로만 사용하도록 프롬프트 격리
- 요약·정보 목록·다음 행동 빠른 질문과 문서·클립보드·사진 첨부 메뉴

## 다음 구현

### AI-006: 긴 문서와 추가 Android 문서 형식

- 긴 PDF·TXT를 단순 앞부분 절단 대신 문단 청크와 질문 관련도 기준으로 선택
- Android의 XLS/XLSX 셀 텍스트 추출을 iPad에서 로컬 구현
- HWP는 공개 사양·검증 가능한 Swift 파서가 있는 형식부터 지원하고,
  암호화·구형 바이너리 등 안전하게 해석할 수 없는 파일은 명확히 안내
- 문서 형식별 크기·시트·페이지 상한과 메모리 압박 회귀 테스트

## 실기기 일괄 확인

- [ ] M4에서 첫 번역 모델 로드 시간과 두 번째 번역 시작 시간을 측정한다.
- [ ] 한국어↔영어, 한국어↔일본어와 영어↔일본어 문단·숫자·URL 보존을
      확인한다.
- [ ] 16,000자 입력, 생성 중 중지, 화면 닫기와 다른 AI 작업 충돌을
      확인한다.
- [ ] 붙여넣기·복사 때 iPadOS 개인정보 배너와 VoiceOver 안내가
      자연스러운지 확인한다.
- [ ] Dynamic Type와 가로·세로 화면에서 원문·결과 편집 영역을 확인한다.
- [ ] Safari 공유 URL, 제목과 URL이 함께 공유된 항목, 직접 붙여넣기와
      scheme 없는 도메인이 같은 웹 질문 화면으로 열리는지 확인한다.
- [ ] 일반 HTML, HTTP redirect, meta/JavaScript redirect와 본문 200자 미만
      동적 페이지에서 제목·최종 URL·본문이 맞는지 확인한다.
- [ ] 2MB 초과 응답, 24,000자 본문, 오프라인, 인증·봇 차단 페이지와
      읽기 중 중지 오류 안내를 확인한다.
- [ ] HTTPS가 아닌 주소는 iPadOS ATS 정책에 따라 차단될 수 있으며,
      이때 HTTPS 사용 안내가 표시되는지 확인한다.
- [ ] WebKit fallback이 비공개 데이터 저장소를 사용하고 화면 이탈 뒤
      로딩·JavaScript 실행이 남지 않는지 확인한다.
- [ ] 웹 본문의 명령문과 경계 문자열을 AI가 실행하지 않고, 답변 화면에서
      제목·출처 URL과 Safari 원문 열기가 유지되는지 확인한다.
- [ ] 개인 Brave Search 계정과 Search 요금제를 준비하고, API 키를
      설정의 Keychain에 저장한 뒤 개인정보 고지 동의 전에는 검색이
      실행되지 않는지 확인한다.
- [ ] 최신 한국어·영어·일본어 질문에서 최대 5개 출처의 제목·URL·발췌와
      날짜가 맞고 원문 링크가 열리는지 확인한다.
- [ ] 검색 결과의 명령문과 `WEB_SEARCH_RESULTS_END` 문자열을 로컬 AI가
      실행하지 않고, 근거가 있는 문장에 실제 출처 번호를 붙이는지 확인한다.
- [ ] 잘못된 키, 결제 필요, 요청 한도, 빈 결과, 오프라인과 30초 초과 때
      로컬 모델이 최신 정보인 것처럼 추측하지 않고 오류를 표시하는지
      확인한다.
- [ ] 검색 뒤 AI 대화 목록을 다시 열거나 앱을 재실행해도 검색어·출처·답변이
      대화 기록에 남지 않는지 확인한다.
- [ ] “오늘 주요 뉴스 웹 검색해 줘” 음성 명령이 출처 검색, M4 답변과
      완료 후 TTS까지 한 번만 실행하는지 확인한다.
- [ ] Brave 대시보드에서 실제 요청 수·비용을 확인하고, 현재 안내한
      Search 요금 및 월 크레딧과 다른 경우 앱 고지를 갱신한다.
- [ ] 대화 제목을 수정한 뒤 대화를 다시 열어 질문을 추가해도 사용자
      제목이 자동 제목으로 되돌아가지 않는지 확인한다.
- [ ] 한국어·영어·일본어 제목과 오래된 메시지 내용 검색, 여러 검색어
      조합과 검색 결과 수가 맞는지 확인한다.
- [ ] 전체 삭제 확인에서 취소하면 유지되고, 삭제를 확정하면 앱 재실행
      뒤에도 모든 대화가 사라지는지 확인한다.
- [ ] 표준 메모리·확장 메모리 기기의 긴 대화를 다시 열었을 때 최근 문맥
      안내가 표시되고 답변은 이어지며, 목록에는 이전 메시지도 모두
      남는지 확인한다.
- [ ] 한국어·영어·일본어, 목록·줄바꿈, 약어·소수·날짜·URL이 섞인 긴
      답변이 빠지거나 중복되지 않고 자연스러운 문장 단위로 읽히는지 확인한다.
- [ ] 화면의 이전·현재·전체 읽기/정지·다음 버튼과 Rivo `4/5/6/R3`가
      같은 문장과 문장 번호를 가리키는지 확인한다.
- [ ] 답변 읽는 중 새 질문 전송, 음성 입력, 생성 중지, 화면 닫기를 반복해도
      이전 TTS와 새 답변 TTS가 겹치지 않고 마지막 문장에서 끝나는지 확인한다.
- [ ] 새 대화에서 TXT·클립보드를 차례로 첨부하면 두 문맥이 모두 유지되고,
      앱을 재실행해 같은 대화를 열어도 첨부 이름과 답변 근거가 복원되는지
      확인한다.
- [ ] 사진을 첨부해 질문한 뒤 PDF로 교체하고 다시 사진으로 교체할 때
      M4 텍스트·비전 모델 전환이 완료되며 이전 질문과 첨부가 섞이지 않는지
      확인한다.
- [ ] 텍스트가 포함된 PDF와 스캔 이미지만 있는 PDF에서 각각 PDFKit 추출과
      페이지 OCR이 동작하고, 14MB 초과 PDF·32MB 초과 사진·총 256KB 초과
      텍스트가 해당 제한을 정확히 안내하는지 확인한다.
- [ ] Files 또는 사진 보관함에서 첨부 원본을 가져오고 앱을 재실행한 뒤에도
      원본이 유지되며, 테스트용 원본을 앱 컨테이너에서 제거한 경우 대화가
      중단되지 않고 누락 안내를 표시하는지 확인한다.
- [ ] 요약·정보 목록·다음 행동 빠른 질문이 현재 대화와 첨부 내용을 기준으로
      한 번만 전송되고 VoiceOver와 큰 글자에서도 각 버튼이 구분되는지 확인한다.
