# 한글 PDF 저장·인쇄

2026-09-15. HWP·HWPX 문서 상단 **… → PDF로 저장 / 인쇄**에서 현재 편집 내용의 출력 미리보기를 만든다. 미리보기에서 별도 PDF 파일로 저장하거나 시스템 인쇄 창을 연다.

## 동작과 보존

- 현재 입력 중인 본문을 확정한 뒤 문단·표·쪽 설정의 복사본으로 출력한다. 간편 보기에서도 원본 페이지 배치를 사용한다.
- 원본 보기와 같은 페이지 구성·그리기를 사용하므로 본문·표·그림·수식·머리말·꼬리말·쪽 번호 등 해당 화면이 지원하는 요소가 출력 대상이다.
- 가로·세로 등 각 쪽의 실제 용지 크기를 PDF에 기록한다. 화면 도구줄·커서·종이 그림자는 출력하지 않는다.
- PDFKit으로 확대·스크롤 가능한 미리보기와 현재 쪽/전체 쪽 수를 표시한다. 파일 앱의 저장 위치·파일 이름 선택을 통해 PDF를 저장한다.
- 인쇄는 시스템 프린터·매수·용지·페이지 범위 설정을 사용한다. 인쇄 중 PDF를 유지하며 취소·닫기 후 편집 화면으로 돌아간다.
- PDF 저장은 원본 문서 저장과 별도다. 원본 파일의 바이트와 수정 상태, 실행 취소 기록을 유지한다. 원본 저장은 기존 **이 문서에 저장**을 사용한다.
- 편집이 제한된 HWP도 읽어 온 페이지를 출력할 수 있다. 비어 있거나 아직 읽는 중인 문서는 출력하지 않는다.

## 구현과 제한

`HWPPDFRenderer`는 UIKit을 포함한 실제 원본 페이지 뷰를 화면 밖에 잠시 배치해 페이지마다 고해상도 이미지로 그린 뒤 Core Graphics PDF에 기록한다. 최대 300dpi·페이지당 1,200만 화소로 제한하며 한 쪽씩 처리한다. 이 방식은 **PDF 글자 선택·검색을 지원하지 않는다**. 미리보기 안에도 이 제한을 표시한다. 문서 형식에 대한 기존 원본 보기의 지원 범위가 출력 품질의 범위이며 한컴 한글과 완전히 같은 배치를 만드는 별도 변환 엔진은 아니다.

출력은 최대 500쪽·200MiB, 용지 한 변 72~4,000pt로 제한한다. 진행률을 표시하며 취소할 수 있다. 실패·취소한 출력과 미리보기를 닫은 임시 PDF는 제거한다. 인쇄 창이 PDF를 사용하는 동안에는 임시 파일을 유지한다.

`HWPPDFPreview`에 PDF 미리보기·파일 내보내기·인쇄를 모았다. 인쇄 창의 기준 뷰는 미리보기 본문에 배치했다. 툴바 버튼 배경의 기준 뷰는 실제 윈도에 연결되지 않는 경우가 있어 화면 테스트에서 발견 후 수정했다.

## 검증

- PDF 자동 검사: 본문·머리말·꼬리말·쪽 번호, 혼합 용지 크기, 표 내용, 실제 HWP 신청서 모든 쪽, 중간 취소와 임시 파일 정리, 안전한 파일 이름을 검사한다.
- 전체 앱 ViewModel 검사: 미확정 입력이 PDF에 포함되고 원본 바이트·수정 상태·실행 취소가 유지되는지 확인한다.
- 화면 검사: 입력 직후 미리보기 → 실제 파일 저장 → 인쇄 창 열고 닫기 → 본문 저장·복귀 → 인쇄 바로가기를 실행한다.
- 독립 PDF 검사: Poppler로 일반 문서 1쪽, 세로·가로 표 2쪽, 실제 HWP 신청서 2쪽, 총 5쪽을 모두 렌더링해 직접 확인했다. M4에서 만든 혼합 용지 PDF 2쪽도 직접 확인했다.
- 실제 프린터에 인쇄 작업을 보내는 검사는 수행하지 않았다. 사용자 체크리스트에 별도 항목으로 남겼다.

최종 테스트·빌드·설치 결과는 아래 완료 기록과 `output/hwp_pdf_20260915/evidence.json`에 기록한다. 중간 실패 기록도 보존한다. M4의 전체 페이지 OCR이 색칠된 표 셀을 건너뛰는 경우가 있어, 출력 파일을 직접 확인한 뒤 테스트의 셀 영역을 따로 인식하도록 조정했다.

수동 가이드 `HWP_MANUAL_TEST_GUIDE_20260915.md`에 PDF 저장·인쇄 10개를 추가해 총 83개다. 사용자의 수동 확인란은 미완료로 유지한다.
