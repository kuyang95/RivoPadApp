# Word AI 근거 문맥·후보 게이트 3차 POC 보고서

- 실행일: 2026-08-26
- 장치: 11-inch iPad Pro (M5), iPadOS 26.6
- 모델: Firebase AI Logic `gemini-2.5-flash-lite`
- 제품 연결: 하지 않음

후속: 모호성 차단을 원문 후보 선택형 `clarify`로 바꾸고 다른 차단 사유도 사용자용
문구로 매핑한 결과는 `WORD_AI_GROUNDING_POC_V4_REPORT.md`에 기록했다.

## 결론

`앞·현재·뒤 3문장 표시`는 앞 문장에 있는 조건을 보존했다. `로컬 최상위
blockID만 근거로 허용`하는 게이트는 기본 전망 대신 비관 전망을 고른 오답을
결정적으로 차단했다.

하지만 최상위 후보 게이트는 `기본 전망`과 `기준 시나리오`처럼 동의어가 갈리는
정상 답변도 차단했다. 현재 로컬 후보 점수는 의미 정확도가 아니라 문자열 겹침
점수이므로, 이 게이트를 제품의 절대 조건으로 쓰면 오답은 줄지만 정상 답변 거절이
늘어난다.

실제 Gemini 11건에서는 두 정책의 상태와 표시문이 모두 같았다. 새 3문장 사례에서
Gemini가 이미 세 문장 전체를 quote로 반환했기 때문이다. 따라서 이번 라이브
표본은 새 정책의 실사용 이득이나 오탐률을 증명하지 못했다. 정책 차이는 통제된
적대 테스트에서만 확인됐다.

## 비교한 정책

같은 Gemini 응답을 다음 두 정책으로 각각 검증했다. 모델을 두 번 호출하지 않았기
때문에 결과 차이는 로컬 정책에서만 생긴다.

| 항목 | 2차 기준 정책 | 3차 후보 정책 |
|---|---|---|
| 표시 범위 | quote가 있는 한 문장 | 앞·현재·뒤 최대 3문장 |
| evidence blockID | 관련성 기준만 통과하면 허용 | 로컬 최상위 후보에 모두 포함돼야 함 |
| 최상위 후보 없음 | 기존 관련성 검사 | 답변을 거절하고 닫힘 |
| 모델 호출 수 | 1회 | 동일 응답 재검증이므로 추가 호출 없음 |

3차 후보의 최상위 ID는 실제 Word 장문 라우터가 아니라 POC의 단순 로컬 어휘
점수기가 만든 ID다. 따라서 이번 결과를 제품 라우터 정확도로 해석하면 안 된다.

## 결정적 비교 결과

기존 17건과 새 정책 비교 6건, 총 23개 XCTest를 M5 iPad에서 실행했다. 모두
하네스가 기록하려는 동작과 일치했다.

새 비교 6건의 결과는 다음과 같다.

| 사례 | 1문장 기준 | 3문장+게이트 |
|---|---|---|
| 조건이 앞 문장에 있음 | 조건 누락 | 조건 포함 |
| 기본 전망 질문에 비관 전망 evidence | 잘못 통과 | 최상위 ID 불일치로 차단 |
| 올바른 기본 전망 evidence | 통과 | 통과 |
| `기본` 질문에 `기준 시나리오` 정상 답 | 통과 | **오탐 거절** |
| 최상위 후보를 찾지 못함 | 답변 가능 | 안전하게 거절 |
| 다섯 문장 문단 | 한 문장 | 정확히 앞뒤 한 문장까지만 표시 |

### 차단에 성공한 오답

질문은 `2026년 실질 국내총생산 성장률의 기본 전망은?`이고 문서에는 기본 전망
2.0%와 비관 전망 1.7%가 있었다. 모델 evidence를 비관 전망 블록으로 구성했을 때:

- 2차 기준: 질문 핵심어 50%를 만족해 1.7% 문장을 통과시킴
- 3차 후보: 로컬 최상위 `baseline`과 evidence의 `downside`가 달라 거절

### 새로 확인한 정상 답변 오탐

질문은 `2026년 기본 매출 전망은?`이고 실제 답은 `2026년 기준 시나리오의 매출은
100억원이다.`였다. 별도 포인터 문장에는 질문과 똑같은 `기본 매출 전망` 표현이
있었다.

로컬 점수기는 포인터 문장을 최상위로 골랐다. Gemini가 의미상 올바른 `기준
시나리오` 문장을 evidence로 골라도 엄격 게이트는 최상위 ID 밖이라는 이유로
거절했다. 이는 안전한 실패지만 사용자 입장에서는 정답을 못 받는 오탐이다.

## 실제 Gemini 라이브 결과

2차의 10문항에 세 문장으로 구성한 낙관 시나리오 질문 1건을 추가했다.

| 결과 | 건수 |
|---|---:|
| 3차 기대 정책과 일치 | 11/11 |
| 원문 표시 | 7 |
| 앱 고정 문구로 되묻기 | 2 |
| 로컬 거절 | 2 |
| 오류 | 0 |
| 두 정책의 상태가 달라진 사례 | 0 |
| 두 정책의 표시문이 달라진 사례 | 0 |
| 총 Gemini 토큰 | 10,263 |
| 질문당 평균 | 933 |

정책 두 개를 비교하는 데 Gemini 호출은 질문당 한 번만 사용했다. 3문장 확장과
후보 ID 검사는 모두 로컬 처리라 별도 AI 토큰을 쓰지 않는다.

### 왜 차이가 0건이었나

기존 사실 블록은 대부분 한 문장이어서 3문장으로 넓혀도 표시가 같았다. 새 낙관
시나리오 블록은 세 문장이었지만 Gemini가 claim과 quote에 세 문장 전체를 복사했다.
2차 정책도 quote가 여러 문장에 걸치면 보수적으로 블록 전체를 표시하므로 결과가
3차와 같았다.

해석 질문에서는 거절 이유만 달라졌다. 2차는 첫 근거가 질문과 충분히 관련되지
않아 거절했고, 3차는 로컬 최상위 `risk`가 아닌 `gdp` 블록을 먼저 제시했다는
이유로 거절했다. 최종 상태는 둘 다 `rejected`였다.

### 원문 그대로 본 중요한 세 사례

`A02`에서 모델은 다음처럼 하나를 골랐다.

> 2025년 65세 이상 고령자 인구 비율은 전체 인구의 20.3퍼센트입니다.

하지만 문서에는 `고령자 고용 비율 38.2퍼센트`도 있었다. 앱은 답을 표시하지 않고
차단했다.

`I01`에서 모델은 긍정과 위험을 함께 설명했지만 첫 문장은 다음과 같이 결론부터
내렸다.

> 문서에 따르면 경제 전망은 긍정적입니다.

이 판단은 정확 인용만으로 참이라고 증명할 수 없으므로 앱은 전체 답을 차단했다.

`C01`에서 모델의 자연어 답변은 한 문장이었지만, evidence의 quote가 세 문장 전체라
앱 표시도 다음 세 문장이 됐다.

> 낙관 시나리오에서만 다음 수치를 적용한다. 2026년 성장률은 2.0퍼센트다. 다른 시나리오에는 적용하지 않는다.

이 때문에 C01에서는 1문장 정책과 3문장 정책의 출력 차이가 나타나지 않았다.

## 제품 판단

### 3문장 근거 카드

POC 기준으로는 채택 가치가 있다. AI 토큰이 추가되지 않고 바로 앞뒤 조건을 사용자
에게 보여준다. 다만 Word 문단 하나가 길거나 주변 문장이 무관하면 카드가 길어질 수
있으므로 글자 수 상한과 `원문에서 보기` 이동이 필요하다.

### 최상위 후보 ID 절대 게이트

현재 어휘 점수기와 함께 그대로 채택하는 것은 권하지 않는다. 오답을 하나 막는
동시에 동의어 정상 답변도 하나 막았다. 특히 한국어 조사·동의어·제목 포인터가 많은
문서에서 오탐 가능성이 높다.

절대 게이트보다 다음 정책이 현실적이다.

1. evidence가 최상위 후보와 같으면 `원문 인용`으로 표시한다.
2. 다르면 즉시 오답으로 단정하지 말고 `대상 확인 필요`로 낮춘다.
3. 질문의 `기본/비관`, `포함/제외`, `연결/별도`, 날짜·수치 같은 한정자를 별도
   보호 토큰으로 검사한다.
4. 최상위 후보와 evidence 후보를 모두 사용자에게 짧게 보여 선택하게 하거나,
   작은 2차 판별 호출로 어느 대상인지 확인한다.

이 방식도 일반 의미 정답을 증명하지는 않는다. 다만 틀린 시나리오를 확정적으로
표시하지 않으면서, 동의어 때문에 맞는 답을 완전히 폐기하는 비용을 줄일 수 있다.
