# Word AI 차단 사유·후보 안내 4차 POC 보고서

- 실행일: 2026-08-26
- 장치: 11-inch iPad Pro (M5), iPadOS 26.6
- 모델: Firebase AI Logic `gemini-2.5-flash-lite`
- 제품 연결: 하지 않음

## 결론

기술적인 `rejected`만 반환하던 모호성 경로를 **원문 후보가 포함된 `clarify`**로
바꿀 수 있었고, 실제 Gemini 평가에서도 의도대로 동작했다.

`고령자 비율은 얼마야?`에 Gemini는 인구 비율 20.3%를 하나 골라 답했다. 앱은
이를 오답으로 취급하거나 조용히 버리지 않고, 로컬 문서에서 찾은 다음 두 후보를
사용자에게 표시했다.

```text
관련된 항목이 여러 개 있습니다.
1. 2025년 65세 이상 고령자 인구 비율은 전체 인구의 20.3퍼센트이다.
2. 2025년 고령자 고용 비율은 38.2퍼센트이다.
어느 항목을 말씀하시는지 알려주세요.
```

이 문구와 수치는 Gemini의 자연어 답변에서 가져오지 않는다. 로컬 모호성 검출기가
선택한 실제 `blockID`를 원본 문서에서 다시 읽어 구성한다. 따라서 모델이 후보
안내에 다른 숫자를 끼워 넣을 수 없다.

## 변경한 검증 결과

`WordAIGroundingValidation`에 다음 정보를 함께 반환하도록 했다.

- `state`: `verified`, `clarify`, `reviewRequired`, `rejected`
- `displayText`: 사용자에게 보여줄 원문 또는 안전한 설명
- `reasons`: 결정적인 검증 사유 코드
- `candidateBlockIDs`: 로컬 문서에서 확인한 후보 ID

`localAmbiguityDetected`는 이제 다음 결과가 된다.

```text
state = clarify
reasons = [localAmbiguityDetected]
candidateBlockIDs = [population-ratio, employment-ratio]
displayText = 앱이 원문 후보로 만든 선택 안내
```

후보는 최대 3개, 후보 원문은 각각 최대 180자로 제한했다. 후보가 두 개 미만이면
기존의 안전한 일반 되묻기 문구를 사용한다.

## 다른 차단 사유 안내

모호성 외의 거절도 기술 코드 대신 사용자용 설명을 함께 반환한다.

| 사유 코드 | 사용자 안내 |
|---|---|
| `quoteNotFoundInBlock`, `unknownBlockID` | AI가 제시한 근거를 문서 원문에서 확인하지 못했습니다. |
| `questionValueNotInEvidence` | 질문의 날짜나 수치와 일치하는 원문 근거를 찾지 못했습니다. |
| `protectedValueNotInEvidence` | 답변의 날짜나 수치가 제시된 원문 근거와 일치하지 않습니다. |
| `polarityMismatch` | 답변의 증가·감소 방향이 원문과 일치하지 않습니다. |
| `evidenceNotRelevantToQuestion` | 제시된 원문이 질문과 충분히 관련되지 않아 답을 확정하지 않았습니다. |
| `evidenceOutsideTopCandidates` | AI가 선택한 근거가 질문의 최상위 원문 후보와 달라 답을 확정하지 않았습니다. |
| `topCandidateNotFound` | 질문과 가장 관련 있는 원문 후보를 확정하지 못했습니다. |
| `semanticInterpretationCannotBeProvenLocally` | 원문 인용만으로 결론을 확인할 수 없어 AI 해석으로 구분했습니다. |

이 설명은 왜 특정 로컬 게이트에서 멈췄는지는 알려준다. 답의 의미가 현실에서 왜
참 또는 거짓인지 설명하는 것은 아니다. 검증기는 여전히 처음 실패한 게이트를
반환하므로 여러 원인이 동시에 있어도 하나만 표시한다.

## 결정적 테스트

기존 근거 검증·정책 비교에 모호한 비율 후보 안내 공격 테스트를 추가해 총 24건을
M5 iPad에서 실행했다. 모두 하네스가 기록하려는 동작과 일치했다.

추가 테스트에서는 모델 자유 형식 메시지를 `고령자 비율은 99퍼센트입니다.`로
만들었다. 결과 안내에는 99%가 나타나지 않았고, 로컬 원문의 20.3%와 38.2%만
표시됐다.

## 실제 Gemini 라이브 결과

3차와 같은 11문항을 다시 실행했다.

| 결과 | 건수 |
|---|---:|
| 기대 정책과 일치 | 11/11 |
| 원문 표시 | 7 |
| 후보 또는 일반 되묻기 | 3 |
| 사유를 설명하며 거절 | 1 |
| 오류 | 0 |
| 총 토큰 | 10,255 |
| 질문당 평균 | 약 932 |

로컬 안내 생성은 Gemini를 추가 호출하지 않으므로 별도 AI 토큰이 들지 않는다.

### 고령자 비율

- 질문: `고령자 비율은 얼마야?`
- Gemini: `2025년 65세 이상 고령자 인구 비율은 전체 인구의 20.3퍼센트입니다.`
- 로컬 사유: `localAmbiguityDetected`
- 후보 ID: `population-ratio`, `employment-ratio`
- 앱 결과: 20.3%와 38.2% 원문 두 개를 나열하고 어느 항목인지 질문

20.3%가 틀려서 차단한 것이 아니다. 사용자가 인구 비율과 고용 비율 중 무엇을
뜻했는지 확정할 수 없어서, 맞을 수 있는 답을 후보로 보존한 채 되물은 것이다.

### 2026년 2.0퍼센트 전망치

GDP, 소비자물가, 낙관 시나리오 성장률 세 후보를 모두 원문으로 보여줬다. 이전의
일반적인 `대상을 구체적으로 알려주세요`보다 사용자가 무엇을 선택해야 하는지
분명해졌다.

### 경제 전망이 긍정적인가

최종 상태는 계속 `rejected`지만 빈 화면이 아니라 다음 설명을 반환했다.

```text
AI가 선택한 근거가 질문의 최상위 원문 후보와 달라 답을 확정하지 않았습니다.
```

2차 기준 정책에서는 관련성 부족, 3차 엄격 정책에서는 최상위 후보 불일치가 첫
실패 원인이므로 두 정책의 사용자 안내 문구는 달랐다.

## 제품 적용 시 필요한 UI

POC는 문자열과 후보 ID까지 만들었지만 실제 버튼 UI는 구현하지 않았다. 제품에서는
다음 형태가 적절하다.

1. 상단에 `여러 항목이 발견되었습니다`와 차단 사유를 짧게 표시한다.
2. 각 후보를 원문 카드 또는 버튼으로 보여준다.
3. 후보를 누르면 그 `blockID`를 후속 질문의 명시적 대상으로 사용한다.
4. `원문에서 보기`로 Word 원본 위치를 열 수 있게 한다.
5. 기술 코드 자체는 진단 로그에 남기고 사용자에게는 번역된 설명만 보여준다.

후보 선택 뒤에는 재검색할 필요 없이 선택한 blockID와 앞뒤 문맥으로 다시 검증할 수
있다. 다만 문서가 편집되었다면 기존 revision 검사를 거쳐 후보를 다시 만들어야 한다.

## 남은 한계

- 후보 원문은 안전하지만 항상 짧고 이해하기 좋은 선택지 이름은 아니다.
- 현재 후보는 단순 어휘 점수 기반이라 동의어 후보를 놓칠 수 있다.
- 최대 3개로 자르므로 네 번째 이후 후보가 있다는 사실을 UI에 별도로 알려야 한다.
- 첫 실패 원인만 반환하므로 진단용으로 모든 실패 원인을 수집하는 모드는 별도다.
- 이번 변경도 테스트 타깃 전용이며 실제 Word 채팅 화면에는 연결하지 않았다.
