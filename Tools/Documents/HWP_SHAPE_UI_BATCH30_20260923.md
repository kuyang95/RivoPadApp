# M5 도형 수동 UI 테스트 — 세부 시나리오 30개

실행일: 2026-09-23. 기기: iPad Pro 11-inch (M5), iPadOS 27.0. 설치된 통합 상단 UI 빌드를 그대로 사용했다. 빌드·재설치하지 않았다.

Device Hub 화면 공유에서 실제 버튼을 누르고 결과 화면을 확인했다. 자동화 테스트 실행 결과를 수동 테스트로 대신하지 않았다. 출력·인쇄·PDF는 제외했다.

**26개 통과 / 2개 실패 / 2개 미검증.** 이 30개는 조작별 세부 시나리오이며 기존 235개 체크리스트의 30개 완료를 뜻하지 않는다. HWPX 테스트이며 HWP 바이너리 형식이나 한컴 프로그램에서의 재열기는 확인하지 않았다.

## 실패 재현과 다음 조치

### F1 — 앱에서 만든 그룹의 위치 편집 거절

`HWP_M5_GROUP_30.hwpx`의 세 도형을 개체 → 선택 → 세 도형 선택 → 그룹 3으로 묶는다. 그룹 선택 → 위치·크기·스타일 → 오른쪽·아래 화살표 → 적용.

실제: “저장할 수 없습니다 / 이 문단에는 현재 버전에서 보존할 수 없는 복합 개체가 있어 직접 편집할 수 없습니다.” 이후 “도형을 수정하지 못했습니다.” 표시. 다시 열어도 좌표 20/60pt로 유지된다. 같은 그룹을 해제한 단일 도형에는 같은 이동이 성공했다.

그룹 생성·저장·해제는 성공하므로 그룹 외곽 편집 허용 판단과 적용 경로를 우선 점검해야 한다. 원인 확정이나 수정 완료를 의미하지 않는다.

### F2 — 본문과 겹친 도형의 선택이 글자 입력으로 전환됨

`HWP_M5_SHAPES_30.hwpx`를 열고 아래 파란 도형 선택 → 개체 → 선택 → 본문과 겹친 빨간 도형 중앙을 누른다.

실제: 글자 탭으로 바뀌고 본문 커서가 잡히며 다중 선택이 종료된다. 본문 문단을 제거한 비교 문서에서는 같은 도형 세 개를 모두 선택할 수 있었다. 도형/본문의 터치 처리 순서를 점검할 필요가 있다. 실제 iPad 직접 터치에서도 재확인이 필요하며, 테스트 파일의 IN_FRONT_OF_TEXT 선언에 대한 렌더링 문제 여부는 별도 미확정이다.

### 막힌 검사

내부 도형 선택은 화면 경로를 확보하지 못해 내부 위치·크기·회전·스타일·순서·삭제를 실행하지 않았다. 현재 작업 디렉터리의 HWPShapeGroupView에는 onSelect 전달은 있지만 사용 지점이 보이지 않았다. 이것은 소스 관찰이며 설치된 바이너리 원인 확정은 아니다.

글 배치·기준·바깥 여백은 원격 조작 제한으로 남겼다. 앱 기능 실패로 판정하지 않았다. 세로 동일 간격, 맞쪽 정렬, 뒤집기 또한 이번에 실행하지 않았다.

## 재현 파일

`HWP_M5_UI_20260923/`:

- `HWP_M5_SHAPES_30.hwpx`: 본문과 겹친 세 도형, F2 재현용.
- `HWP_M5_GROUP_30.hwpx`: 본문과 겹치지 않는 세 도형의 초기 상태.
- `group-saved.hwpx`: 실제 기기에서 그룹을 만들고 저장한 상태, F1 재현용.
- `ungrouped-saved.hwpx`: 실제 기기에서 해제·이동·원위치 복귀 후 저장한 최종 상태.

초기 파일은 테스트 준비를 위해 생성했으며 생성 자체를 UI 테스트 통과로 세지 않았다. 저장 파일 구조를 추가 확인한 결과 group-saved에는 사각형 3개·그룹 1개, ungrouped-saved에는 사각형 3개·그룹 0개가 있었다. 이 검사는 화면 확인의 보조 근거다. 화면 증거는 작업의 CUA 스크린샷 도구 결과에 남아 있다.

## UI 교체 후 재검사 — 2026-09-23 오후

사용자가 UI 변경을 설치한 뒤 같은 M5에서 재개했다. 홈의 새 카드 스타일과 주황색 입력 버튼을 화면으로 확인했다. 이 작업에서는 앱 코드 수정·빌드·설치를 하지 않았다.

| 대상 | 재검사 결과 | 관찰 |

| F1 그룹 위치 편집 | 실패 재현 | 같은 문단의 세 도형 선택·그룹 생성 후 오른쪽/아래 화살표와 적용을 누르면 동일한 복합 개체 보존 오류. 위치 미반영 |

기존 통과 동작 중 문서 열기, 단일/다중 선택, 그룹 생성·해제, 단일 도형 숫자 위치 적용은 새 UI에서도 동작했다. 이 재검사를 새 30개 완료로 합산하지 않았다. 최초 묶음의 **26 통과 / 2 실패 / 2 미검증** 판정과 전체 체크리스트 수치는 유지한다.

테스트용 그룹 생성·해제 변경은 버리고, 추가 위치·정렬 변경은 실행 취소한 뒤 문서 목록으로 복귀했다. 출력 관련 검사는 수행하지 않았다. Device Hub 메뉴에서도 별도 터치 입력 방식 전환을 찾지 못했으나, 이것만으로 실제 iPad 터치 스크롤도 실패한다고 판정하지 않는다.
