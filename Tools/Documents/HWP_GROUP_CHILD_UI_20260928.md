## F3 — 내부 편집이 다른 도형 크기에 영향

초기 그룹 외곽은 X 25/Y 65/390×95. 빨강은 그룹 안 (0,45,90,50), 녹색은 (145,20,90,50), 파랑은 (300,0,90,50)이다.

녹색의 Y를 30, 높이를 70으로 바꾸면 자식들의 전체 세로 범위가 95에서 100으로 늘어난다. 화면에서 빨강 높이가 약 64→61 px, 파랑 높이도 약 64→61 px로 줄었다. 선택하지 않은 도형이 바뀌므로 실패다. 실행 취소로 원상 복구되고 다시 실행과 저장·재열기에서 재현했다.

코드상 원인 후보: `HWPOriginalDocumentCanvas.swift`의 `HWPShapeGroupView.bounds`가 매번 현재 자식 사각형들의 합집합을 구하고 외곽 크기에 맞춰 전부 다시 확대·축소한다. `HWPShapeEditing.groupChildIndex`의 선택 좌표 계산도 같은 범위를 사용한다. 고정된 그룹 내부 좌표 기준을 유지하고 렌더링·선택 계산에 함께 적용하는 수정이 필요하다. 이는 코드와 관찰에 근거한 진단이며 수정 검증은 아직 하지 않았다.

재현 저장본: [child-resize-style-saved.hwpx](HWP_M5_UI_20260928/child-resize-style-saved.hwpx).

## F4 — 앞뒤 순서 변경 후 선택 대상 교체

노란 사각형을 빨간 사각형과 겹치게 놓고 내부 순서 메뉴에서 뒤로 보내기를 누른다. 겹침은 정상 변경되지만 파란 선택 테두리가 빨강으로 옮겨 간다. 편집 창을 다시 열면 노랑의 X 45 대신 빨강의 X 0/Y 45가 표시된다. 노랑을 다시 선택해 앞으로 가져와도 빨강이 선택된다.

코드상 근거: `HWPDocumentView.editShape`는 편집 후 `refreshedShapeTarget(target)`을 호출하며, 이 함수는 변경 전 `groupChildIndex`를 그대로 사용한다. 자식 배열의 순서가 바뀌면 같은 인덱스가 다른 도형을 가리킨다. 순서 이동량을 반영해 선택 대상을 갱신하거나 안정적인 자식 식별자를 사용하는 수정이 필요하다.
