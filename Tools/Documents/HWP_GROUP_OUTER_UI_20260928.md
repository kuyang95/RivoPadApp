# M5 그룹 도형 외곽 크기·회전 수동 검사

날짜: 2026-09-28  
기기: iPad Pro 11-inch (M5), iPadOS 27.0, Device Hub 화면 공유·직접 조작  
앱: `net.rivo.visioncraft`  
테스트 문서: 앱 문서 폴더의 `HWP_GROUP_OUTER_QA2.hwpx` (`HWP_M5_UI_20260923/group-saved.hwpx`의 복사본)

## 결과

| 조작 | 결과 |
|---|---|
| 그룹 외곽 너비 390→300pt, 높이 95→120pt | 통과. 빨강·초록·파랑 세 도형이 그룹 안에서 함께 비율에 맞춰 변경됨 |
| HWPX 원본 저장·닫기·재열기 | 통과. 저장 완료 표시와 재열기 후 300×120pt 확인 |
| 그룹 외곽 캔버스 회전 손잡이 드래그 | **실패 F5.** 두 차례 모두 회전 대신 그룹이 이동하고 저장 중 경고 표시. 회전값 0° 유지 |
| 편집 창 회전 슬라이더 | Device Hub 입력으로 0°/359°만 관찰. 목표 각도 적용은 미검증 |

## F5 재현

1. `HWP_GROUP_OUTER_QA2.hwpx`를 원본 보기로 연다. 빨강·초록·파랑 도형 중 하나를 눌러 그룹 외곽 파란 테두리를 표시한다.
2. 그룹 외곽 위쪽의 원형 회전 손잡이에서 오른쪽 아래 방향으로 드래그한다.
3. 기대: 그룹이 회전하고 세 도형의 상대 배치가 함께 회전한다. 위치는 의도치 않게 바뀌지 않는다.
4. 실제: 그룹 전체가 오른쪽 아래로 이동하고 `저장할 수 없습니다. 문서를 저장하는 동안에는 편집할 수 없습니다. 저장이 끝나면 다시 시도해주세요.` 경고가 뜬다. 경고를 닫고 편집 창을 열면 회전은 0°다.
5. 같은 손잡이에서 다시 드래그해도 같은 결과였다. 최종 X 157.5/Y 233pt, 너비 300/높이 120pt, 회전 0°를 확인했다.

`이 문서에 저장`으로 HWPX 저장 완료를 확인한 뒤 문서를 닫고 재열었다. 위치와 크기는 유지되고 회전은 여전히 0°였다. 저장된 재현본: [group-outer-size-saved.hwpx](HWP_M5_UI_20260928/group-outer-size-saved.hwpx).

회전 손잡이의 터치 판정 또는 이동 제스처 우선순위가 원인일 가능성이 있지만, 코드 원인은 아직 확정하지 않았다. 저장 중 경고는 이동이 반영되는 현상과 함께 별도로 확인해야 한다. 한컴 한글 재열기·출력은 이번 검사 범위에 없다.

## F5 수정 재검사

회전 손잡이가 도형 프레임 밖에 있어 실기기에서 터치를 안정적으로 받지 못했고, 이동 제스처가 손잡이 오버레이까지 적용될 수 있었다. 손잡이를 프레임 안에 배치하고 이동 제스처를 도형 본체에만 연결한 앱을 M5에 설치했다.

같은 문서의 그룹을 선택해 회전 손잡이를 드래그하자 빨강·초록·파랑 도형이 함께 **80° 회전**했다. 편집 창에서 X **157.5pt**, Y **233pt**, 너비 **300pt**, 높이 **120pt**가 그대로인 것을 확인했고 저장 경고가 나타나지 않았다. `이 문서에 저장` 후 닫고 다시 열어도 같은 회전·위치·크기가 유지됐다. 그룹 본체 이동과 실행 취소도 화면에서 확인했다. 저장본: [group-outer-rotation-fixed.hwpx](HWP_M5_UI_20260928/group-outer-rotation-fixed.hwpx).

M5 빌드·설치 성공, 도형 편집 회귀 테스트 **26/26 통과** (`/tmp/hwp-f5-m5-shape-tests.xcresult`). F5는 해결했다. 그룹 외곽의 글 배치·순서 조합은 아직 검사하지 않아 전체 체크리스트 항목은 부분 검증이다. 한컴 한글 재열기·출력도 검사하지 않았다.

## 그룹 외곽 글 배치·앞뒤 순서 후속 검사: F6

같은 M5 실기기에서 [검사용 HWPX](HWP_M5_UI_20260928/group-outer-layout-qa.hwpx)를 열었다. 기존 80° 회전 그룹에 독립 노란 도형을 겹치고, 한 문단에 본문 735자를 넣은 복사본이다. 이 문서는 글 앞 배치 상태에서 1쪽으로 보였다.

| 조작 | M5 실화면 결과 |
|---|---|
| 그룹을 앞으로 가져오기 2회 | 겹침 표시가 바뀌고 그룹 `zOrder=2`, 독립 도형 `zOrder=1`로 저장됐다. 닫고 다시 열어 겹침 표시와 저장값을 확인했다. [저장본](HWP_M5_UI_20260928/group-outer-layout-saved.hwpx) |
| 그룹을 본문과 겹치도록 이동 후 글 뒤 | 본문 글자가 빨강·초록 도형 위에 표시됐다. 이 상태는 1쪽이었다. |
| 글 둘레 | 본문이 도형 영역을 피했으나 문서가 1쪽에서 5쪽으로 늘고 줄 사이에 큰 빈 공간이 생겼다. 정상 배치로 판정할 수 없다. |
| 위아래 | 글 둘레와 같은 5쪽 배치. HWPX 저장 완료 표시 후 닫고 재열어도 5쪽과 큰 줄 간격이 유지됐다. [저장본](HWP_M5_UI_20260928/group-outer-layout-top-bottom-saved.hwpx) |

F6 재현 절차: 검사용 문서를 원본 보기로 열고 그룹을 선택해 `개체 → 위치·크기·스타일 → 본문과의 배치`를 `글 둘레` 또는 `위아래`로 바꿔 적용한다. 기대 결과는 도형을 피해 본문이 이어지는 적절한 줄 배치다. 실제로는 줄 하나마다 도형 하단까지의 높이가 반복 적용돼 5쪽으로 늘어난다. 저장본 `Contents/section0.xml`의 줄 높이 `vertsize=20200`(202pt)가 14개 줄에 반복되는 것도 확인했다. 코드에서는 `HWPShapeEditing.finalized`가 그룹 하단 높이를 `HWPFlowLayout.measure`의 `minimumHeight`로 전달하고, `measure`가 이를 모든 줄의 높이에 사용한다. 따라서 단순 화면 확대 문제가 아니다.

이번 검사는 그룹 외곽의 앞뒤 순서와 글 뒤 표시에는 통과 근거를 확보했지만, **글 둘레·위아래 본문 배치 결함 F6** 때문에 체크리스트의 그룹 외곽 편집 항목을 실패로 기록했다. 글 둘레의 좌우 흐름, 다른 문단·HWP 바이너리, 한컴 한글 앱 재열기는 아직 검증하지 않았다. 출력 관련 검사는 제외했다.

## F6 수정 재검사와 남은 배치 차이

본문의 모든 줄에 도형 높이를 최소 줄 높이로 반복 적용하던 계산을 첫 줄의 도형 앵커에만 적용하도록 수정했다. M5에 수정 앱을 설치해 같은 735자 문서에서 `글 둘레`와 `위아래`를 다시 조작했고, 5쪽으로 늘어나던 현상 없이 **1/1쪽**을 확인했다. 위아래 배치 상태로 HWPX를 저장하고 다시 열어도 1/1쪽이었다. 도형 편집 자동 회귀 검사 27개도 통과했다.

다만 `글 둘레`에서는 도형 왼쪽·오른쪽 남는 공간으로 본문이 흐르는 결과를 확인하지 못했다. 따라서 F6의 반복 줄 높이 결함은 해결됐지만, 그룹 외곽 편집 전체는 수동 체크리스트에서 **부분 검증**이다. 출력 검사는 하지 않았다.

## F7: 독립 사각형 편집 대상 오류

그룹과 별도로 놓인 노란 사각형을 `글자처럼 취급`으로 변경해 저장한 [재현본](HWP_M5_UI_20260928/shape-inline-saved.hwpx)을 조사했다. 독립 사각형 `id=105`는 `treatAsChar=0`으로 남고, 대신 그룹 내부 사각형 `id=101`이 `treatAsChar=1`로 바뀌었다. 닫고 다시 열었을 때 스위치가 꺼져 있고 그룹 도형이 비정상적으로 늘어나는 화면과 일치한다.

HWPX 사각형을 순서로 찾을 때 그룹 내부의 사각형까지 최상위 목록에 섞여 들어간 것이 원인이었다. 그룹 내부 범위에 포함된 도형을 최상위 편집 후보에서 제외하도록 수정하고, 그룹 생성 후 독립 사각형 편집이 그룹 자식을 건드리지 않는 회귀 테스트를 추가했다. M5에서 도형 편집 테스트 **28/28 통과** (`/tmp/hwp-f7-all-shape.xcresult`) 및 수정 앱 재설치까지 확인했다.

새 복사본 `HWP_SHAPE_INLINE_F7_RETEST.hwpx`를 M5에서 열고 독립 사각형의 편집 시트까지 진입했다. 화면 공유 입력으로 `글자처럼 취급` 스위치의 켜짐 상태를 확인하지 못해, **이 수정본의 저장·재열기 수동 검사는 아직 완료하지 않았다.** 이 항목을 통과로 계산하지 않는다.

## F8: 사각형 둘레 배치 수정·실기기 재검사

`HWP_GROUP_OUTER_F6_RETEST.hwpx`의 80° 회전 그룹을 `글 둘레`로 바꾼 뒤 M5 실화면에서 본문이 도형 옆으로 흐르지 않고 일부 글자와 겹치는 현상을 재현했다. [수정 전 저장본](HWP_M5_UI_20260928/group-square-wrap-f8-repro.hwpx)은 첫 줄 높이 190pt, 뒤 줄 너비 425.2pt였다. 기존 계산은 사각형 둘레 배치에서도 그룹 하단을 첫 줄의 최소 높이로 사용하고, 뒤 줄의 가로 너비를 줄이지 않았다.

사각형 둘레 배치에서는 그룹 높이를 줄 높이로 예약하지 않고, 회전한 도형의 외접 범위를 각 줄의 제외 영역으로 계산하도록 수정했다. 도형 편집 회귀 테스트 **29/29 통과** (`/tmp/hwp-f8-square-wrap.xcresult`) 후 앱을 M5에 설치했다. 그룹 X를 157.5→162.5→157.5pt로 변경해 재배치를 유도하자 본문이 그룹 왼쪽으로 흐르고 그룹 아래에서 전체 너비로 이어졌다. 1/1쪽을 유지했으며, 원본 HWPX 저장·닫기·재열기 후에도 같았다. [수정 후 저장본](HWP_M5_UI_20260928/group-square-wrap-f8-fixed.hwpx)에는 도형 옆 18줄의 너비 224.1pt, 아래 4줄의 너비 425.2pt, 모든 줄 높이 10pt가 기록돼 있다.

이 배치 시나리오는 통과했다. 다른 문단·HWP 바이너리의 그룹 배치 조합은 검사하지 않아 그룹 외곽 편집 전체는 부분 검증이다. 출력 검사는 제외했다.

## F9: 바깥 여백 수동 검사

M5에서 같은 회전 그룹의 바깥 여백을 왼쪽 20pt, 오른쪽 10pt, 위 5pt, 아래 15pt로 입력·적용했다. 본문은 도형 옆을 따라 배치되고 1/1쪽을 유지했다. 이전 저장본에서 도형 옆 줄 너비는 224.1pt였고, 왼쪽 여백 적용 뒤에는 204.1pt로 줄었다. 원본 HWPX를 저장·닫기·재열어 편집창의 네 값이 유지됨을 확인했다. [저장본](HWP_M5_UI_20260928/group-out-margin-f9-saved.hwpx)의 그룹 `outMargin` 값도 네 입력값과 일치한다. 바깥 여백 항목은 통과했다.

같은 수정본으로 독립 노란 사각형의 본문 배치를 `글 앞 → 글 뒤 → 글 앞`으로 변경했다. 두 변경 모두 M5에서 적용·HWPX 저장을 확인했고, `글 뒤`는 닫고 재열어 편집 시트에서도 유지됐다. `글 앞`은 재열기 화면과 저장 파일에서 유지됐다. 녹색 그룹 자식과 노란 도형의 겹침 순서도 상태에 따라 바뀌었다. [글 뒤 저장본](HWP_M5_UI_20260928/shape-front-back-f7-saved.hwpx)에는 독립 `rect id=105`만 `BEHIND_TEXT`, [글 앞 저장본](HWP_M5_UI_20260928/shape-front-f7-saved.hwpx)에는 같은 도형만 `IN_FRONT_OF_TEXT`이며 두 파일 모두 그룹 자식 `id=101/102/103`은 변경되지 않았다. 따라서 **글 앞·글 뒤** 수동 항목은 통과, **글자처럼 취급**은 계속 미실행이다.
