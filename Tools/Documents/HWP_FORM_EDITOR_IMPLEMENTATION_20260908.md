# HWP 신청서 편집기 첫 구현

작성: 2026-09-08

## 동작

간편 문서의 표·행 편집창에서 기존 HWP 양식의 빈 문단에 처음 글자를 넣고,
HWP로 저장한 뒤 다시 열어 수정할 수 있다. 기준 신청서의 제품명 문단을 포함해
PARA_TEXT가 없었던 표 문단 41개가 입력 가능해졌다. 같은 셀 안의 여백 문단도
포함하는 수이며, 입력 항목 41개를 의미하지 않는다.

내부 표를 소유한 문단 2개는 읽기 전용으로 구분한다. 그 내부 셀의 일반 빈 문단은
편집 가능하다. 기존 행 편집, 적용, 실행 취소·다시 실행, 원본 HWP 저장 흐름을 사용한다.

## 변경 범위

- 파서는 실제 문단 헤더, 텍스트 레코드 유무, 위치 0의 유효한 글자 모양,
  레코드 깊이와 종류, 원시 컨트롤 토큰, 범위 태그와 보호 여부를 확인한다.
- 없는 텍스트 레코드는 해당 문단 헤더 바로 뒤에 올바른 자식 깊이로 한 번 삽입한다.
  저장 후 재열기에서는 기존 레코드를 교체한다.
- 빈 문단에도 입력용 글자 run을 유지해 첫 입력의 미리보기와 저장본에 기존 글꼴·크기를 이어 준다.
- 헤더 글자 수의 상위 플래그, UTF-16 길이, 탭·줄바꿈 마스크, 줄 캐시 수와 빈 줄 표시를 갱신한다.
  문단 끝 표시만 남았을 때에도 재입력이 가능하다.
- 저장 직전 원본 바이트를 다시 파싱해 편집 시작 시점의 전체 블록과 비교한다.
  저장 후에는 모든 문단의 텍스트·ID·표 위치·영역과 표/셀 개수를 재검증한다.
- 수정하지 않은 레코드는 확장 길이 헤더를 포함한 원래 인코딩을 유지한다.
  변경이 없는 구역의 압축 스트림도 다시 압축하지 않는다.

소스 주소와 capability를 별도의 공개 모델로 추가하는 부분은 후속 단계로 남겼다.
이번 구현에서는 파서 내부 판정과 기존 `isEditable`, 저장 시 원본 전체 재검증으로 연결했다.

## 검증

`shortcuts_exampleTests/HWPEmptyParagraphEditingTests.swift`와 원본 공개 신청서 fixture를 추가했다.

macOS용 임시 검증 패키지에서 실제 파서·저장기·텍스트 편집기와 문서 모델을 빌드해
**21개 테스트를 실행했고 전부 통과했다.** 새 파일의 순수 문서 테스트 8개,
기존 HWP 테스트 7개, 앞선 간편 표 테스트·fixture 검사·화면 렌더 검사 6개이다.
기존 인터넷 예제 테스트에는 같은 예제의 현재 로컬 fixture 경로를 연결했다.

확인한 항목:

- 실제 신청서의 빈 문단 41개 동시 입력·저장·재열기.
- 표 4개와 병합/내부 표 위치, 변경하지 않은 문단과 관련 없는 OLE 스트림 보존.
- 위치 0 글자 모양과 편집 미리보기/저장본의 글자 서식 일치.
- 제품명 입력 → 재열기 → 두 번째 수정 → 지우기 → 재입력, 텍스트 레코드 중복 없음.
- 압축/비압축 문서, 비기본 입력 서식, 이모지의 UTF-16 길이, 탭·줄바꿈과 제거.
- 잘못된 문단 길이·서식 참조·레코드 깊이·알 수 없는 자식 레코드·범위 태그의 편집 제한.
- 내부 표 컨트롤 보존, 중복 ID와 오래된 편집 스냅샷 거부, 무변경 저장의 바이트 일치.
- 기존 텍스트 교체, 여러 줄 캐시, 서명된 문서, 표 병합, 실제 그림/표 예제 회귀 검사.

iOS 앱과 테스트 타깃의 `build-for-testing`도 통과했다. UIKit을 사용하는 실제 행 편집
→ 실행 취소 → 다시 실행 → HWP 저장 통합 테스트는 추가하고 컴파일했지만 실행하지 않았다.
위 21개를 iOS 실기기 테스트 결과로 해석하면 안 된다.

실행 로그: `/tmp/rivopad-hwp-empty-regression.log`, `/tmp/rivopad-hwp-empty-ios-build.log`.

## 남은 검증과 후속 범위

- iPad Pro M4에서 실제 행 편집창·키보드·VoiceOver 조작 확인. 이번 작업에서 기기에 설치하지 않았다.
- 외부 한컴 앱에서 저장본을 열어 짧은 입력값의 표시와 양식 유지 확인. 이 환경에는 한컴 앱이 없어 실행하지 못했다.
- 긴 여러 줄 입력에 따른 행 높이와 이후 내용 재배치, 여러 서식이 섞인 문장 중간 삽입/삭제.
- 항목 이름 연결과 음성 명령의 대상 지정은 아래 후속 구현에 반영했다. 실제 음성/클라우드 응답 검증은 남아 있다.

이번 결과는 기존 양식의 짧은 값 입력을 위한 첫 저장 경로이다. 전체 페이지 조판이나
전체 음성 편집기를 완성했다는 의미는 아니다.

## 후속 구현: 항목 이름으로 수정할 칸 찾기

기준 신청서의 분리된 레이블/값 셀에서 제품명, 출품자, 소속, 연락처, 이메일, 주소의
**입력 항목 14개**를 찾는다. 원래 레이블 셀 ID와 값 셀 ID를 함께 유지하고,
반복되는 소속·연락처·이메일에는 출품자 1·2·3 문맥을 붙인다. 주소처럼 공통으로
쓰이는 항목에는 출품자 문맥을 임의로 이어 붙이지 않는다.

- `HWPFormFields`는 짧은 전체 셀 레이블과 수평으로 인접한 값 셀을 기준으로 연결한다.
  지원하는 이름/동의어와 번호가 있는 출품자 등 구역 이름을 사용한다. 긴 안내문 안의
  단어, 표의 제목 행, 개인/단체의 빈 표시 칸, 내부 표 부모 문단은 입력 항목으로 추측하지 않는다.
- 간편 문서의 행 보기와 입력창, VoiceOver, AI 수정안 미리보기에서 같은 항목 이름을 쓴다.
  입력창의 실제 초점도 선택된 문단 ID에 연결한다. 표 번호는 간편 보기와 AI에서 일치한다.
- “제품명을 한글빛으로 바꿔줘”, “출품자 2 연락처를 …로 바꿔줘” 같은 요청을
  레이블과 구역/표/행 조건으로 좁힌다. 성명/이름, 연락처/전화번호/핸드폰번호,
  이메일/전자우편 등 동의어와 두 번째 출품자 같은 표현도 처리한다.
- “연락처를 …로 바꿔줘”처럼 중복되는 항목은 로컬에서 먼저 확인 질문을 만든다.
  “출품자 2”, “2번”, “두 번째”, “표 1 8행” 같은 답변은 원래 값/지시를 유지한다.
  구역 이름도 중복될 때에는 표 위치로 한 번 더 좁힐 수 있다.
- 없는 출품자 번호, 모순되는 위치, 읽기 전용/여러 문단 값 셀, 읽기 제한으로
  대상 전체가 누락된 경우에는 다른 칸으로 대체하지 않는다. 미지원 하위 항목을
  출품자의 이름 칸으로 오인하는 경우도 막는다.
- HWP/HWPX AI 요청에 `formContext`를 추가하고 대상 레이블과 빈 값 문단을 함께 전송한다.
  긴 문서에서도 찾은 항목을 우선 포함한다. 원본 문서 revision은 그대로 유지한다.
- 명확한 대상이 있는 수정 요청에서는 해당 값 문단만 편집 가능으로 전달한다.
  로컬 검증기도 레이블 셀, 다른 출품자의 값, 모호한 대상을 거부한다.
- HWP 응답 스키마·프롬프트·검증기의 작업 종류를 `replaceText`로 제한했다.
  Word 문서의 기존 `setStyle` 경로는 유지한다. 적용은 기존 HWP의 실행 취소·저장 경로를 쓴다.

### 후속 검증 결과

`HWPFormFieldTests.swift`의 순수 문서/대상 지정 테스트 15개를 추가했다.
앞선 테스트와 합쳐 **macOS 검증 패키지에서 36개 테스트가 통과**했다.
제품명 수정안을 검증한 뒤 실제 HWP 작성기로 저장·재열기하고,
레이블·다른 문단·표 4개·병합 위치가 유지되는지 확인했다. 짧은 답변의 이어가기,
잘못된 대상/서식 거부, 긴 문서의 빈칸 포함, 일반 질문과 수정 지시 구분도 검사했다.

iOS 앱과 테스트 타깃의 `build-for-testing`이 통과했다. 실제 HWP 뷰 모델의
항목 스냅샷 → 수정안 적용 → 실행 취소/다시 실행 → 저장 통합 테스트도 추가하여 컴파일했다.
이 UIKit 통합 테스트를 실행하거나 M4에 설치한 것은 아니다.

변경된 행 보기 컴포넌트를 390/700 포인트 너비로 렌더링하고 작은 화면 결과를 확인했다.
스크린샷은 `/tmp/rivopad-hwp-form-fields-390.png`, `/tmp/rivopad-hwp-form-fields-700.png`이다.
로그는 `/tmp/rivopad-hwp-form-ai-test.log`, `/tmp/rivopad-hwp-form-ai-build.log`이다.

값의 해석과 최종 수정안 생성은 기존 클라우드 AI가 담당한다. 이번 자동 검사에서는
AI 응답에 해당하는 수정안을 주입해 로컬 연결과 저장 결과를 검증했으며,
실제 음성 인식과 클라우드 응답, M4에서의 조작을 통과했다고 주장하지 않는다.
현재 이름 연결은 확인된 형태의 수평 레이블/값 셀과 단일 문단 값 변경을 대상으로 한다.
모든 한글 양식 구조나 긴 여러 줄 입력의 조판을 지원하는 것은 아니다.
