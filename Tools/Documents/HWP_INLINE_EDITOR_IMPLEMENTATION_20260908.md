# 원본 문서 내 커서 편집 — 첫 구현

2026-09-08. 목표는 원본 화면의 본문과 표 안에 실제 커서를 놓고 입력하는 것이다. 이번 단계는 **편집 가능한 한 문단 안의 커서·선택·텍스트 입력**을 연결한다.

## 사용 흐름

원본 문서에서 상단 연필 → 본문이나 표 안의 글자/빈 문단 터치 → 키보드 입력. 커서 이동, 선택 범위 교체, 복사·텍스트 붙여넣기, 입력 중 실행 취소를 제공한다. 키보드의 완료, 다른 문단 선택, 저장 또는 문서 실행 취소를 누르면 조합 중인 글자까지 확정하여 기존 편집 모델에 반영한다. 저장 형식은 원래 HWP/HWPX를 유지한다.

연필을 눌러도 간편 문서로 이동하지 않는다. 원본 편집을 시작할 때 AI 패널을 접어 문서 공간을 확보하며, AI 도우미 버튼으로 다시 열 수 있다.

## 구현

- `HWPInlineEditingSession`: 동시에 한 입력기를 관리한다. 초안은 입력기에 유지하여 매 음절마다 모든 쪽을 다시 배치하지 않는다. 첫 변경 여부로 저장/실행 취소 버튼을 활성화하고, 문단 종료 때 한 번 반영한다. 이전 입력기의 늦은 콜백은 세션 토큰으로 제외한다.
- `HWPInlineTextEditor`: 원본 문단 위치에 `UITextView`를 놓는다. iPadOS의 커서, 선택 손잡이, 한글 marked text, 키보드 편집 메뉴를 사용한다. SwiftUI 갱신 시 `attributedText`를 덮어쓰지 않는다. 키보드가 나타나면 바깥 문서 스크롤에 커서 위치를 드러낸다.
- `HWPInlineParagraphGeometry`와 원본 캔버스: 기존 줄 좌표, 셀 여백, 세로 정렬, 쪽 배율로 입력 영역을 구한다. 선택한 문단의 기존 글자만 숨기며 표 테두리와 주변 내용은 유지한다. 글자를 그리는 읽기 전용 뷰의 터치 처리를 꺼 본문 터치가 입력 영역에 전달되게 했다.
- `HWPDocumentView`: 보기 전환, 글꼴 선택, AI 스냅샷, AI 적용, 저장, 내보내기, 뒤로 가기, 실행 취소 전에 입력을 확정한다. 문서 실행 취소는 한 문단의 입력 세션을 하나의 변경으로 처리한다.
- `HWP5DocumentRewriter`: 글자 모양 경계를 기존 위치에 고정하던 동작을 수정했다. 삽입·삭제에 맞춰 서식 경계를 이동하며 HWP 탭의 8단위 길이, 삭제된 스타일 구간, 문단 헤더의 스타일 개수를 처리한다. 화면과 같은 스타일 소유 규칙으로 저장한다.

## 범위와 남은 작업

입력창이 문서 위의 실제 위치에 놓이지만, 문서 전체를 하나의 연속된 입력기로 만든 단계는 아니다.

- 현재 선택과 입력은 한 문단 안에서 동작한다. Enter는 기존 문단 내부의 줄바꿈으로 저장한다. 문단 간 선택, 새 문단 생성·합치기, 경계를 넘는 삭제/커서 이동은 후속 작업이다.
- 입력이 기존 영역보다 길면 입력기 내부에서 스크롤하여 모두 확인할 수 있고 화면에 안내한다. 표의 자동 확장과 뒤 문단·쪽의 완전한 재배치는 이번에 구현하지 않았다. 편집을 마친 원본 미리보기에서는 기존 배치에 의해 일부 긴 내용이 잘릴 수 있다.
- 복합 컨트롤 소유 문단, 도형 안 텍스트, 머리말·꼬리말, 여러 쪽으로 나뉜 문단은 이번 입력 대상으로 열지 않는다. 쪽 조각을 원본 전체 텍스트로 잘못 저장하지 않도록 원본 ID와 전체 텍스트를 검사한다.
- 활성 문단은 UIKit으로 배치한다. 저장된 글꼴·크기·색·강조 서식은 사용하지만, 한컴 고유의 자폭·기준선·양쪽 정렬이 읽기 화면과 완전히 같은지는 서식별 추가 검증이 필요하다.
- 실제 한컴에서 수정본 재열기와 실기기 키보드의 모든 입력 조합을 검증한 상태는 아니다.
