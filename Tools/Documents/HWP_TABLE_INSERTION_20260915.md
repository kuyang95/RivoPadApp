# 새 표 삽입 — 2026-09-15

빈 문서에서는 상단 **표**를 바로 누르고, 내용이 있는 문서에서는 일반 본문에 커서를 둔 뒤 **표 → 행 수·열 수 → 삽입**을 누른다. 행과 열은 각각 1~20개이며, 본문 너비에 맞춘 동일 너비의 열로 만든다. 커서 앞뒤 글과 글자 서식은 표 위아래 문단에 남고, 첫 셀에서 바로 입력을 시작한다.

새 표는 바탕 10pt, 검은 0.3mm 테두리와 기본 셀 여백으로 생성한다. 기존 셀 입력·서식·행열 추가/삭제·병합/분할·크기 조절을 그대로 사용할 수 있다. 표 삽입은 실행 취소·다시 실행에 포함되며, 실제 파일은 ‘이 문서에 저장’을 눌러 갱신한다.

## 구현 및 보존 범위

- HWPX에는 표와 셀 문단, 크기·위치·테두리 정의를 추가한다. HWP 5에는 표 앵커, 표 제어, 셀 목록과 문단을 추가한다. 두 형식 모두 원래 형식으로 저장한다.
- 기존 본문과 표 번호가 이동한 뒤에도 글자 서식과 기존 표 내용을 유지한다. 다른 구역과 바이너리 자료를 보존한다.
- 높이가 큰 표는 기존 쪽 배치 기능과 연결하며, 쪽 번호가 이어진다. 새 표 앞뒤의 빈 문단에서 본문 입력을 계속할 수 있다.
- HWP의 빈 문단에 텍스트 레코드가 없는 경우에도 표 앵커를 추가한다. 초기 검사에서 확인한 저장 실패를 수정했다.
- 영문·일문 번역 및 [직접 테스트 가이드](HWP_MANUAL_TEST_GUIDE_20260915.md)의 57개 수동 체크 항목을 갱신했다. 사용자 수동 검사는 완료 표시하지 않았다.

HWP 저장 구조는 [한컴 HWP 5.0 공개 명세](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.2.pdf)의 표 65, 69~70, 75, 79~80을 참고했다.

## 검증

- 실제 M4 전체 앱 검사 29개 통과: 새 표 삽입 7개, 기존 표 구조 14개, 쪽 번호 8개. 저장 전 입력 보존, 실행 취소·다시 실행, 원본 형식 저장, 외부 파일 변경 충돌도 확인했다.
- 시뮬레이터 회귀 검사 79개 통과: 새 표, 기존 셀·표 구조·크기 편집, 쪽 나누기·쪽 번호, 문단 편집. 20×20 최대 크기, 유니코드와 부분 글자 서식, 구역과 기존 표 보존, 긴 표의 쪽 배치를 포함한다.
- 화면 조작 검사 1개 통과: 빈 문서에서 창 열기·취소, 잘못된 크기 거부, 3×2 표 생성, 첫 셀 커서, 실행 취소·다시 실행, 한글 여러 줄 입력, 4×3으로 행열 추가, 저장 후 재열기. 설정 창과 최종 표 화면을 직접 확인했다.
- 초기 시뮬레이터 실행이 진단 수집 또는 테스트 연결 단계에서 멈춘 경우는 해당 시뮬레이터를 다시 시작해 해결했다. 최종 회귀·화면 검사는 정상 종료했다.

## M4 빌드·설치

Xcode 27로 일반 Debug 빌드에 성공했다. 이번 빌드 실행에 한해 최소 OS를 앱 기준 iOS 26.2로 맞췄으며 Pod 파일은 수정하지 않았다.

실제 **iPad Pro 11-inch M4**에 2026-09-15 **16:01:58 KST 설치**, **16:02:15 실행**을 확인했다. 앱 이름은 **VisionCraft**다. 설치된 앱 경로와 실행 프로세스가 같은 앱을 가리키는지 확인하고 실기기 화면도 저장했다. 설치 앱 복사본, 실행 파일 해시, 검사 결과와 화면은 `output/hwp_table_insert_20260915/evidence.json`에 정리했다.

## 현재 제한

일반 본문의 커서 위치에 표를 넣는다. 글자 범위 선택, 목록 문단, 다단 본문, 기존 셀 안의 중첩 표는 지원하지 않는다. 열 너비가 20pt보다 작아지는 조합은 적용할 수 없다. 복잡한 표 스타일 템플릿, 자동 맞춤, 표 캡션과 표 전체 삭제는 이번 범위에 포함하지 않았다.

한컴 한글 앱에서 저장 결과를 직접 여는 수동 호환성 검사는 남아 있다.
